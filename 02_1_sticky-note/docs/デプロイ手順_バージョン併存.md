# デプロイ手順（同一サーバで前バージョン残し・新バージョン追加）

同じサーバ上で**前のバージョン（旧）を残したまま**、**新バージョン**を別ポート・別ディレクトリで立ち上げる手順です。切り替え・ロールバックも可能にします。

- **初回デプロイ（02_1_sticky-note のみ・前バージョンなし）**: → **`docs/デプロイ手順_初回.md`** を参照（wlinko-pj から 02_1_sticky-note だけ clone してデプロイ）。
- 以下は**将来、旧版を残しつつ新版を追加する場合**の手順です。

---

## 1. 構成イメージ

| 種別 | ディレクトリ | ポート | PM2名 | 公開（例） |
|------|--------------|--------|-------|------------|
| **旧（前バージョン）** | `/var/www/wl-sticky-note/releases/v1` | 3000 | `wl-sticky-note-v1` | ポート80 → 3000 |
| **新（新バージョン）** | `/var/www/wl-sticky-note/releases/v2` | 3001 | `wl-sticky-note-v2` | ポート8080 → 3001 |

- **サーバ**: IP `172.16.1.81` / ドメイン `wl-sticky-note.local`

- 旧: 既存の「初回デプロイ」を v1 として扱う。
- 新: 新コードを v2 として別ディレクトリ・別ポートでデプロイし、必要に応じて Nginx で別ポート（例: 8080）を公開する。
- 本番のメインアクセスを新に切り替える場合は、Nginx の 80 番を 3001 に向け、80→3000 は「旧版用」として残すか、止めるか選べるようにします。

---

## 2. 前提条件

- Ubuntu Server（20.04 LTS 以降推奨）
- SSH と sudo が使えること
- 既存環境がある場合: Node.js / npm / PM2 / Nginx は導入済み想定

---

## 3. 初回（前バージョン＝v1 として残す）

既に `deploy.sh` で 1 本だけデプロイしている場合は、そのままを「v1」とみなします。

### 3.1 既存を v1 構成にそろえる（任意）

既存が `/var/www/...` の別パスで動いている場合、v1 用ディレクトリにそろえたいときの例です。

```bash
# 例: 既存アプリを v1 として releases にそろえる
sudo mkdir -p /var/www/wl-sticky-note/releases
sudo mv /path/to/current/app /var/www/wl-sticky-note/releases/v1   # 既存を v1 に
sudo chown -R $USER:$USER /var/www/wl-sticky-note
```

既存の PM2 名が `wl-sticky-note` のままなら、そのまま「旧」として運用し、**新バージョンだけ** v2 で追加しても構いません。

### 3.2 初回からバージョン構成でデプロイする場合

まだ何もデプロイしていない場合の例です。

```bash
# リポジトリを v1 用ディレクトリに配置
sudo mkdir -p /var/www/wl-sticky-note/releases
cd /var/www/wl-sticky-note/releases
sudo git clone https://github.com/your-org/your-repo.git v1
cd v1/src   # または 02_1_sticky-note の src に相当するパス
sudo chown -R $USER:$USER /var/www/wl-sticky-note

# 既存 deploy.sh で 1 本だけ起動（ポート 3000・PM2 名はそのままでも可）
npm install
npm run build
PORT=3000 pm2 start server.js --name wl-sticky-note-v1
pm2 save
```

Nginx は既存の `nginx.conf` のとおり 80 → 3000 で問題ありません。

---

## 4. 新バージョン（v2）のデプロイ

前バージョン（v1）は触らず、新コードを v2 として追加します。

### 4.1 サーバ上で v2 用ディレクトリを用意

```bash
cd /var/www/wl-sticky-note/releases
git clone https://github.com/your-org/your-repo.git v2
# または rsync/scp で新ビルド済みソースを v2 に配置
cd v2/src
```

※ リポジトリが 1 つで「v2 は別ブランド」の場合は、`git clone` したディレクトリ名を `v2` にすればよいです。

### 4.2 環境変数・ポート

v2 は **ポート 3001** で動かします（v1 の 3000 と重ねないため）。

```bash
# v2 用 .env を作成（ポート 3001）
echo "PORT=3001" > .env
echo "NODE_ENV=production" >> .env
# 必要なら AI_BOARD_URL も追加
```

### 4.3 ビルドと PM2 起動

```bash
npm install
npm run build
PORT=3001 pm2 start server.js --name wl-sticky-note-v2
pm2 save
```

v1 はそのまま `wl-sticky-note-v1`（ポート 3000）で動き続けます。

### 4.4 Nginx で v2 を公開（ポート 8080 で例）

旧は 80 → 3000、新は 8080 → 3001 にする例です。

```bash
sudo cp /var/www/wl-sticky-note/releases/v2/src/nginx.versioned.conf.example /etc/nginx/sites-available/wl-sticky-note-versioned
sudo ln -sf /etc/nginx/sites-available/wl-sticky-note-versioned /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

ファイアウォールで 8080 を開ける場合:

```bash
sudo ufw allow 8080/tcp
sudo ufw reload
```

- 旧: `http://wl-sticky-note.local/` または `http://172.16.1.81/` （80 → 3000）
- 新: `http://wl-sticky-note.local:8080/` または `http://172.16.1.81:8080/` （8080 → 3001）

---

## 5. 本番を「新バージョン」に切り替える場合

80 番を新（v2）に向け、旧（v1）は 8080 など別ポートに移す例です。

1. Nginx の設定で:
   - `listen 80` → `proxy_pass http://localhost:3001`（v2）
   - 旧 v1 用に `listen 8080` → `proxy_pass http://localhost:3000`
2. `sudo nginx -t && sudo systemctl reload nginx`
3. 必要なら `ufw allow 8080` で旧版用ポートを開放。

これで「メインは新、旧は残したまま別ポートで参照可能」になります。

---

## 6. 運用コマンド一覧

| 目的 | コマンド |
|------|----------|
| 全バージョン一覧 | `pm2 list` |
| 旧（v1）ログ | `pm2 logs wl-sticky-note-v1` |
| 新（v2）ログ | `pm2 logs wl-sticky-note-v2` |
| 旧再起動 | `pm2 restart wl-sticky-note-v1` |
| 新再起動 | `pm2 restart wl-sticky-note-v2` |
| 新だけ停止 | `pm2 stop wl-sticky-note-v2` |
| Nginx 設定確認 | `sudo nginx -t` |
| Nginx 再読込 | `sudo systemctl reload nginx` |

---

## 7. ロールバック（新を止めて旧に戻す）

1. Nginx の 80 番を再び 3000（v1）向けに戻す。
2. `sudo nginx -t && sudo systemctl reload nginx`
3. 必要なら `pm2 stop wl-sticky-note-v2` で v2 を停止。

---

## 8. スクリプトを使う場合（deploy-versioned.sh）

`src/deploy-versioned.sh` に、**バージョン名**と**ポート**を指定してデプロイするスクリプトを用意しています。

```bash
cd /var/www/wl-sticky-note/releases/v2/src   # またはデプロイするバージョンの src
chmod +x deploy-versioned.sh
./deploy-versioned.sh v2 3001
```

- **第1引数**: バージョン名（PM2 名は `wl-sticky-note-<第1引数>`）。例: `v1`, `v2`
- **第2引数**: ポート番号。例: v1=3000, v2=3001

初回は v1 を 3000 で、2 回目は v2 を 3001 で実行する想定です。既存の `deploy.sh` は「1 本だけ・上書き」用として残してあります。

Nginx で複数バージョンを公開する場合は、`src/nginx.versioned.conf.example` をコピーして編集し、`sites-available` に配置してください。サーバは **172.16.1.81**、ドメインは **wl-sticky-note.local** で記載しています。

---

## 9. まとめ

- **前のバージョン**: そのまま同じディレクトリ・同じポート（例: 3000）で残す。
- **新バージョン**: 別ディレクトリ（`releases/v2`）・別ポート（3001）でデプロイし、Nginx で別ポート（例: 8080）公開。
- 本番を新に切り替えるときは Nginx の 80 を 3001 に向け、旧は 8080 などで残すと安全にロールバックできます。
