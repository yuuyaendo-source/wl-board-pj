# wl-sticky-note 開発の進め方（ローカル・本番の整理）

今回のデプロイで **wl-sticky-note** は **ローカル環境** と **本番環境** の 2 つが存在する状態になりました。今後の開発をどう進めるかを整理したドキュメントです。

---

## 1. 環境の整理

| 環境 | 場所 | URL（付箋ボード） | 用途 |
|------|------|-------------------|------|
| **ローカル** | 開発PC（wlinko-pj リポジトリ内の 02_1_sticky-note） | <http://localhost:3000> | 日々の開発・動作確認 |
| **本番** | サーバ 172.16.1.203（wlboardsys.internal.wonder-link.com） | <https://wlboardsys.internal.wonder-link.com> / <https://wlboardsys.internal.wonder-link.com/board/wl> | 実際の利用・AI-Board・Desktopアプリの連携先 |

- **本番の連携先ボード**: `wl` → <https://wlboardsys.internal.wonder-link.com/board/wl（AI-Board・Desktopアプリはここを向く）>
- ローカルでは `localhost:3000` で開発し、本番ではサーバ上の 02_1_sticky-note を `wlboardsys.internal.wonder-link.com` で公開する想定です。

---

## 2. 開発フローのイメージ

```
[ローカル開発] → [動作確認] → [Git に push] → [本番サーバで pull & デプロイ]
```

1. **ローカルで開発** … 02_1_sticky-note のコードを編集（wlinko-pj リポジトリ内）
2. **ローカルで動作確認** … `cd src` → `npm run dev` で <http://localhost:3000> を確認
3. **Git に push** … wlinko-pj のリモート（GitHub 等）に push
4. **本番サーバで反映** … サーバで `git pull` し、ビルド・再起動（後述）

---

## 3. Git の進め方（推奨）

- **main（または main 相当）**: 本番に反映してよい状態を置く
- **開発用ブランチ**（任意）: 機能追加・修正は `feature/xxx` や `develop` で行い、確認後に main にマージしてもよい
- **タグ**（任意）: 本番反映のタイミングで `v1.0.1` のようにタグを打つと、どのコミットが本番か追いやすい

運用例:

- 小規模なら **main のみ**で開発し、問題なければそのまま本番で `git pull` する
- 複数人・大きな変更なら **feature ブランチ**で開発 → main にマージ → 本番で `git pull origin main` する

---

## 4. 本番への反映手順

修正を本番環境に反映するときは、**本番サーバ**で次を実行します。

```bash
# サーバに SSH
ssh user@172.16.1.203
# または
ssh user@wlboardsys.internal.wonder-link.com

# 02_1_sticky-note のみが clone されているディレクトリへ
cd /var/www/wl-sticky-note
git pull

# ビルドと再起動
cd 02_1_sticky-note/src
npm install
npm run build
pm2 restart wl-sticky-note
```

- 初回デプロイ時と同じく、**02_1_sticky-note だけ**が sparse-checkout されているので、`git pull` で 02_1_sticky-note 以下だけが更新されます。
- 依存関係の追加・変更をした場合は必ず `npm install` を実行してください。

## 5. 連携アプリ（AI-Board・Desktop）の環境切り替え

| アプリ | ローカルで開発・確認するとき | 本番で使うとき |
| -------- | ------------------------------ | ---------------- |
| **付箋ボード（wl-sticky-note）** | <http://localhost:3000> | <https://wlboardsys.internal.wonder-link.com> |
| **AI-Board** | 付箋送信先: localhost:3000 / board_id: wl（または開発用ID） | `POSTIT_BOARD_URL=https://wlboardsys.internal.wonder-link.com`、`config.json` の `board_id`: `wl` |
| **Desktopアプリ** | `postit_board_url`: <http://127.0.0.1:3000/、`postit_board_id`>: wl（または開発用） | `postit_board_url`: <https://wlboardsys.internal.wonder-link.com/、`postit_board_id`>: wl |

- **ローカルで付箋ボード＋AI-Board＋Desktop をまとめて試す**: 付箋ボードを localhost:3000 で起動し、AI-Board と Desktop は付箋ボードURLを localhost のままにしておく。
- **本番**: 上表のとおり、AI-Board は `POSTIT_BOARD_URL`、Desktop は `config.json` の `postit_board_url` で **<https://wlboardsys.internal.wonder-link.com/>** を指定し、いずれも **board_id: wl** で <https://wlboardsys.internal.wonder-link.com/board/wl> を連携先にする。

## 6. 困ったときの確認リスト

| 確認項目 | ローカル | 本番 |
| ---------- | ---------- | ------ |
| 付箋ボードが起動しているか | `npm run dev`（src で） | `pm2 list` → wl-sticky-note、`pm2 logs wl-sticky-note` |
| ボード wl が存在するか | <http://localhost:3000/board/wl> で開けるか | <https://wlboardsys.internal.wonder-link.com/board/wl> で開けるか |
| AI-Board の送信先 | 環境変数未設定 or localhost:3000 | `POSTIT_BOARD_URL=https://wlboardsys.internal.wonder-link.com` |
| Desktop のポーリング先 | config で localhost:3000 | config で <https://wlboardsys.internal.wonder-link.com/、postit_board_id>: wl |
| サーバの 02_1_sticky-note の更新 | — | `cd /var/www/wl-sticky-note && git pull` で最新化 |

---

## 7. まとめ

- **開発はローカル**で行い、**本番はサーバ上の 02_1_sticky-note**（sparse-checkout）を更新する形で進める。
- 反映の流れは「**ローカルで commit → push → 本番サーバで pull → npm install & build → pm2 restart**」。
- 本番の連携先は **<https://wlboardsys.internal.wonder-link.com/board/wl>** に統一し、AI-Board・Desktopアプリは本番ではこのURL（および board_id: wl）を向くように設定する。

初回デプロイの詳細は **`docs/デプロイ手順_初回.md`**、本番反映のコマンドは **`docs/デプロイ手順_初回.md` の「6. 今後の更新」** を参照してください。
