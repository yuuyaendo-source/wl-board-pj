# 本番 Sticky-note と AI-Board・Desktop の連携整理

本番の Sticky-note を使いながら、AI-Board と Desktop アプリの両方が連携した状態を実現するための整理です。

---

## 1. 現状

### できていること

| 項目 | 内容 |
|------|------|
| **Sticky-note** | 本番環境で稼働（例: http://wl-sticky-note.local/board/wl） |
| **AI-Board** | 本番は **http://wl-ai-board.local** で稼働（サーバー移動後。DNS または hosts で名前解決） |
| **Desktop アプリ** | 本番の Sticky-note に接続・アクセス可能（`postit_board_url` 本番設定） |

### できていないこと（設定後は解消）

| 項目 | 内容 |
|------|------|
| **Sticky-note → AI-Board の付箋連携** | 本番で付箋を追加したときに AI-Board へ通知するには、付箋ボードの .env に **`AI_BOARD_URL`**（AI-Board の本番URL）を設定する。`add-note` 時に `/api/receive_note` を呼ぶ実装済み。 |
| **付箋追加時の通知** | Sticky-note に付箋が追加されても、Desktop に「新しい付箋が投稿されました」が届かない（ポーリング先・ネットワーク・初回タイミングのいずれか要確認） |

---

## 2. やりたいこと

**本番の Sticky-note を使いながら、AI-Board と Desktop アプリの両方が連携した状態にする。**

- **Desktop**: 本番ボードを開く・新付箋でトースト通知
- **AI-Board**: カメラ検知した付箋を本番 Sticky-note（board: wl）に送信し、AI コメント連携
- **Sticky-note**: 本番で付箋の一元管理（Web で追加した付箋も、AI-Board から送った付箋も同じボードに表示）

**リン子連携の詳細**（いつリン子がコメント・発声するか）は **02_2_AI-Board/docs/リン子連携仕様.md** を参照。

---

## 3. 技術的なポイント

| 役割 | 対象 | 内容 |
|------|------|------|
| **付箋の送信先** | AI-Board → Sticky-note | 環境変数 `POSTIT_BOARD_URL`（本番: `http://wl-sticky-note.local`）。付箋検知・Web アプリからの送信先。 |
| **付箋の参照元** | Desktop → Sticky-note | `config.json` の `postit_board_url` と監視対象ボードID。**`postit_board_ids`**（配列）を指定すると複数ボードを監視し、いずれかに新付箋があればトースト。未設定時は **`postit_board_id`** のみ。 |
| **ボード ID** | 共通 | 本番では `board_id: wl`（http://wl-sticky-note.local/board/wl） |

- **Sticky-note 側**: `GET /api/boards/:id/summary` でサマリー（付箋数・最終付箋時刻）を返す。Desktop はこれを一定間隔でポーリング。
- **AI-Board 側**: 付箋検知時に `POST {POSTIT_BOARD_URL}/api/sticky_notes` で本番に送信するには、`POSTIT_BOARD_URL=http://wl-sticky-note.local` の設定が必要。

## 4. やること・確認チェックリスト

**本番用設定例ファイル**  
- **AI-Board**: `02_2_AI-Board/.env.production.example` をコピーして `.env` にし、`GEMINI_API_KEY` 等を設定  
- **付箋ボード (wl-sticky-note)**: `02_1_sticky-note/src/.env.production.example` をコピーして `src/.env` にし、**`AI_BOARD_URL`** を AI-Board の本番 URL に（例: **`http://wl-ai-board.local`**）。HTTPS かつ自己証明書の場合は **`AI_BOARD_INSECURE_SSL=1`** を設定（付けないと receive_note が呼ばれず付箋・リン子が反応しない）。  
- **Desktopアプリ**: `02_3_WL_Desktop_app/config.production.example.json` を参考に `config.json` を設定  

### 4.1 AI-Board と Sticky-note の付箋連携（AI-Board → 本番送信）

- [ ] AI-Board の環境変数に **`POSTIT_BOARD_URL=http://wl-sticky-note.local`** を設定（.env または起動時）
- [ ] `src/config.json` の **`board_id`** が **`wl`** になっている
- [ ] AI-Board 起動後、付箋検知で本番の http://wl-sticky-note.local/board/wl に付箋が追加されることを確認

### 4.2 Desktop の付箋通知（本番ボードの新付箋でトースト）

- [ ] Desktop の **`config.json`** で  
  - **`postit_board_url`**: 本番（例: `http://wl-sticky-note.local/`）  
  - **`postit_board_id`**: トレイクリックで開くデフォルト（本番: **`wl`**）  
  - **`postit_board_ids`**: （任意）新付箋を監視するボードIDの**配列**。例: `["wl", "board_2"]`。未設定時は `postit_board_id` のみ監視。**複数ボードのいずれかに付箋が追加されても通知**される。  
  - **`postit_poll_interval_sec`**: **60** 以上（0 だとポーリング無効）
- [ ] **Desktop アプリを動かしている PC** から、ブラウザや `curl` で  
  **http://wl-sticky-note.local/api/boards/wl/summary** にアクセスできること（同じネットワーク・DNS または hosts で `wl-sticky-note.local` が解決できること）
- [ ] 本番ボードに新付箋を追加し、約 1 分以内に「新しい付箋が投稿されました」トーストが出ることを確認

### 4.3 まとめの確認

- [ ] 本番の付箋ボード（http://wl-sticky-note.local/board/wl）が開ける
- [ ] Desktop: トレイから本番ボードが開ける／新付箋でトーストが出る
- [ ] AI-Board: 本番ボードに付箋が送られる／AI コメント連携が動く

## 5. 付箋通知が届かないときの切り分け

1. **ポーリングが無効になっていないか**  
   `postit_poll_interval_sec` が 0 だと通知は出ません。60 など 10 以上を指定してください。

2. **初回ポーリングまで最大 1 分かかる**  
   起動後、最初の 1 回は「現状の把握」のみで通知は出ません。その後のポーリングで「付箋数や最終付箋時刻が増えた」ときに通知されます。起動直後に付箋を追加した場合は、次のポーリング（最大で約 1 分後）で通知が出る想定です。

3. **ネットワーク**  
   Desktop を動かしている PC から、本番 Sticky-note に到達できるか確認してください。  
   - ブラウザで http://wl-sticky-note.local/board/wl を開けるか  
   - `curl http://wl-sticky-note.local/api/boards/wl/summary` で JSON が返るか  

   同じネットワークにない場合や名前解決できない場合は、hosts の設定やネットワーク構成の見直しが必要です。

4. **接続テスト**  
   Desktop アプリのトレイメニューに **「付箋ボード接続テスト」** を追加済み。これを実行すると、現在の設定で付箋ボードに接続できるか・失敗時は理由（タイムアウト／接続できません／404 など）がトーストで表示されます。通知が届かないときはまずここで接続を確認してください。

5. **付箋をどこに投稿しているか**  
   Desktop の通知は **レガシー付箋ボード**（例: http://wl-sticky-note.local/board/wl）の「付箋数・最終投稿時刻」の変化をポーリングして検知しています。  
   **Board System**（タスクボード /boards/taskboard やメインボードなど）にだけ投稿している場合、レガシー板「wl」の内容は変わらないため、通知は出ません。  
   通知を出したい場合は、**付箋をレガシー板 wl に投稿**する（ブラウザで /board/wl を開いて付箋を足す、または AI-Board／カメラ経由で wl に送る）必要があります。

## 6. /api/boards/wl/summary が 404 になる場合

本番で `http://wl-sticky-note.local/api/boards/wl/summary` が 404 になる主な原因は次の2つです。

### 6.1 まず /api/health で切り分けする

**http://wl-sticky-note.local/api/health** にアクセスしてください。

- **200 で `{"ok":true,"message":"Express API is running"}` が返る**  
  → Express（server.js）は動いている。6.2 へ（ボード "wl" の有無を確認）。

- **404 が返る**  
  → Express の API が届いていない。**6.3 へ**（本番の起動方法・デプロイを確認）。

### 6.2 ボード "wl" がまだ存在しない（/api/health は 200 の場合）

Sticky-note では、**ボードは初回アクセス時に作成**されます。誰も `http://wl-sticky-note.local/board/wl` を開いたことがないと、ボード "wl" が boards.json に存在せず、summary API は 404（Board wl not found）を返します。

**対処**: ブラウザで **http://wl-sticky-note.local/board/wl** を **1回開く**。これでボード "wl" が作成され、以降は `/api/boards/wl/summary` が 200 で応答します。

### 6.3 本番が server.js を動かしていない（/api/health が 404 の場合）

`/api/boards/:id/summary` と `/api/health` は **Express（server.js）** で定義されています。本番で **server.js が動いていない**（古いデプロイや `next start` のみの起動など）と、これらの API は存在せず 404 になります。

**対処**:

1. **最新コードでデプロイし直す**  
   サーバで `02_1_sticky-note/src` に移動し、`git pull` のうえ再度ビルド・再起動する。
   ```bash
   cd /var/www/wl-sticky-note/02_1_sticky-note/src
   git pull
   npm run build
   pm2 restart wl-sticky-note
   ```

2. **PM2 で server.js が動いているか確認する**  
   ```bash
   pm2 list
   pm2 show wl-sticky-note
   ```  
   `script` が **server.js** になっていること、`ecosystem.config.js` を読んで起動していることを確認する。`next start` だけの起動になっていないようにする。

3. **再デプロイ後、もう一度確認**  
   - http://wl-sticky-note.local/api/health → 200  
   - http://wl-sticky-note.local/board/wl を1回開いたあと  
   - http://wl-sticky-note.local/api/boards/wl/summary → 200
