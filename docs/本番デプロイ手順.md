# 本番デプロイ手順（付箋ボード ＋ Board System）

本ドキュメントは **wl-sticky-note（付箋ボード）** と **Board System（Wonder Rinko）** を同一サーバに本番デプロイする手順です。  
**PM2 + systemd + Nginx** でホストに直接インストールする方式です。

- **Docker で本番デプロイする場合** → **[本番デプロイ手順_Docker.md](本番デプロイ手順_Docker.md)** を参照（Blue/Green デプロイ・PostgreSQL 利用）。
- **どの手順を読むか迷った場合** → [デプロイ・運用.md](デプロイ・運用.md) の索引を参照。

---

- **サーバ**: IP `172.16.1.81` / ドメイン `wl-sticky-note.local`
- **リポジトリ**: wlinko-pj（02_1_sticky-note と board-system を取得）
- **構成**: 付箋ボード（3000）＋ Board System API（8000）＋ Board System フロント（3001）を Nginx で1つのドメインにまとめます。付箋ボードは `/` と `/_next/`、Board System は **`/boards/`** 以下（basePath）で提供し、両方の `/_next/` が衝突しないようにしています。

**releases 配下で運用している場合**は、上記の `02_1_sticky-note` / `board-system` のパスを `releases/02_1_sticky-note` / `releases/board-system` に読み替えてください。

## 3. リポジトリを clone する

付箋ボードと Board System の両方が必要なため、**02_1_sticky-note** と **board-system** を sparse-checkout で取得します。

```bash
sudo mkdir -p /var/www/wl-sticky-note
sudo chown $USER:$USER /var/www/wl-sticky-note
cd /var/www/wl-sticky-note

# wlinko-pj を sparse で clone（YOUR_ORG を実際の GitHub ユーザー/組織名に置き換え）
git clone --filter=blob:none --sparse https://github.com/YOUR_ORG/wlinko-pj.git .

# 付箋ボードと Board System をチェックアウト
git sparse-checkout set 02_1_sticky-note board-system
git checkout
```

結果として次のディレクトリができます。

- `/var/www/wl-sticky-note/02_1_sticky-note/` … 付箋ボード
- `/var/www/wl-sticky-note/board-system/` … Board System（backend / frontend）

## 4. 付箋ボードのデプロイ

付箋ボードは既存の `deploy.sh` でデプロイします（Node.js / PM2 / Nginx の初回設定を含む）。

```bash
cd /var/www/wl-sticky-note/02_1_sticky-note/src
chmod +x deploy.sh
./deploy.sh
```

この時点では Nginx は付箋ボードのみをプロキシしています。Board System 用の設定は後で追加します。

### 4.1 付箋ボードの本番用 .env（Board System 連携）

Board System と連携する場合は、`02_1_sticky-note/src/.env` を用意し、PM2 再起動します。

```bash
cd /var/www/wl-sticky-note/02_1_sticky-note/src
cp .env.example .env
# 以下を編集（本番のドメインに合わせる）
# BOARD_SYSTEM_API_URL=http://127.0.0.1:8000
# NEXT_PUBLIC_BOARD_SYSTEM_URL=http://wl-sticky-note.local/boards
nano .env
pm2 restart wl-sticky-note --update-env
```

- **BOARD_SYSTEM_API_URL**: 同一サーバなら `http://127.0.0.1:8000`
- **NEXT_PUBLIC_BOARD_SYSTEM_URL**: Board System のトップ URL。例: `http://wl-sticky-note.local/boards`（/boards/taskboard 等に遷移）

## 5. Board System バックエンドのデプロイ

### 5.1 Python と venv

**backend のパス**: リポジトリを `releases` 配下に置いている場合は `.../releases/board-system/backend`、そうでなければ `.../board-system/backend`。

```bash
# Python 3.10 以上が無い場合（Ubuntu 22.04 なら python3 で可）
sudo apt update
sudo apt install -y python3 python3-venv python3-pip

# releases 配下の例（環境に合わせてパスを変更）
cd /var/www/wl-sticky-note/releases/board-system/backend
# または: cd /var/www/wl-sticky-note/board-system/backend

python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

**`.venv/bin/uvicorn` が無い場合**: 上記の `cd` で **board-system の backend ディレクトリ**に移動してから venv 作成と `pip install` を実行する。完了後 `which uvicorn` で絶対パスを確認し、systemd の `ExecStart=` をそのパスに合わせる（「トラブルシューティング」参照）。

### 5.2 環境変数と DB マイグレーション

```bash
cp .env.example .env
nano .env
# 本番例:
# DATABASE_URL=sqlite+aiosqlite:///./board.db
# POSTIT_BOARD_URL=http://127.0.0.1:3000  または http://wl-sticky-note.local
# （任意）OLLAMA_URL=http://172.16.1.242:11435/v1
```

```bash
# マイグレーション実行（カレントに board.db が作成される）
alembic upgrade head
```

### 5.3 systemd で常時起動（推奨）

```bash
sudo nano /etc/systemd/system/board-system-api.service
```

内容（**パスと User は環境に合わせてください**。`releases` 配下に置いている場合は `.../releases/board-system/backend` に。`User=` は実在するユーザー名に）:

```ini
[Unit]
Description=Board System API (FastAPI)
After=network.target

[Service]
Type=simple
User=devuser01
WorkingDirectory=/var/www/wl-sticky-note/releases/board-system/backend
Environment="PATH=/var/www/wl-sticky-note/releases/board-system/backend/.venv/bin"
ExecStart=/var/www/wl-sticky-note/releases/board-system/backend/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable board-system-api
sudo systemctl start board-system-api
sudo systemctl status board-system-api
```

## 6. Board System フロントエンドのデプロイ

ビルド時と実行時の環境変数で、**本番の API の URL** を指定します。Nginx で `/boards-api` を 8000 にプロキシする前提です。

### 6.1 環境変数とビルド

```bash
cd /var/www/wl-sticky-note/board-system/frontend
cp .env.local.example .env.local
nano .env.local
```

本番用の例（同一ドメインで Board System を /boards 以下で提供する場合）。basePath は本番ビルドで自動的に `/boards` になります。

```env
NEXT_PUBLIC_API_URL=http://wl-sticky-note.local/boards-api
NEXT_PUBLIC_LEGACY_BOARD_URL=http://wl-sticky-note.local
```

**重要**: Board System は **本番ビルド（NODE_ENV=production）で自動的に basePath `/boards`** が有効になります（`next.config.ts` で指定済み）。`.env.local` に API 用の URL を設定してからビルドしてください。

```bash
npm install
# .env.local に NEXT_PUBLIC_API_URL, NEXT_PUBLIC_LEGACY_BOARD_URL を設定済みなら
npm run build
```

### 6.2 PM2 で起動（ポート 3001）

```bash
# ecosystem.config.js が無い場合は次のコマンドで起動
PORT=3001 pm2 start npm --name "board-system-frontend" -- start
pm2 save
```

または `ecosystem.config.js` を用意する場合の例（`board-system/frontend/ecosystem.config.js`）:

```js
module.exports = {
  apps: [{
    name: 'board-system-frontend',
    script: 'node_modules/next/dist/bin/next',
    args: 'start -p 3001',
    cwd: '/var/www/wl-sticky-note/board-system/frontend',
    env: { NODE_ENV: 'production', PORT: '3001' },
    instances: 1,
    autorestart: true,
  }]
};
```

```bash
cd /var/www/wl-sticky-note/board-system/frontend
pm2 start ecosystem.config.js
pm2 save
```

## 7. Nginx に Board System 用のプロキシを追加

付箋ボード用の設定に、Board System の API とフロント用の `location` を追加します。

設定ファイルの場所:  
`/etc/nginx/sites-available/wl-sticky-note`  
（または 02_1_sticky-note の `nginx.conf` を参考にしたファイル）

**設定内容**（既存の `location /` より**前**に配置）:

- **`/boards-api/`** → 8000（Board System API）
- **`/boards/`** → 3001（Board System フロント。ページもアセットも /boards 以下）
- **`/_next/`** → **3000**（付箋ボードのアセット。Board System のアセットは /boards/_next/ で 3001 に届く）
- **`/`** → 3000（付箋ボード）
- **`/socket.io/`** → 3000（付箋ボード）

**全体の設定例は `docs/nginx-with-board-system.conf.example` を参照**し、`/etc/nginx/sites-available/wl-sticky-note` をそれに合わせてください。既存設定を手で直す場合は、**`location /_next/` を 3001 ではなく 3000 に**し、Board System 用に **`location /boards`**（スラッシュなし）を 3001 に追加し、`/taskboard` `/main` `/meeting` `/personal` の各 location は**削除**してください。

```bash
sudo nano /etc/nginx/sites-available/wl-sticky-note
sudo nginx -t
sudo systemctl reload nginx
```

## 8. アクセス確認

**本番で「Board System ボタンで付箋ボードが開く」「/boards が 404」になる場合**は、次を確認してください。

| 確認項目 | 対処 |
| ---------- | ------ |
| 付箋ボードの Board System リンク先 | `02_1_sticky-note/src/.env` に `NEXT_PUBLIC_BOARD_SYSTEM_URL=http://wl-sticky-note.local/boards` を設定し、**付箋ボードを再ビルド**（`npm run build`）してから PM2 再起動。 |
| Board System の /boards が動くこと | `cd board-system/frontend && rm -rf .next && npm run build` のあと `pm2 restart board-system-frontend --update-env`。本番ビルドで basePath `/boards` は自動有効。 |
| Nginx の /boards | `location /boards`（末尾スラッシュなし）が `proxy_pass http://127.0.0.1:3001;` になっていること。`/boards/` だと `/boards` 単体で「このページは現在機能していません」になる。 |

| 付箋ボード（本番ボード） | <http://wl-sticky-note.local/board/wl> |
| Board System（Task） | <http://wl-sticky-note.local/boards/taskboard> |

### Meeting ボード（Today → Morning 同期）と実行時刻の変更

- **仕様**: パーソナルボードの **Today** に D&D した付箋は、**毎朝 10:15** に Meeting ボード（MORNING）へコピーされる想定です。
- **時刻の変更**: アプリ内に時刻は持たず、**cron または systemd タイマー**で `POST /daily_reset/sync_to_morning` を呼ぶ時刻で決まります。**変更したい場合は cron の設定を編集**してください。
- **cron で 10:15 に実行する例**（本番サーバで `crontab -e`）:

  ```cron
  # 毎日 10:15 に Today → Meeting 同期（Board System API の URL は環境に合わせる）
  15 10 * * * curl -s -X POST http://127.0.0.1:8000/daily_reset/sync_to_morning
  ```

- **別の時刻にする例**: 先頭の `15 10` を変更します。例: `0 9` = 9:00、`30 10` = 10:30。
- **テスト**: 翌朝まで待たずに試す場合は、Meeting ページ（`/boards/meeting`）の **「今の Today を反映（テスト用）」** ボタンで手動実行できます。または `curl -X POST http://127.0.0.1:8000/daily_reset/sync_to_morning` をサーバ上で実行しても同じです。

## 11. トラブルシューティング

### 付箋ボードの「Board System」ボタンで付箋ボードが開く / Board System の各ページが 404

- **ボタンを押すと付箋ボードが開く**: 付箋ボードのリンク先が誤っています。`NEXT_PUBLIC_BOARD_SYSTEM_URL` は **ビルド時に** 埋め込まれるため、**.env を変えただけでは反映されません**。付箋ボード側で `02_1_sticky-note/src/.env` に **`NEXT_PUBLIC_BOARD_SYSTEM_URL=http://wl-sticky-note.local/boards`** を設定したうえで、**付箋ボードを再ビルド**してください。

  ```bash
  cd /var/www/wl-sticky-note/02_1_sticky-note/src   # または releases/02_1_sticky-note/src
  # .env に NEXT_PUBLIC_BOARD_SYSTEM_URL=http://wl-sticky-note.local/boards があるか確認
  rm -rf .next && npm run build
  pm2 restart wl-sticky-note --update-env
  ```

- **/boards や /boards/taskboard が 404**: **.next を削除してから**再ビルド。本番ビルドでは basePath `/boards` が自動で有効です。

  ```bash
  cd /var/www/wl-sticky-note/releases/board-system/frontend
  rm -rf .next && npm run build
  pm2 restart board-system-frontend --update-env
  ```

- **Pull したのに自動取り込みなど新機能が表示されない**: フロントは **ビルド成果物（.next）** を配信しているため、`git pull` のあとに **Board System フロントの再ビルドと PM2 再起動**が必要です。上記「Board System フロント」の手順（`rm -rf .next` → `npm run build` → `pm2 restart board-system-frontend --update-env`）を実行してください。ブラウザのキャッシュが残っている場合はスーパーリロード（Ctrl+Shift+R）やキャッシュ削除も試してください。
- **React #418（Hydration failed）や `task?_rsc=...` が 404**: RSC の取得失敗がハイドレーション不一致を起こしています。(1) **Nginx**: `location /boards/` の `proxy_pass` は **`http://127.0.0.1:3001`** のみにし、**末尾にパスを付けない**でください。`proxy_pass http://127.0.0.1:3001/boards/` のようにすると、転送先でパスがずれ RSC が 404 になります。`docs/nginx-with-board-system.conf.example` を参照。(2) **フロントをクリーンビルド**: `cd board-system/frontend && rm -rf .next && npm run build && pm2 restart board-system-frontend --update-env`。(3) **ブラウザ**: キャッシュ削除またはシークレットウィンドウで `/boards/taskboard` を開き直す。(4) 変更を反映するには必ずクリーンビルド（`rm -rf .next && npm run build`）を実行してください。
- **/boards/task だけ 404 で Meeting・Personal は OK**: ルートを **`/task` → `/taskboard`** に変更しました。**対処**: (1) `git pull` で最新を取得。(2) **PM2 が実際に使っているディレクトリ**でビルドする（下記「taskboard が 404 のとき」参照）。(3) ブラウザで **`/boards/taskboard`** を開く。
- **/boards/taskboard がまだ 404（curl で 3001 に聞いても 404）**: **PM2 の cwd に最新コードがない**か、**pull がローカル変更で失敗している**ことがあります。下記「releases 運用で taskboard が 404・pull で Aborting になる」を参照。
- **releases 運用で taskboard が 404・pull で Aborting になる**: PM2 の cwd が `releases/board-system/frontend` なのに、`git pull` はリポジトリルートで行うため **releases 配下は sparse-checkout に含まれず**、pull で更新されるのは `board-system/frontend` です。またローカル変更があると `git pull` が Aborting になります。**手順**: (1) **リポジトリルートで** `cd /var/www/wl-sticky-note` → `git stash`（または `git stash -u`）でローカル変更を退避。(2) `git pull` で最新を取得。(3) **ルートの board-system/frontend を releases にコピー**: `rsync -a --exclude=node_modules --exclude=.next --exclude=.env.local --exclude=.env /var/www/wl-sticky-note/board-system/frontend/ /var/www/wl-sticky-note/releases/board-system/frontend/`（.env.local と node_modules は残す。releases に .env.local が無ければ手動でコピーまたは作成）。(4) **releases の frontend でビルド**: `cd /var/www/wl-sticky-note/releases/board-system/frontend` → `rm -rf .next` → `npm install` → `npm run build` → `pm2 restart board-system-frontend --update-env`。(5) 確認: `curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3001/boards/taskboard` が `200`。必要なら `git stash pop` で退避した変更を戻す。
- Nginx で **`location /boards`**（末尾スラッシュなし）が 3001 にプロキシされていること。`location /boards/` だと `/boards` 単体にマッチせず「このページは現在機能していません」になる。`docs/nginx-with-board-system.conf.example` を参照。

---

- **502 Bad Gateway**: 各アプリ（3000 / 3001 / 8000）が起動しているか確認。`pm2 list`、`sudo systemctl status board-system-api`、`curl -s http://127.0.0.1:8000/health`。
- **Board System で API エラー**: フロントの `NEXT_PUBLIC_API_URL` が本番で `/boards-api` になっているか、ビルドし直しているか確認。
- **付箋削除が Task に反映されない**: 付箋ボードの `.env` の `BOARD_SYSTEM_API_URL=http://127.0.0.1:8000` と、バックエンドの `POSTIT_BOARD_URL` が正しいか確認。
- **付箋ボード（/board/wl）で CSS・JS・フォントが 404**: 付箋ボードの HTML が参照する `/_next/` は**付箋ボード（3000）**で配信する必要があります。Nginx で **`location /_next/` を 3000 に**プロキシしているか確認。誤って 3001 に振っていると、付箋ボードのアセットが Board System 側で 404 になります。**正しい構成**: `/_next/` → 3000、`location /boards` → 3001。**docs/nginx-with-board-system.conf.example** を参照。
- **/boards が「このページは現在機能していません」**: Nginx の **`location /boards/`**（末尾スラッシュあり）だと、URL が **`/boards`** だけのときにマッチせず、付箋ボード（3000）に送られてエラーになります。**`location /boards`**（スラッシュなし）に変更するか、**`location = /boards { return 302 .../boards/; }`** を追加してから **`location /boards/`** で 3001 にプロキシ。`docs/nginx-with-board-system.conf.example` を参照。
- **/boards が開くが 404・メニューが正常に表示されない**: **必ず .next を削除してから**再ビルドしてください。本番（`npm run build`）では `next.config.ts` により自動で basePath `/boards` が有効になります。

  ```bash
  cd /var/www/wl-sticky-note/releases/board-system/frontend
  rm -rf .next
  npm run build
  pm2 restart board-system-frontend --update-env
  ```

  Nginx で **`location = /boards { return 302 .../boards/; }`** と **`location /boards/`** が設定されていること。`docs/nginx-with-board-system.conf.example` を参照。
- **Board System（/boards/taskboard）で CSS・JS が 404**: Board System は basePath `/boards` でビルドしているか確認。Nginx で **`location /boards`** が 3001 にプロキシされていること。本番では **`npm run build` のあと `npm start`** で起動すること。
- **board-system-api が status=217/USER で落ちる**: systemd の `User=` が誤っているか、`WorkingDirectory` / `ExecStart` のパスが実在しません。`User=` を実際のユーザー名（例: devuser01）に、パスを **releases** を使っている場合は `.../releases/board-system/backend` に合わせてから `sudo systemctl daemon-reload` → `sudo systemctl restart board-system-api`。
- **status=203/EXEC で「uvicorn: No such file or directory」**: systemd の `ExecStart=` のパスが誤っています。**実際の uvicorn の場所**を確認してから service を修正。例: `ls /var/www/wl-sticky-note/releases/board-system/backend/.venv/bin/uvicorn`。無い場合は `cd .../backend && python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt` で venv を作り直し、`which uvicorn` でパスを確認して `/etc/systemd/system/board-system-api.service` の `ExecStart=` をその絶対パスに合わせる。`sudo systemctl daemon-reload` → `sudo systemctl restart board-system-api`。
- **sqlite3.OperationalError: attempt to write a readonly database**: Board System API が **DB ファイル（board.db）やそのディレクトリに書き込めていません**。systemd で動かしているユーザー（例: devuser01）に、**backend ディレクトリと board.db の書き込み権限**を付与する。例: `sudo chown -R devuser01:devuser01 /var/www/wl-sticky-note/releases/board-system/backend`、既に board.db がある場合は `sudo chown devuser01:devuser01 /var/www/wl-sticky-note/releases/board-system/backend/board.db`。その後 `sudo systemctl restart board-system-api`。
- **PM2 で board-system-frontend が "Invalid project directory provided, no such directory: .../3001"**: **`next start -p 3001 3001`** のようにポートが二重になっている。PM2 起動時に **余計な引数を付けない**こと。`pm2 start npm -- start 3001` は誤り（`npm run start 3001` となり next に 3001 が二重で渡る）。正しくは **`pm2 start ecosystem.config.js`** または **`pm2 start npm --name "board-system-frontend" -- start`**（`start` の後に何も付けない）。その後 `pm2 delete board-system-frontend` で消してから起動し直す。
- **付箋ボード（http://.../board/wl）が 404**: (1) アクセスログに `GET /board/wl` が 404 で出ているのに **curl 127.0.0.1:3000/board/wl は 200** なら、**Nginx に `location /` が抜けている**。付箋ボード用には **`location /`** と **`location /socket.io/`** の両方を 3000 にプロキシするブロックが必須。`docs/nginx-with-board-system.conf.example` の末尾（付箋ボード用）をコピーして追加する。(2) 別の Nginx server にリクエストが流れている場合も同様に確認。**sites-enabled に他サイト（例: brainstorming）があるとき**、同じ IP や `default_server` を持っていると、付箋ボード用の server より先にマッチして 404 になる。対処: ブラウザで **ホスト名（<http://wl-sticky-note.local/board/wl）>** で開く。または他サイトの `server_name` からその IP を外す／付箋ボード用を `listen 80 default_server` にする。(2) **他サイト（例: brainstorming）で `server_name _` を使っている場合**、同じ IP でアクセスするとそちらに流れることがある。付箋ボード用の server に **`listen 80 default_server;`** を付け、他サイトの `listen` からは `default_server` を外す。設定例は `docs/nginx-with-board-system.conf.example`。(3) Nginx に **`location /board`**（s なし）が 3001 に振っていないかも確認。
- **付箋の受け渡しができない・パーソナルでメモを投稿できない**: (1) 付箋ボード（/board/wl）が 404 だと Task の「付箋ボードから取り込み」が使えない。(2) パーソナル投稿や D&D で **Internal Server Error（500）** が出る場合、バックエンドで例外が発生している。**`journalctl -u board-system-api -n 100 --no-pager`** で直近のログと Python のトレースバックを確認。本番では `create_sticky_note` 内の AI 呼び出しで例外が出ても 500 にならないようガード済み。それでも 500 が出る場合は `move_to_personal` 等の別エンドポイントのエラーなので、ログの traceback を手がかりに修正する。(3) バックエンドの `.env` で **`POSTIT_BOARD_URL=http://wl-sticky-note.local`**、フロントの `.env.local` で **`NEXT_PUBLIC_LEGACY_BOARD_URL=http://wl-sticky-note.local`** を確認。
