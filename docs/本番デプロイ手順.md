# 本番デプロイ手順（付箋ボード ＋ Board System）

本ドキュメントは **wl-sticky-note（付箋ボード）** と **Board System（Wonder Rinko）** を同一サーバに本番デプロイする手順です。

- **サーバ**: IP `172.16.1.81` / ドメイン `wl-sticky-note.local`
- **リポジトリ**: wlinko-pj（02_1_sticky-note と board-system を取得）
- **構成**: 付箋ボード（3000）＋ Board System API（8000）＋ Board System フロント（3001）を Nginx で1つのドメインにまとめます。

---

## 1. 前提条件

- Ubuntu Server（20.04 LTS 以降推奨）
- SSH と sudo が使えること
- Git 2.25 以上（sparse-checkout 用）
- **Python 3.10 以上**（Board System バックエンド用）

---

## 2. サーバに SSH 接続

```bash
ssh user@172.16.1.81
# または
ssh user@wl-sticky-note.local
```

---

## 3. リポジトリを clone する

付箋ボードと Board System の両方が必要なため、**02_1_sticky-note** と **board-system** を sparse-checkout で取得します。

```bash
sudo mkdir -p /var/www/wl-sticky-note
sudo chown $USER:$USER /var/www/wl-sticky-note
cd /var/www/wl-sticky-note

# wlinko-pj を sparse で clone（YOUR_ORG を実際の GitHub ユーザー/組織名に置き換え）
git clone --filter=blob:none --sparse https://github.com/YOUR_ORG/wlinko-pj.git .

# 付箋ボードと Board System をチェックアウト
git sparse-checkout set 02_1_sticky-note board-system
git checkout
```

結果として次のディレクトリができます。

- `/var/www/wl-sticky-note/02_1_sticky-note/` … 付箋ボード
- `/var/www/wl-sticky-note/board-system/` … Board System（backend / frontend）

---

## 4. 付箋ボードのデプロイ

付箋ボードは既存の `deploy.sh` でデプロイします（Node.js / PM2 / Nginx の初回設定を含む）。

```bash
cd /var/www/wl-sticky-note/02_1_sticky-note/src
chmod +x deploy.sh
./deploy.sh
```

この時点では Nginx は付箋ボードのみをプロキシしています。Board System 用の設定は後で追加します。

### 4.1 付箋ボードの本番用 .env（Board System 連携）

Board System と連携する場合は、`02_1_sticky-note/src/.env` を用意し、PM2 再起動します。

```bash
cd /var/www/wl-sticky-note/02_1_sticky-note/src
cp .env.example .env
# 以下を編集（本番のドメインに合わせる）
# BOARD_SYSTEM_API_URL=http://127.0.0.1:8000
# NEXT_PUBLIC_BOARD_SYSTEM_URL=http://wl-sticky-note.local
# （同一サーバなので API は 127.0.0.1:8000、フロントは同じドメインで /task 等）
nano .env
pm2 restart wl-sticky-note --update-env
```

- **BOARD_SYSTEM_API_URL**: 同一サーバなら `http://127.0.0.1:8000`
- **NEXT_PUBLIC_BOARD_SYSTEM_URL**: ブラウザからアクセスする URL。例: `http://wl-sticky-note.local`（Board System は同じドメインの /task, /main 等で提供）

## 5. Board System バックエンドのデプロイ

### 5.1 Python と venv

```bash
# Python 3.10 以上が無い場合（Ubuntu 22.04 なら python3 で可）
sudo apt update
sudo apt install -y python3 python3-venv python3-pip
cd /var/www/wl-sticky-note/board-system/backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 5.2 環境変数と DB マイグレーション

```bash
cp .env.example .env
nano .env
# 本番例:
# DATABASE_URL=sqlite+aiosqlite:///./board.db
# POSTIT_BOARD_URL=http://127.0.0.1:3000  または http://wl-sticky-note.local
# （任意）GEMINI_API_KEY=...
```

```bash
# マイグレーション実行（カレントに board.db が作成される）
alembic upgrade head
```

### 5.3 systemd で常時起動（推奨）

```bash
sudo nano /etc/systemd/system/board-system-api.service
```

内容（`WorkingDirectory` と `ExecStart` のパスは環境に合わせてください）:

```ini
[Unit]
Description=Board System API (FastAPI)
After=network.target

[Service]
Type=simple
User=YOUR_USER
WorkingDirectory=/var/www/wl-sticky-note/board-system/backend
Environment="PATH=/var/www/wl-sticky-note/board-system/backend/.venv/bin"
ExecStart=/var/www/wl-sticky-note/board-system/backend/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable board-system-api
sudo systemctl start board-system-api
sudo systemctl status board-system-api
```

## 6. Board System フロントエンドのデプロイ

ビルド時と実行時の環境変数で、**本番の API の URL** を指定します。Nginx で `/boards-api` を 8000 にプロキシする前提です。

### 6.1 環境変数とビルド

```bash
cd /var/www/wl-sticky-note/board-system/frontend
cp .env.local.example .env.local
nano .env.local
```

本番用の例（同一ドメインで /boards-api に API を置く場合）:

```env
NEXT_PUBLIC_API_URL=http://wl-sticky-note.local/boards-api
NEXT_PUBLIC_LEGACY_BOARD_URL=http://wl-sticky-note.local
```

```bash
npm install
npm run build
```

### 6.2 PM2 で起動（ポート 3001）

```bash
# ecosystem.config.js が無い場合は次のコマンドで起動
PORT=3001 pm2 start npm --name "board-system-frontend" -- start
pm2 save
```

または `ecosystem.config.js` を用意する場合の例（`board-system/frontend/ecosystem.config.js`）:

```js
module.exports = {
  apps: [{
    name: 'board-system-frontend',
    script: 'node_modules/next/dist/bin/next',
    args: 'start -p 3001',
    cwd: '/var/www/wl-sticky-note/board-system/frontend',
    env: { NODE_ENV: 'production', PORT: '3001' },
    instances: 1,
    autorestart: true,
  }]
};
```

```bash
cd /var/www/wl-sticky-note/board-system/frontend
pm2 start ecosystem.config.js
pm2 save
```

## 7. Nginx に Board System 用のプロキシを追加

付箋ボード用の設定に、Board System の API とフロント用の `location` を追加します。

設定ファイルの場所:  
`/etc/nginx/sites-available/wl-sticky-note`  
（または 02_1_sticky-note の `nginx.conf` を参考にしたファイル）

**追加する内容**（既存の `server { ... }` ブロック内に、既存の `location /` より**前**に、より具体的な location を並べる）:

```nginx
    # Board System API（/boards-api/ → バックエンド 8000）
    location /boards-api/ {
        proxy_pass http://127.0.0.1:8000/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # Board System フロント（Next.js 3001）
    location /_next/ {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
    location /task { proxy_pass http://127.0.0.1:3001; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; proxy_cache_bypass $http_upgrade; }
    location /main { proxy_pass http://127.0.0.1:3001; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; proxy_cache_bypass $http_upgrade; }
    location /morning { proxy_pass http://127.0.0.1:3001; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; proxy_cache_bypass $http_upgrade; }
    location /personal { proxy_pass http://127.0.0.1:3001; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; proxy_cache_bypass $http_upgrade; }
```

編集例:

```bash
sudo nano /etc/nginx/sites-available/wl-sticky-note
# 上記の location を、既存の「location /」の直前に挿入
sudo nginx -t
sudo systemctl reload nginx
```

**注意**: `location /` は付箋ボード（3000）用のままにし、`/task` `/main` `/morning` `/personal` `/boards-api/` `/_next/` だけ 3001 / 8000 に振り分けます。

## 8. アクセス確認

| 用途 | URL |
|------|-----|
| 付箋ボード（本番ボード） | http://wl-sticky-note.local/board/wl |
| Board System（Task） | http://wl-sticky-note.local/task |
| Board System（Meeting） | http://wl-sticky-note.local/morning |
| Board System（パーソナル） | http://wl-sticky-note.local/personal/hori など |
| Board System API ヘルス | http://wl-sticky-note.local/boards-api/health |

付箋ボードのツールバー「Board System」は、`NEXT_PUBLIC_BOARD_SYSTEM_URL=http://wl-sticky-note.local` にしておけば http://wl-sticky-note.local/task などに遷移します。

## 11. トラブルシューティング

- **502 Bad Gateway**: 各アプリ（3000 / 3001 / 8000）が起動しているか確認。`pm2 list`、`sudo systemctl status board-system-api`、`curl -s http://127.0.0.1:8000/health`。
- **Board System で API エラー**: フロントの `NEXT_PUBLIC_API_URL` が本番で `/boards-api` になっているか、ビルドし直しているか確認。
- **付箋削除が Task に反映されない**: 付箋ボードの `.env` の `BOARD_SYSTEM_API_URL=http://127.0.0.1:8000` と、バックエンドの `POSTIT_BOARD_URL` が正しいか確認。
