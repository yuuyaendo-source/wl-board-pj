# 役割
あなたはPython (OpenCV/Flask) と Next.js のエキスパートです。
現在開発中の「AI-Board」プロジェクトに対し、以下の3つの運用改善機能を実装してください。

# 1. プロジェクト構成の前提
- Frontend: Next.js (Port 3000)
- Backend: Python Flask (Port 5000)
- Camera: OpenCVで映像取得 -> Flaskで処理 -> Frontendへ通知

# 実装タスク

## タスクA：物理座標とデジタル座標の同期 (台形補正)
**ファイル:** `sticky_note_detector.py` (Python)
**目的:** カメラの設置角度に関わらず、物理ボードの「右上」に貼った付箋が、デジタル画面の「右上」に表示されるようにする。

**指示:**
1. **キャリブレーション機能の追加:**
   - アプリ起動時（または特定のキー `c` を押した時）に、OpenCVウィンドウ上で「プロジェクター投影範囲の四隅」をマウスでクリックして指定するモードを作成してください。
   - 順序: 左上 -> 右上 -> 右下 -> 左下。
2. **ホモグラフィ変換の実装:**
   - 指定された4点を使用し、カメラ視点の画像を「正対した長方形（デジタルキャンバスの比率）」に変換するホモグラフィ行列を計算してください。
   - 付箋検知は、この「変換後の画像」に対して行ってください。これにより、斜めから撮影しても付箋が正方形として認識されます。
3. **座標の正規化:**
   - 検知した付箋の中心座標 `(x, y)` を、キャンバス全体に対するパーセンテージ `(0.0 〜 1.0)` に変換して出力してください。

## タスクB：付箋サイズの自動最適化
**ファイル:** `sticky_note_detector.py` (Python) および Frontendコンポーネント
**目的:** カメラとの距離によって付箋のサイズが狂うのを防ぐ。

**指示:**
1. **Python側:**
   - 付箋を検知した際、ボード全体（変換後画像）の幅に対する「付箋の幅の比率 (`ratio_w`)」を計算し、APIレスポンスに含めてください。
2. **Next.js側:**
   - 付箋データを表示する際、基本的にはCSSで読みやすい固定サイズ（例: `160px x 160px`）を適用してください。
   - ただし、受信した `ratio_w` が閾値（例: 0.2以上。模造紙など）を超えた場合のみ、表示サイズを2倍にするなどの条件分岐を追加してください。

## タスクC：スマホ撮影機能 (アプリレス対応)
**ファイル:** Next.js側の新規ページ `/src/app/mobile/upload/page.tsx` (App Router想定)
**目的:** 専用カメラがない環境でも、スマホから手軽に付箋を取り込めるようにする。

**指示:**
1. **スマホ専用UIの作成:**
   - URL: `/mobile/upload`
   - デザイン: Tailwind CSSを使用し、中央に巨大な「カメラを起動」ボタンを配置したシンプルなUI。
   - 機能: `<input type="file" accept="image/*" capture="environment" />` を使用し、スマホの背面カメラを直接起動する。
2. **アップロード処理:**
   - 撮影された写真を、Pythonサーバーの新規エンドポイント `/api/upload_image` にPOST送信する。
   - 送信中はローディング表示、完了後は「ボードに送信しました！」というトーストを表示する。
3. **Python側エンドポイント作成:**
   - `/api/upload_image` で画像を受け取り、既存の「付箋検知ロジック」を再利用して付箋を切り出し、メインの処理フロー（OCR -> Gemini -> Voicevox）に流し込んでください。

# 注意点
- 既存の Voicevox 連携コードや Gemini API 連携コードは壊さないでください。
- Python側で、Webカメラ映像からの検知ロジックを関数化し、「Webカメラループ」と「スマホアップロード」の両方から呼べるようにリファクタリングしてください。
