## 2. 推奨実装順序（プラン）

### 案A: 受付モードの完成度を先に上げる
1. **受付モードのトラッキング調整**  
   - 改善指示書6の「※受付モードのトラッキングは調整が必要」に対応。  
   - ポーズ・表情のずれ修正、検出安定化など。
2. **Phase 2B: 音声統合**  
   - 改善議論で合意済み。WebRTC リアルタイム音声・双方向・リップシンク。
3. **Phase 2C: UI改善**  
   - 接続状態・音声レベル・ミュート/音量。
4. **パーソナルモード拡張**  
   - 自動切替（社員検知）、名前・顔一致（任意切り替え時の認証）。

### 案B: 音声を最優先にする
1. **Phase 2B: 音声統合**  
   - 受付対応の「声」を通すことを最優先。
2. **Phase 2C: UI改善**  
   - 音声周りのUI（接続・音量・ミュート）。
3. **受付モードのトラッキング調整**  
   - 見た目の仕上がりを調整。
4. **パーソナルモード拡張**  
   - 自動切替・名前顔一致。

### 案C: パーソナルモードを先に形にする
1. **パーソナルモードの自動切替（社員検知）**  
   - カメラで顔検知 → パーソナルモードに自動切替（簡易版でも可）。
2. **パーソナルモードの名前・顔一致**  
   - 任意切り替え時に「誰か」を識別する仕組み（簡易認証）。
3. **受付モードのトラッキング調整**  
   - ポーズ・表情の調整。
4. **Phase 2B / 2C**  
   - 音声統合とUI改善。

## 3. 各ブロックの実装イメージ（概要）

### 受付モードのトラッキング調整
- operator.html: MediaPipe/Kalidokit のパラメータ（`minDetectionConfidence` 等）、解像度・フレームレート。
- index.html: 受信した `tracking_data` の VRM へのマッピング（ポーズ・表情のスケール/オフセット）。
- 必要なら `レセプション_トラッキング_切り分け.md` の手順で再現しつつ修正。

### Phase 2B: 音声統合
- 既存の WebRTC（SimplePeer）を音声ストリームに対応させる、または音声専用の Peer を追加。
- 受付→ディスプレイ: オペレーターのマイク音声をディスプレイで再生＋リップシンク（AudioContext 等）。
- ディスプレイ→受付: エントランス側マイクをオペレーター側で再生（双方向）。
- オプション: VOICEVOX 変換モード（音声→テキスト→VOICEVOX→再生）は後から追加可能。

### Phase 2C: UI改善
- 接続状態: 「受付接続中」「音声接続中」などの表示。
- 音声レベルメーター、ミュート/音量スライダー（operator・index 両方で必要に応じて）。

### パーソナルモード拡張
- **自動切替**: カメラで顔検出 → 登録済み社員か簡易判定 → パーソナルモードに切替。  
  - 社員登録は「顔写真 or 特徴ベクトル」を簡易ストアに持つ想定。
- **名前・顔一致**: 任意で Personal を選んだときに「名前選択 or ログイン」→ カメラで顔照合して有効化。  
  - 初回は「名前リスト＋顔登録」の簡易フローでよい。

## 4. どれから着手するか

- **「受付の見た目を安定させたい」** → 案A（トラッキング調整から）。
- **「受付で声を通したい」** → 案B（Phase 2B から）。
- **「パーソナルモードを早く使いたい」** → 案C（パーソナル拡張から）。

次の一歩として「どの案で進めるか」と「その中のどのブロックから着手するか」を決めると、具体的なタスクに分解しやすいです。
