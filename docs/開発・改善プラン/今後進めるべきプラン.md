# 今後進めるべきプラン（wlinko-pj）

本ドキュメントは、wlinko-pj 全体の**現状の整理**と**今後進めるべき開発・改善**のプランです。  
日付を追記して随時更新してください。

---

## 1. 現状の整理（2026年2月時点）

### 1.1 構成アプリと役割

| アプリ | 役割 | 本番・開発 |
|--------|------|------------|
| **wl-sticky-note（02_1_sticky-note）** | 付箋ボード。複数人で付箋を追加・編集・リアルタイム同期。ボード名保存・削除はボードから直接削除。 | **正規版1本**。本番: wl-sticky-note.local (172.16.1.81)。デプロイは `02_1_sticky-note/docs/デプロイ手順.md`。 |
| **AI-Board（02_2_AI-Board）** | カメラで付箋検知→Sticky-note へ送信、AIコメント・音声、3Dアバター。3モード（AI-Board / Reception / Personal）。 | 本番 URL: **http://wl-ai-board.local**（サーバー移動後。DNS/hosts で名前解決）。本番送信は `POSTIT_BOARD_URL=http://wl-sticky-note.local`。 |
| **Wonder Rinko Desktop（02_3_WL_Desktop_app）** | 社員PC常駐。付箋ボードの新付箋をポーリングしてトースト通知、パーソナルモードへのDeep Link。 | 本番 Sticky-note に接続可能。配布は MSI またはフォルダ＋起動手順（会社ポリシーで exe 単体は不可）。 |

### 1.2 本番連携の状態

- **Sticky-note**: 本番で稼働。`/board/wl` が AI-Board・Desktop の連携先。
- **Desktop**: 本番の付箋ボードに接続・トレイから開く。新付箋通知はポーリングで実装済み（要: 本番で `/api/boards/wl/summary` が 200 であること）。
- **AI-Board**: 本番に付箋を送るには `POSTIT_BOARD_URL=http://wl-sticky-note.local` と `board_id: wl` の設定が必要。未設定時はローカル Sticky-note 向け。

詳細は **02_1_sticky-note/docs/本番連携の整理.md** を参照。

### 1.3 直近で完了したこと

- Sticky-note: 正規版1本化、デプロイ手順・README の作り直し、メニューバー改善（付箋作成・アイコン・ツールチップ・並び順・参加者削除）、ボード名保存、付箋削除を「右下移動」から「ボードから削除」に変更。
- Desktop: MSI 配布対応、付箋ボード接続テストメニュー、ポーリング初回即実行。
- ドキュメント: デプロイ手順の一本化（docs/デプロイ手順.md）、本番連携の整理。

## 2. 短期（すぐに進められること）

### 2.1 本番連携の安定化

- [ ] **Desktop の付箋通知**: 本番で `/api/health` および `/api/boards/wl/summary` が 200 になることを確認。404 の場合はサーバで `server.js` が動いているか・最新デプロイかを確認（本番連携の整理.md の「6. /api/boards/wl/summary が 404 になる場合」参照）。
- [ ] **AI-Board → 本番送信**: 本番運用で付箋を Sticky-note に送る場合、AI-Board の `.env` に `POSTIT_BOARD_URL=http://wl-sticky-note.local`、`config.json` の `board_id: wl` を設定し、付箋検知で本番ボードに反映することを確認。
- [ ] **Desktop 配布**: 本番連携確認後、MSI またはフォルダ＋起動手順でメンバーに配布。`02_1_sticky-note/docs/AI-Board・Desktopアプリの開発の進め方.md` の手順に従う。

### 2.2 Sticky-note の軽微な改善

- 改善要望があれば **02_1_sticky-note/docs/WSN改善指示書.md** に追記し、優先度をつけて対応。
- 既存の **02_1_sticky-note/機能追加指示書1.md** や **docs/開発・改善プラン/改善指示書*** のうち、Sticky-note に関係する項目を必要に応じて実施。

## 3. 中期（数週間〜数ヶ月）

### 3.1 AI-Board の完成度向上

**次の実装プラン.md** の案（A/B/C）に沿って、どれを優先するか決める。

- **受付モードのトラッキング調整**: ポーズ・表情のずれ修正、検出安定化。`docs/開発ドキュメント/レセプション_トラッキング_切り分け.md` を参照。
- **Phase 2B: 音声統合**: WebRTC リアルタイム音声・双方向・リップシンク（改善議論で合意済み）。
- **Phase 2C: UI改善**: 接続状態インジケーター、音声レベル・ミュート/音量。
- **パーソナルモード拡張**: 自動切替（社員検知）、名前・顔一致（任意切り替え時の認証）。`docs/開発ドキュメント/パーソナル_名前顔管理_設計.md` 参照。

### 3.2 Desktop アプリの拡張

- **02_3_WL_Desktop_app/README.md** の「今後の拡張」に記載のとおり、アバター表示ウィンドウ・音声・適切なタイミングでのニュース・付箋投稿の促しなど、優先度をつけて検討。
- 配布後のフィードバック（通知が届かない、MSI の不具合など）を **本番連携の整理.md** や本プランに反映。

### 3.3 ドキュメント・運用の維持

- デプロイ手順は **02_1_sticky-note/docs/デプロイ手順.md** のみを正とする。変更があればその都度更新。
- 本番サーバの更新手順（git pull → build → pm2 restart）を運用で定着させる。
