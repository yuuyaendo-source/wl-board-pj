# 課題
付箋を検知した際、解析処理（OCRやAPI通信）が走ると、その間OpenCVのメインループ（`cv2.imshow`やキャリブレーション操作）がフリーズしてしまいます。

# 指示
Pythonの標準ライブラリ `threading` と `queue` を使用して、解析処理を「非同期（別スレッド）」に分離してください。

## リファクタリング要件

1. **メインスレッド（UI担当）**
   - カメラ映像の取得、HSV変換、画面描画、マウスイベント処理に専念する。
   - 付箋を検知したら、その画像データを `RequestQueue` に入れるだけにする（待機しない）。
   - 「解析中...」のようなステータス文字を画面隅に表示する機能を追加する。

2. **ワーカースレッド（解析担当）**
   - バックグラウンドで常に `RequestQueue` を監視する。
   - キューに画像が入ってきたら、重い処理（OCR -> Gemini API -> Voicevox）を実行する。
   - 処理が終わったら、結果（テキストなど）をメインスレッド側が参照できる変数（またはコールバック）に格納する。

3. **排他制御とクールダウン**
   - 短時間に大量のリクエストが飛ばないよう、解析中は次のリクエストを受け付けないフラグ管理（`is_processing`）を追加してください。

これにより、解析APIを叩いている最中でも、キャリブレーションのスライダーが滑らかに動くようにしてください。
