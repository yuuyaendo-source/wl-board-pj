# 改善計画9：タスクローテーション（停滞タスクの自動並び替え）機能の実装プラン

タスクレーンに長期間滞留しているタスクの視認性を下げる（循環させる）ため、1日おきに「期限が10日以内のタスク」を除いたタスクの上部を、レーンの一番下に自動で移動（ローテーション）させる機能を実装します。

## User Review Required

> [!IMPORTANT]
> **「1日おき」の判定条件について**
> 毎日実行される日次バッチ（`run_8am`）の中で、JSTでの実行日の日付（基準日からの経過日数など）を判定し、2日に1回実行する簡易的な実装を想定しています（例: `today.toordinal() % 2 == 0` の日に実行）。
> 
> **対象ボードと移動件数について**
> この並び替えは **Task Board** および **Personal Board** の双方を対象とします。
> - **Task Board**: 各列（「完了」を除く）において、上から **10個** のタスクをローテーション。
> - **Personal Board**: `INBOX` レーンにおいて、上から **3個** のタスクをローテーション。
> 
> 「期限が10日以内」のタスクは優先度が高いとみなし、ローテーションの対象外（現在の上部の位置をキープ）とします。

## Proposed Changes

### Backend 修正

#### [MODIFY] routers/daily_reset.py
- 朝 8:00 に実行される `run_8am` API 内で、既存の `apply_due_date_rules(db)` の**実行後**に、新しい自動並び替え関数 `rotate_stale_tasks(db)` を呼び出します（期限間近のタスクが `Today` へ移動した後の `INBOX` に対して処理を行うため）。
- `rotate_stale_tasks(db)` の詳細仕様：
  - **実行頻度判定**: JST現在日の `today = datetime.now(ZoneInfo("Asia/Tokyo")).date()` に対し、`today.toordinal() % 2 == 0` で判定（該当しない日は `{"skipped": True}` を返す）。
  - **対象取得**:
    - **Task Board**: `board_type == TASK` で、`matrix_quadrant` が「完了（5）」以外の各象限（列）にある配置を取得し、`sort_order` 昇順でソート。
    - **Personal Board**: `board_type == PERSONAL` で、各ユーザーの `Lane.INBOX` にある配置を取得し、`sort_order` 昇順でソート。
  - **除外条件**: `due_date` が今日から10日以内のタスク（`0 <= (due_date - today).days <= 10` または期限切れ）はローテーションから除外（先頭側の位置を維持）。
  - **並び替え実行条件**:
    - Task Boardの各列: 除外されなかったタスクが **11件以上** 存在する場合にのみ実施。
    - Personal Boardの各INBOX: 除外されなかったタスクが **4件以上** 存在する場合にのみ実施。
  - **並び替え＆正規化**:
    - 除外されなかったタスクのうち、先頭の規定件数（Task: 10件, Personal: 3件）を抽出。
    - `[先頭維持タスク + 規定件数以降のタスク] + [抽出した先頭タスク]` の順にリストを再構成。
    - リスト全体に対して、`sort_order` を `0` から連番で再採番して保存（`sort_order` の肥大化を防ぎ、フロントエンドの D&D 順序と整合性を保つ）。
  - **戻り値/ログ**: 対象となったボード・列ごとの移動件数を記録し、ロガーに出力するとともに `run_8am` のレスポンスに含めます。

#### [MODIFY] routers/board_placements.py (必要に応じて)
- バッチ処理内での `sort_order` の再採番ロジックが、既存のドラッグ＆ドロップ時の並び替え処理（`reorder` など）と競合・矛盾しないよう、安全なトランザクション内で実装します。

## Verification Plan

### Automated Tests
- バックエンドの自動ローテーションロジック `rotate_stale_tasks` に対する単体テストを追加。
  - JSTでの実行日が条件を満たさない場合、処理がスキップされること。
  - 期限が10日以内のタスクが抽出対象から正しく除外され、移動しないこと。
  - 対象タスク数が実行条件（Task: 11件以上、Personal: 4件以上）を満たさない場合、処理がスキップされること。
  - 条件を満たす場合、Taskボードは10件、Personalボードは3件が末尾に移動し、全体が `0` からの連番に再採番されること。
  - `apply_due_date_rules` との実行順序が正しく、先に `Today` に移動すべきタスクがローテーションの計算に影響しないこと。

### Manual Verification
- Task Board（各列）と Personal Board（INBOX レーン）に多数のタスク（期限設定なし、10日以内の期限、10日以上先の期限が混在）を配置する。
- 日次バッチ（`POST /daily_reset/run_8am`）を手動でトリガーする。
- 期限が10日以内のタスクは位置をキープし、それ以外のタスクが規定数（Task: 10個, Personal: 3個）だけ一番下（末尾）に移動していることをフロントエンド画面で確認する。
- 移動後、同じ列内でタスクをドラッグ＆ドロップし、並び替えが正常に機能すること（`sort_order`の正規化が正しいこと）を確認する。
