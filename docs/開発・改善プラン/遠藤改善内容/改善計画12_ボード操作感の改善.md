# 改善計画12：Google Map風の直感的なボード操作と複数付箋選択の実装プラン

## 1. 概要・変更目的
付箋ボードの操作感をMiroやFigmaなどのモダンなコラボレーションツールに近づけ、より直感的で効率的な操作を実現します。
キャンバスの空きスペースでのドラッグ操作の役割を見直し、業界標準に沿った操作体系に再構築します。

1. **パン移動（画面スクロール）**: 「Spaceキー＋左ドラッグ」または「ホイール押し込み（中ボタンドラッグ）」に割り当てます。
2. **複数付箋選択（範囲選択）**: キャンバスの空きスペースでの「左ドラッグ」を、矩形選択（Selection Box）に割り当てます。
3. **追加選択（トグル）**: 「Shiftキー」を用いたクリックや範囲選択により、現在の選択状態を維持したまま付箋の追加・解除を行えるようにします。
4. **複数付箋の同時移動**: 選択状態の付箋をまとめてドラッグ移動できるように拡張します。

---

## 2. 具体的な実装仕様

### ① パン移動（キャンバスのスクロール）の操作変更
`src/app/board/[id]/page.js` におけるマウスイベント処理を改修します。
- **パン移動開始条件**: 
  - `Spaceキー` を押しながらの左ドラッグ（`e.button === 0 && isSpacePressed`）
  - マウスホイール押し込みによるドラッグ（`e.button === 1`）
- **テキスト入力との干渉防止・スクロール無効化**:
  - `keydown` / `keyup` イベントでSpaceキーの状態を管理する際、`e.target.closest('input, textarea')` の場合は文字入力とみなし、Spaceキーのパン移動判定を無視します。
  - キャンバス上でSpaceキーを押した際にブラウザ標準の「下スクロール」が発動しないよう、適切に `e.preventDefault()` を適用します。
- パン移動時はカーソルを `grab` / `grabbing` に変更し、コンテナの `scrollLeft` / `scrollTop` を操作します。

### ② 複数付箋選択（矩形選択）と追加選択の実装
- **範囲選択開始条件**: Spaceキーを押さずに、キャンバスの空き領域を左ドラッグ（`e.button === 0 && !isSpacePressed`）。
- **矩形の描画と座標計算（始点・終点の正規化）**: 
  - 画面上のマウス座標（クライアント座標）と、キャンバスの内部座標を `scale`（ズーム倍率）を用いて正しく変換し、半透明の選択ボックスを描画します。
  - 右下から左上へのドラッグなど、任意の方向のドラッグでも正しく矩形を描画・判定できるよう、`Math.min` / `Math.max` を用いて選択矩形の基準座標（左上の `x`, `y`）および幅・高さを正規化（Normalize）します。
- **交差判定（Intersection Test）**: 
  - 正規化された選択矩形と各付箋の座標（`x`, `y`, `width`, `height`）の重なりを判定し、`selectedNoteIds`（選択中の付箋ID配列）を更新します。
- **追加選択（Shiftキー）**: `e.shiftKey` が押されている場合は、既存の `selectedNoteIds` に対して交差した付箋をトグル（追加・解除）します。押されていない場合は新規選択とします。

### ③ 複数付箋の同時移動
- **一括移動の処理**: 
  - 各 `StickyNote.js` は自身が選択されているか (`isSelected`) を受け取り、ドラッグ開始時に親 (`page.js` 側) へ移動差分 (`dx`, `dy`) を通知する構造にリファクタリングします。
- **ピン留め（pinned）付箋の除外**: 
  - 選択範囲に `pinned: true` の付箋が含まれている場合、それらは一括ドラッグ時の移動対象から除外し、その場に固定したままにします。
- **通信パフォーマンスの最適化（負荷対策）**: 
  - ドラッグ中（`mousemove`）はローカルの描画更新にとどめるか、Socket.ioでの `update-note` 送信にスロットル制御（例: 100msに1回）を適用し、通信量の急増によるカクつきやサーバー遅延を防ぎます。
  - ドラッグ完了時（`mouseup`）に最終的な座標を確実に同期します。

### ④ モバイル（タッチ操作）の対応方針
スマートフォンやタブレットなどのタッチ環境では修飾キー（Space/Shift）が存在しないため、以下のように役割を定義します。
- **1本指ドラッグ**: キャンバスの空き領域は「パン移動」、付箋上は「付箋の単独移動」（既存の挙動を維持）。
- **2本指操作**: ピンチイン・ピンチアウトによるズーム＆パン移動。
- **複数選択（範囲選択）**: 今回の実装ではPC（デスクトップ環境）向けの操作系向上を主軸とするため、モバイル環境での範囲選択は対象外（PC専用機能）として割り切ります。

## 4. 検証計画

### 手動動作検証

1. **パン移動（画面スクロール）と干渉防止の確認**:
   - Spaceキーを押しながらキャンバスを左ドラッグし、画面がスクロールすることを確認する。
   - テキスト入力中（付箋のテキスト編集やタイトル入力）にSpaceキーを押した際、文字の空白が入力され、パン移動が誤作動しないことを確認する。
   - キャンバス上でSpaceキーを押しても、ブラウザ標準の下スクロールが発生しないことを確認する。
2. **範囲選択（矩形選択）と追加選択の確認**:
   - キャンバスの空き領域を右下から左上など様々な方向へドラッグし、選択ボックスが正しく描画され、交差した付箋が選択状態になることを確認する。
   - Shiftキーを押しながら範囲選択またはクリックを行い、選択状態がトグル（追加・解除）されることを確認する。
3. **複数付箋の同時移動と負荷対策の確認**:
   - 複数選択状態で付箋をドラッグし、全ての選択付箋（ピン留めを除く）が同時に移動することを確認する。
   - 多数の付箋を移動させても画面が極端にカクつかず、ドラッグ終了後に他クライアントへ正しく同期されることを確認する。
   - `pinned: true`（ピン留め）の付箋が選択状態にあっても、ドラッグ時に移動しないことを確認する。
4. **既存機能・モバイル環境の確認**:
   - 付箋の単独操作、入力エリアのクリック等に干渉しないことを確認する。
   - モバイルエミュレータ（または実機）で、1本指ドラッグが従来通りパン移動として機能することを確認する。
