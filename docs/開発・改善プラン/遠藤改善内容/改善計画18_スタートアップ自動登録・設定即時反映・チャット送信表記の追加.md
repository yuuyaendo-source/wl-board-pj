# 改善計画18：スタートアップ自動登録・設定即時反映・チャット送信表記の追加

## 1. 概要・変更目的

デスクトップアプリ（`wl_desktop_app`）のユーザビリティ向上のため、以下の3つの機能改善を行います。

1. **スタートアップ登録の自動化（OS設定との安全な同期）**
   - 以前セキュリティソフトの誤検知防止のために無効化した起動時の自動スタートアップ登録を、ユーザーの利便性を優先して自動化します。設定で無効化されていない限り、アプリ起動時に自動でスタートアップへ登録されるようにします。**また、セキュリティソフトの誤検知を防ぐため、OS側のスタートアップ設定状態（ショートカットの有無およびタスクマネージャーでの無効化状態）を正としてアプリ内の設定を同期する安全な方式を採用します。**
2. **設定の完全自動保存化（設定ダイアログのUI挙動統一）**
   - 既存の「保存」「キャンセル」ボタンを廃止し、設定ダイアログ内での操作が即座に反映される完全な自動保存UIに変更します。チェックボックスやテキストフィールドの操作時にUXの不一致が起きないよう統一します。
3. **チャット送信方法のUI表記追加**
   - ユーザーが操作方法を迷わないよう、チャットパネル内のテキスト入力欄付近に「Ctrl + Enter で送信」というヒントテキストを明記し、使い勝手を向上させます。

## 2. 具体的な実装仕様 (Proposed Changes)

### ① スタートアップ登録の自動化（OS設定との安全な同期）

- **`config_loader.py`**:
  - デフォルト設定に `"startup_enabled": True` を追加します。既存ユーザーの `config.json` にキーが存在しない場合でも、`load_config()` の仕様により自動的に `True` がフォールバック適用されるため、スムーズに移行できます。
- **`startup.py`**:
  - **【重要変更】レジストリ判定の追加**: 既存の `is_startup_enabled()` はショートカットファイルの有無のみを確認していましたが、これではタスクマネージャーから「無効化」された状態を検知できません。そのため、`winreg` モジュールを用いてレジストリ（`HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\StartupFolder` 配下）の値を読み取り、バイナリ値の先頭バイトが無効化を示す値（例: `03` 等）である場合は `False` を返すよう判定ロジックを強化します。
  - **【重要変更】再有効化時のタスクマネージャー制限解除**: `set_startup_enabled(True)` 実行時、レジストリの `StartupApproved` に無効化値が存在する場合は、**該当のレジストリエントリ自体を削除する**ことで、タスクマネージャーによる起動ブロックを確実かつシンプルに解除する処理を追加します。
- **`app.py`**:
  - **【重要変更】OS設定との同期と初回起動デッドロック防止**: ユーザーがOS側（タスクマネージャー等）で手動で無効化・削除した設定をアプリが勝手に復元する挙動は、マルウェアの永続化手法とみなされセキュリティソフトの誤検知リスクを高めます。そのため、起動時の初期化処理では、強化された `startup.is_startup_enabled()` を呼び出してWindows OS側の実際のスタートアップ状態を取得し、その結果に合わせて `config.json` の `startup_enabled` を上書き（同期）します。これによりOS側の状態を正とします。
  - **初回起動時の例外判定**: 初回起動時など、ショートカットが未作成かつレジストリ（`StartupApproved`）に無効化記録が存在しないクリーンな状態の場合は、同期によって即座に `False` に上書きされるのを防ぎ、`config.json` の `startup_enabled: True` に従って自動登録を実行します。
  - **【留意点】エラーハンドリング**: スタートアップ同期処理で例外が発生した場合（アクセス権限の問題など）も、アプリの起動処理自体が中断しないよう `try-except` で保護します。
  - **【留意点】誤検知リスク対策**: `winreg` の再導入により、一部の過敏なセキュリティソフトが反応するリスクが考えられます。`build_msi.ps1`等におけるバイナリへの署名（Code Signing）が正しく機能していることを前提とし、リリース前の入念な動作検証を実施します。

### ② 設定の完全自動保存化（保存ボタンの廃止と即時反映）

- **`settings_dialog.py`**:
  - **ボタンの整理**: 既存の「保存」および「キャンセル」ボタンを廃止し、ウィンドウ下部は「閉じる」ボタンと「アップデート確認」ボタンのみの構成とします。
  - **即時保存ロジック**: 既存の `_on_save` メソッドから設定保存・適用ロジックを分離し、汎用的な `_save_settings` メソッドを新設します。
  - **イベントバインド**:
    - **チェックボックス / セレクトボックス**: `command` プロパティに `_save_settings` をバインドし、操作時に即時保存させます。
    - **テキスト入力フィールド**: フォーカスが外れたタイミング（`<FocusOut>` イベント）、および **Enter (`<Return>`) キー押下時**にフォーカスを外す（または `_save_settings` を呼ぶ）バインドを行い、UXを向上させます。※CustomTkinterの `CTkEntry` ウィジェット自体へのバインドで発火しない場合は、内部の `_entry` (Tkinter標準ウィジェット) に対してバインド（例: `entry._entry.bind("<FocusOut>", ...)`）を行います。
  - **自動保存時のエラーハンドリング改善**: 自動保存時にエラーが発生した場合、既存の `messagebox.showerror` などのモーダルダイアログをポップアップさせると、フォーカス移動のたびにダイアログが出て操作不能に陥るリスクがあります。そのため、自動保存時のエラーは `log_error` によるログ出力や、ダイアログ下部の控えめなステータスラベル表示などに留める設計とします。
  - **【留意点】副作用のガードロジックの粒度**: `_save_settings` 内では、「メモリ上の保存済み設定値」と「現在のUI上の値」を比較（差分チェック）し、**値に変更があった項目のみ**に絞って設定ファイルの保存や関連処理（来客通知のSocket.IO再接続、OSへのショートカット登録処理など）を実行するようにします。これにより、変更がない状態でのフォーカスアウトのたびに不要なネットワーク再接続などが発生するのを防ぎます。
  - **【留意点】閉じる際の未保存防止**: テキスト入力中でフォーカスが当たったままウィンドウの「閉じる（ウィンドウ右上の✕ボタン含む）」が操作された場合、`<FocusOut>` が発火する前に設定が失われるのを防ぐため、ウィンドウを閉じるイベント（`_on_close`）の先頭で必ず `_save_settings` を一度呼び出すよう保証します。差分チェックが組み込まれているため、`<FocusOut>`と連続して発火しても二重実行の弊害は防げます。

### ③ チャット送信方法のUI表記追加

- **`chat_panel.py`**:
  - `_build_ui` メソッド内で、メッセージ入力欄（`self._entry`）や送信ボタン（`self._send_btn`）が配置されている `bottom` フレームの周辺に、新たにヒントラベル（`ctk.CTkLabel`）を追加します。
  - **配置の指定**: レイアウト崩れを防ぐため、ヒントラベルは入力欄全体を含む `bottom` フレームの直前（`attach_row` と `bottom` の間）に右寄せで配置します（または、既存の配置の邪魔にならないよう `bottom` フレーム内の送信ボタンの下など、具体的な位置にアンカーさせます）。
  - テキストを「Ctrl + Enter で送信」とし、視覚的な邪魔にならないよう文字色をグレー（例: `text_color=("gray40", "gray60")`）、フォントサイズを少し小さめ（11pt程度）に設定します。
  - 従来の `Ctrl+Enter` 送信ロジック（`_on_send_shortcut`）は変更せずにそのまま維持します。

## 4. 検証計画 (Verification Plan)

### Manual Verification

1. **スタートアップ登録の自動化（安全な同期）**:
   - `config.json` を初期状態（ファイル削除など）にしてアプリを初回起動後、デッドロックに陥らずにWindowsのスタートアップフォルダにショートカットが自動作成されることを確認する。
   - OS側で手動でショートカットを削除、**またはタスクマネージャーの「スタートアップ」タブから「無効化」** した後、アプリを再起動すると、**ショートカットが勝手に再作成されず**、アプリ内の設定画面でも「PC起動時に自動で起動」のチェックが外れた状態に同期されていることを確認する。
   - アプリの設定画面で明示的にチェックを入れ直した場合は、再度ショートカットが作成され、**かつレジストリ (`StartupApproved`) の該当エントリが削除され有効化**されることを確認する。
   - スタートアップディレクトリやレジストリへのアクセス権がない等、意図的にエラーを発生させる状況でも、アプリがクラッシュせずに正常起動することを確認する。
2. **設定の完全自動保存化**:
   - 設定ダイアログを開き、「保存」「キャンセル」ボタンが存在しないことを確認する。
   - チェックボックス（例：「PC起動時に自動で起動」）を切り替えた瞬間に `config.json` が更新され、システムへの適用が行われることを確認する。
   - テキスト入力フィールドの値を変更し、別の場所をクリックしてフォーカスを外した瞬間、または **Enter (`<Return>`) キーを押した瞬間**に `config.json` が更新されることを確認する。
   - 差分チェックの確認：テキスト入力フィールドをクリックしてフォーカスを当て、値を変更せずにフォーカスを外した場合、無駄な保存処理や再接続処理が走らないことをログ等で確認する。
   - 閉じる際の保存確認：テキスト入力欄の値を変更し、フォーカスを外さずにそのままウィンドウ右上の「✕」ボタン等を押した際、入力した値が正しく保存されていることを確認する。
   - エラーハンドリングの確認：意図的に保存処理を失敗させた場合、モーダルダイアログで操作不能にならず、ログ出力やステータスラベル等で控えめにエラーが通知されることを確認する。
3. **チャット送信方法のUI表記**:
   - ブレスト用のチャットパネルを開き、入力欄全体付近に「Ctrl + Enter で送信」というヒントが表示され、目立ちすぎずレイアウトが崩れていないことを確認する。
   - 従来通り、`Ctrl+Enter` キーでメッセージが正常に送信されることを確認する。
