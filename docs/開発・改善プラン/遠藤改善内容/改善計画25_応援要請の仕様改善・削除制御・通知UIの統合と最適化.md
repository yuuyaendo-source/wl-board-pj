# 改善計画25：応援要請の仕様改善・削除制御・複数人アサインの可視化・通知UIの統合

## 1. 概要・目的

本計画では、タスクの「応援要請」のライフサイクルを明確化し、複数人アサイン時の状態管理や削除制御を厳格化することで、業務の抜け漏れや誤操作を防ぎます。
さらに、**複数人に割り当てられているタスクの進捗（誰が対応中で、誰が完了したか）をパーソナルボード上で互いに可視化**し、チームワークを円滑にします。
また、デスクトップアプリにおいて二重に存在していた通知UI（ネイティブトーストとリン子アバターの吹き出し）を一本化します。ミニポート本体を非表示にしていても、OSネイティブのトーストは使用せず、画面右下に「リン子の吹き出し」のみを一時的にポップアップ表示させることで、ブランド体験を損なうことなくUXを統一します。

---

## 2. 改善項目と解決アプローチ

### ① 応援要請のレーン復帰と赤色表示の継承

* **現状の課題**: 応援要請（`lane = HELP_REQUEST`）が他のメンバーに引き取られた後、要請した本人のパーソナルボード上で元のレーンに戻る仕組みがありません。また、レーンを戻すと「応援要請されたタスクである」という視覚的情報（赤色）が消えてしまいます。
* **解決策**:
  * **DBスキーマ拡張**: `sticky_notes` テーブルに `is_help_request`（Boolean）フラグを追加します。
  * **自動レーン復帰**: 他のユーザーが付箋をパーソナルやチームに引き取った際、元の要請者のパーソナル配置（`HELP_REQUEST`）を自動的に `INBOX` に戻します。
  * **赤色表示の永続化**: `is_help_request=True` の付箋は、引き取った人（応援を振られた人）および要請した本人のパーソナルボードでも、完了するまで赤色（`cardColor="red"`）でハイライト表示し続けます。

### ② 複数人アサイン時の安全な削除制御

* **現状の課題**: 複数人に割り振られている付箋を1人がゴミ箱（削除）に入れると、タスクボード上のステータスが「完了」に進んでしまい、他の担当者の進捗と矛盾が生じます。
* **解決策**:
  * バックエンドの削除API（`DELETE /board_placements/{id}`）にて、同一付箋に他のパーソナル配置が存在するかチェックします。
  * 他の担当者のレーンが「完了（DONE）」以外に存在する場合、HTTP 400エラーを返し「他の担当者が完了にするまで削除できません」と操作をブロックします。

### ③ 複数人アサインの状況可視化と完了ステータスの共有

* **現状の課題**: パーソナルボード上では自分のタスク状態しか見えず、同じタスクを他に誰が持っているか、誰が完了したかが分かりません。
* **解決策**:
  * **他担当者バッジの表示**: パーソナルボードにおいて、その付箋が自分以外の誰かにアサインされている場合、該当付箋に「自分以外の担当者アイコンバッジ」を表示します（自分のバッジは除外）。
  * **完了状態のリアルタイム共有**: 他の担当者がその付箋を「完了（DONE）」レーンに移動させた場合、**該当者のバッジの色（グレースケール＋チェックマーク表示）を変化**させ、誰が終わったのかを視覚的に通知します。

### ④ 通知UIの「吹き出し」への一本化（ネイティブトースト廃止）

* **現状の課題**: デスクトップアプリで「ネイティブトースト」と「ミニポート上の吹き出し」が混在しており、通知体験が統一されていません。
* **解決策**:
  * `notifications.py` にある OSネイティブのトースト呼び出しを廃止します。
  * **吹き出しの独立ポップアップ化**: ミニポート本体が非表示（バックグラウンド）の状態でも、通知受信時にはミニポート本体を出現させることなく、**「吹き出し」ウィンドウのみ**を画面右下（旧トースト位置）に一時的に表示します。
  * 吹き出しは指定秒数（`duration_sec`）が経過すると自動的にフェードアウト・非表示となります。

## 3. 具体的な実装仕様 (Proposed Changes)

### 3.1 データベース変更 (Alembic Migration)

新しいマイグレーションスクリプトを作成し、`sticky_notes` テーブルにフラグを追加します。

* `backend/alembic/versions/xxxx_add_is_help_request.py`

```python
def upgrade() -> None:
    with op.batch_alter_table("sticky_notes", schema=None) as batch_op:
        batch_op.add_column(
            sa.Column("is_help_request", sa.Boolean(), server_default=sa.text("false"), nullable=False)
        )

def downgrade() -> None:
    with op.batch_alter_table("sticky_notes", schema=None) as batch_op:
        batch_op.drop_column("is_help_request")

```

### 3.2 バックエンド API ロジック改修 (`board-system`)

* `backend/app/schemas/board_placement.py`
* 複数人アサイン時の状態を示すため、`TakenByUser` スキーマに `is_done: bool` を追加します。

```python
class TakenByUser(BaseModel):
    id: int
    name: str
    name_short: str
    is_done: bool = False  # 追加: このユーザーが完了(DONE)にしたかどうか

```

* `backend/app/schemas/sticky_note.py` & `board_placement.py`
* レスポンススキーマに `is_help_request: bool = False` を追加します。

* `backend/app/routers/boards.py` (`GET /boards/personal`)
* パーソナルボード取得時、同一付箋に対する自分以外の配置情報（`BoardPlacement`）から `taken_by` リスト（自分以外の所有者一覧）を組み立てて返却します。その際、各ユーザーの `lane == Lane.DONE` であれば `is_done = True` とします。

* `backend/app/routers/board_placements.py` & `sticky_notes.py`
* **削除制御**: `DELETE` メソッドで、他の未完了パーソナル配置がある場合は HTTP 400 でブロックし、未完了メンバーを通知します。
* **引き取り時のレーン復帰**: `move_to_personal` や `copy_to_team` 実行時、対象付箋において自分以外のパーソナル配置が `HELP_REQUEST` レーンにある場合、それらを自動的に `INBOX` に更新します。

### 3.3 フロントエンドのUI対応 (`frontend`)

* `frontend/app/components/NoteCard.tsx` & `PersonalBoardView.tsx`
* **他担当者バッジの表示**: 渡された `taken_by` リスト（自分以外）を展開し、付箋の端（または下部）にアバター風バッジを表示します。
* **完了状態の色変化**: `taken_by` のうち `is_done === true` のメンバーバッジには、`grayscale opacity-60` のスタイルと「✅」アイコンを適用し、未完了メンバーと一目で区別できるようにします。
* **赤色表示**: `note.is_help_request` が `true` の場合、付箋を完了にするまで赤基調（`cardColor="red"`）でハイライト表示します。

### 3.4 デスクトップアプリの通知統合 (`wl_desktop_app`)

* `wl_desktop_app/notifications.py`
* ネイティブトースト（`win10toast` 等）の処理を削除し、UIディスパッチを経由してアバターモジュールの「吹き出しのみ」にルーティングします。

```python
def show_toast(title: str, msg: str, url: str = None, duration_sec: int = 5, force_show: bool = False):
    if not are_enabled() and not force_show:
        return
    # トースト呼び出しをすべて吹き出し表示（linko_avatar）に委譲
    if _ui_dispatch:
        _ui_dispatch(lambda: _trigger_speech_bubble_notification(msg, duration_sec))

```

* `wl_desktop_app/linko_avatar.py` & `speech_bubble.py`
* ミニポート本体が非表示（`_miniport_visible == False`）の場合、`SpeechBubble` のみを画面右下の固定位置に表示するスタンドアロンモードを実装します。

```python
# speech_bubble.py 内の表示ロジック拡張
def show_message(self, text: str, duration_sec: float = 3.0, standalone: bool = False):
    self.label.configure(text=text)
    
    if standalone:
        # ミニポート本体が出現しないよう、吹き出しのみを画面右下へ配置
        sw = self.winfo_screenwidth()
        sh = self.winfo_screenheight()
        x = sw - self.WIDTH - 24
        y = sh - self.HEIGHT - 60
        self.geometry(f"+{x}+{y}")
    else:
        self._align_to_parent()

    self.deiconify()
    self.attributes("-topmost", True)
    
    if self._hide_job:
        self.after_cancel(self._hide_job)
    self._hide_job = self.after(int(duration_sec * 1000), self.withdraw)

```

## 4. 検証および運用計画 (Verification Plan)

1. **応援要請のライフサイクル検証**:

* ユーザーAが付箋を `HELP_REQUEST` レーンに置く（赤色表示になる）。
* ユーザーBがそれを引き取ると、ユーザーAのボードで付箋が自動で `INBOX` に戻り、両者のボードで完了するまで赤色のまま維持されることを確認する。

1. **複数人アサインの可視化と削除制御検証**:

* ユーザーAとBが同じ付箋を持っている際、お互いのパーソナルボードに相手のバッジが表示されることを確認する（自分のバッジは表示されない）。
* ユーザーAが該当付箋をゴミ箱に入れようとすると、「他の担当者が完了にするまで削除できません」とブロックされることを確認する。
* ユーザーBが付箋を `DONE` に移動させると、ユーザーAのボード上にある「ユーザーBのバッジ」がグレーアウト＋チェックマーク（✅）に変化することを確認する。
* ユーザーBが完了状態になった後であれば、ユーザーAが正常に付箋を削除できることを確認する。

1. **通知UIの吹き出し一本化検証**:

* ミニポート本体を非表示にする。
* 通知トリガーを発生させ、**ミニポート本体は出現せず、吹き出しのみ**が画面右下にポップアップ表示されることを確認する。
* 指定秒数経過後、吹き出しが自動的に消えることを確認する。
