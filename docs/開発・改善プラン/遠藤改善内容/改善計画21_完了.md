# 改善計画21：アセット欠落対策とゼロダウンタイム化（ホストOS対応版） 完了報告

ご依頼いただいた「改善計画21：デプロイ時のアセット欠落によるクラッシュ（Offline化）の抜本的対策とゼロダウンタイム化」に基づく、インフラ・デプロイスクリプトおよび Nginx ルーティングの改修が完了いたしました。

---

## 実施した変更の詳細

### 1. 静的アセットのホストOSディレクトリでの永続化
- **デプロイスクリプトの改修 (`deploy.sh`)**:
  - Board System のビルド後、新コンテナから `.next/static/` ディレクトリ配下のアセットを、ホストOS上の共通ディレクトリ（`/var/www/wlinko-pj/shared_static/frontend/` および `sticky-note/`）に自動で同期・上書きコピーする処理を追加しました。
- **自動クリーンアップの導入**:
  - 同期処理の直後に、ホストOS上で 14日以上経過した古いアセットファイルや空のディレクトリを自動で削除（`find -mtime +14 -delete`）するメンテナンスロジックを実装し、ストレージの肥大化を防ぎました。

### 2. Nginx による直接配信と確実なリカバリ (404)
- **直接配信ルーティング (`nginx.conf`)**:
  - Board System および 付箋ボードの `/_next/static/` に対するリクエストを、Node/Next.js コンテナへプロキシせず、`alias` を用いてホストOS上の永続化ディレクトリから Nginx が直接高速配信するように変更しました。
- **エラーハンドリング（`try_files $uri =404;`）**:
  - 旧バージョンのブラウザから存在しない古いJSファイルが要求された際、Next.jsのフォールバックHTMLが返ることを防ぎ、純粋な `404 Not Found` ステータスを確実に返却するよう設定しました。これにより、Next.jsクライアントの `ChunkLoadError` 検知と自動ハードリロード（リカバリ）が正常に発火するようになりました。

---

## 確認方法

1. **ホストOSへの同期確認**:
   - `deploy.sh` を実行し、ターミナルログに `Syncing static assets to host directory...` と表示され、`/var/www/wlinko-pj/shared_static/` 内に静的ファイルが配備されていることを確認してください。
2. **Nginx配信とリカバリ挙動の確認**:
   - Web画面をブラウザで開いたまま放置し、裏でデプロイを実行して Blue/Green の環境切り替えを行わせます。
   - ブラウザで画面内の遷移操作等を行った際、クラッシュ（`🔴 Offline` や構文エラー）が発生せず、ページが自動的にリロードされて最新版のUIに切り替わる（ゼロダウンタイム）ことを確認してください。
