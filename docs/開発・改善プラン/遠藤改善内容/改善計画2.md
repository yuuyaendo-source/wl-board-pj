# 応援要請（赤色）付箋の引き受け時自動移動プラン

ご依頼いただいた仕様変更（「応援要請」の付箋が誰かに引き受けられた時点で、赤色を維持したまま本来の列へ自動移動する）を実現するため、バックエンドのレスポンス拡張とフロントエンドの振り分けロジック修正を行います。

## 提案する変更内容

### Backend 修正

#### [MODIFY] [board_placement.py (schema)](file:///c:/Users/yuuya/Documents/dev/wl-board-pj/board-system/backend/app/schemas/board_placement.py)

- APIレスポンスモデル `BoardPlacementWithNoteResponse` に以下のプロパティを追加します。
  - `is_accepted_by_others: bool = False`

#### [MODIFY] [boards.py (router)](file:///c:/Users/yuuya/Documents/dev/wl-board-pj/board-system/backend/app/routers/boards.py)

- `get_board_task()` 処理内にて、「当該付箋を `HELP_REQUEST` 以外のレーン（`INBOX`, `TODAY`, `DONE`）で所持しているユーザーが存在するか」をチェックします。
- 存在する場合、`is_accepted_by_others = True` としてレスポンスに含めます。

### Frontend 修正

#### [MODIFY] [types.ts](file:///c:/Users/yuuya/Documents/dev/wl-board-pj/board-system/frontend/lib/types.ts)

- `PlacementWithNote` の型定義に `is_accepted_by_others?: boolean` を追加します。

#### [MODIFY] [page.tsx](file:///c:/Users/yuuya/Documents/dev/wl-board-pj/board-system/frontend/app/taskboard/page.tsx)

- タスクボードの列振り分けロジックを以下のように変更します。
  - **変更前**: `task_color === "red"` なら無条件で「応援要請・未振り分け」列
  - **変更後**: `task_color === "red"` かつ `is_accepted_by_others` が `false`（誰も引き受けていない）の場合のみ「応援要請・未振り分け」列。引き受けられた場合は `else` ルートに入り、付箋の `matrix_quadrant` に基づいて本来の列（アイデア、タスク、完了）に配置されます。

## 検証計画

- `is_accepted_by_others` フラグが正しくフロントに渡ることを確認します。
- 赤色の付箋を「パーソナルボードへコピー（メンバーへドロップ）」した直後に、赤色状態を維持したまま、元々のAI判定列（タスク列など）へ即座に移動することを確認します。
