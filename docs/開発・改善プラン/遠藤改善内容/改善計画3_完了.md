# チーム機能追加およびデプロイスクリプト・DBマイグレーション改修のウォークスルー

タスクボード上の付箋を「チーム」単位で所属メンバー全員のパーソナルボードへ一括コピーする機能の実装、GUIでのチーム・メンバー管理機能、ならびに本番・ステージング環境に対応した Alembic マイグレーションとデプロイスクリプトの改修を行いました。

---

## 1. 新機能の概要

1. **チーム概念の追加**
   - 「ネットワーク」「構築」などのチームを作成し、ユーザーをチームに所属させることができます。
2. **タスクボードからのチーム一括コピー**
   - タスクボードのヘッダーに配置されたチームエリア（👥 ネットワーク、👥 構築 など）に付箋をドラッグ＆ドロップすると、**そのチームに所属する全メンバーのパーソナルボード（INBOXレーン）へ一括コピー**されます。
3. **直感的な GUI 管理パネル（メンバー・チーム管理）**
   - ヘッダーの「メンバー管理」ボタンから開くパネルを「メンバー管理」と「チーム管理」の 2 タブ形式へ拡張。
   - メンバー追加・編集時に所属チームをドロップダウンで選択・更新できます。
   - チーム自体の新規作成・チーム名の変更・削除・所属メンバーの確認をGUI上で完結して行えます。
4. **自動Seedおよびマイグレーション**
   - アプリ起動時に「ネットワーク」「構築」チームを自動生成し、初期メンバー（ID 1〜7）に割り当てます。
   - Alembic マイグレーションファイルおよびデプロイスクリプト (`deploy.sh`, `deploy-staging.sh`) により、本番・ステージング環境でも自動的にテーブル作成とSeedが行われます。

## 2. 画面・UI仕様

### メンバー・チーム管理パネル ([AddUserMenu.tsx](file:///c:/Users/yuuya/Documents/dev/wl-board-pj/board-system/frontend/app/components/AddUserMenu.tsx))
- **メンバー管理タブ**:
  - 名前・メールアドレス・呼び名に加え、**所属チームの選択ドロップダウン**を配置。
  - メンバー一覧に所属チームのバッジを表示。編集ボタンから所属チームの変更が可能。
- **チーム管理タブ**:
  - 新規チーム追加フォーム（チーム名入力）。
  - 既存チーム一覧（インライン名変更、チーム削除ボタン、所属メンバー一覧を表示）。
  - チーム削除時、所属していたメンバーのチーム設定は安全に「未所属 (NULL)」へ変更されます。

### タスクボード ([page.tsx](file:///c:/Users/yuuya/Documents/dev/wl-board-pj/board-system/frontend/app/taskboard/page.tsx))
- ヘッダーの「パーソナルボードへコピー」エリア下に、**チーム用ドロップゾーン（`TeamDropZone`）**を動的に配置。
- 各チームバッジには「👥 チーム名 (所属人数)」が表示され、インディゴ色のアクセントカラーで個人用ターゲットと区別されます。
- 付箋をドロップすると `POST /sticky_notes/{id}/copy_to_team` が呼び出され、「ネットワーク チーム全員（X名）にコピーしました」等のトースト通知が表示されます。所属メンバーが0人のチームにドロップした場合はエラーメッセージが表示されます。

## 3. バックエンド & DB の変更点

### DB スキーマ
- **`teams` テーブル**: `id` (PK), `name` (Unique), `created_at`, `updated_at`
- **`users` テーブル**: `team_id` (FK: `teams.id`, ON DELETE SET NULL, NULL可)

### Alembic マイグレーション
- [j0k1l2m3n4o5_add_teams_and_user_team_id.py](file:///c:/Users/yuuya/Documents/dev/wl-board-pj/board-system/backend/alembic/versions/j0k1l2m3n4o5_add_teams_and_user_team_id.py)
  - `teams` テーブルを作成し、`users` テーブルに `team_id` カラムと外部キー制約を追加。

### API エンドポイント
| メソッド | パス | 説明 |
|---|---|---|
| `GET` | `/teams` | チーム一覧と各チームの所属人数を取得 |
| `POST` | `/teams` | 新規チームを作成 (`{ name: string }`) |
| `PATCH` | `/teams/{team_id}` | チーム名を更新 (`{ name: string }`) |
| `DELETE` | `/teams/{team_id}` | チームを削除 (所属ユーザーの team_id は Set NULL) |
| `POST` | `/sticky_notes/{note_id}/copy_to_team` | 指定チーム所属メンバー全員の Personal ボードへコピー |
| `POST`/`PATCH` | `/users`, `/users/{user_id}` | ユーザー作成・更新時に `team_id` を読み書き |

## 4. シードおよびデプロイスクリプトの改修

1. **`db.py` の `seed_teams()`**
   - アプリ起動時 (`main.py` の `lifespan`) に「ネットワーク」「構築」が存在しなければ作成し、初期ユーザー (ID 1〜7) で `team_id` が未設定のユーザーに仮割り当て（奇数ID: ネットワーク, 偶数ID: 構築）。
2. **`scripts/seed_teams.py`**
   - 本番・ステージング環境用のスタンドアロン Seed スクリプト。
3. **`deploy-staging.sh`**
   - `build` 後、`up -d` でサービスを立ち上げる**前**に一時コンテナ (`run --rm`) で `alembic upgrade head` および `python scripts/seed_teams.py` を順序通り実行。
   - `2>/dev/null || true` を除去し、エラー時に即座にログを出力して停止する堅牢なエラー処理に変更。
4. **`deploy.sh`**
   - `alembic upgrade head` の実行直後に `python scripts/seed_teams.py` を実行するステップを追加。

## 6. 動作検証手順

1. **GUIでのチーム作成・メンバー変更の検証**:
   - Web画面右上の「メンバー管理」を開き、「チーム管理」タブを選択。
   - 「開発」などの新規チームを追加し、正常に一覧に表示されることを確認。
   - 「メンバー管理」タブに戻り、既存ユーザーの「編集」をクリック。所属チームを「開発」に変更して保存。
2. **チームへの付箋一括コピーの検証**:
   - タスクボード画面を開き、ヘッダーに「👥 開発」ドロップエリアが表示されていることを確認。
   - 任意のお試し付箋を「👥 開発」ドロップエリアにドラッグ＆ドロップ。
   - トースト通知で「開発 チーム全員（1名）にコピーしました」と表示されることを確認。
   - 該当ユーザーのパーソナルボード (`/personal?owner_id=X`) を開き、付箋がコピー追加されていることを確認。
3. **デプロイスクリプトの検証**:
   - Alembic マイグレーションファイル (`j0k1l2m3n4o5_add_teams_and_user_team_id.py`) を Git コミット対象に含めてコミット。
   - `./deploy/deploy-staging.sh` を実行し、コンテナ起動前に Alembic マイグレーションとチームシードが正常実行されることを確認。
