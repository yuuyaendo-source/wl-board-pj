# 改善計画22：システム全体の安定性・セキュリティ向上とパフォーマンス最適化（確定改訂版）

## 1. 概要・目的

本計画では、稼働中のシステム全体（付箋ボード、Board Systemバックエンド、デスクトップアプリ）において潜在している**データ消失リスク**、**セキュリティの脆弱性**、および**パフォーマンスのボトルネック**を解消します。
これまでのコードレビューおよび技術的フィードバック（アトミック保存の排他制御・`.tmp`残存防止・シャットダウン時の同期/非同期競合防止、TLS検証の局所化・対象拡充、FastAPI `app.state` を用いたHTTPクライアント共有と全外部通知の完全非同期化、PIDによる自プロセス一時ファイルの独立クリーンアップ・Windowsファイルロック対策・起動時クリーンアップ追加）をすべて反映し、より堅牢でセキュアな運用基盤を確立します。

---

## 2. 現状の課題と解決アプローチ

### ① `wl-sticky-note` におけるデータ破損・消失リスク
* **現状の課題**: `boards.json` へのデータ保存時、直接上書きしているため、書き込み中のプロセス終了（OSシャットダウンや PM2 再起動など）でデータが0バイト化（全消失）するリスクがあります。
* **解決策**: 
  * 一時ファイル（`.tmp`）に書き込んだ後、OSレベルでアトミック（不可分）にリネームする方式へ変更します。
  * **排他制御**: `isSaving` フラグを導入し、高頻度な保存要求による一時ファイル（`.tmp`）の競合（Race Condition）を防ぎます。
  * **グレースフル・シャットダウンとゴミ削除（競合対策強化）**: 終了シグナル（SIGINT/SIGTERM）受信時は、非同期保存（`isSaving`）の完了を待機してから `httpServer.close()` の完了コールバック内で確実に同期フラッシュ（`writeFileSync`/`renameSync`）します。万が一リネーム失敗等が発生した場合は、`catch` ブロックで `.tmp` ファイルを即座に削除（`unlinkSync`）し、不完全な一時ファイルの残存を防ぎます。

### ② グローバルな TLS 検証無効化の影響範囲（セキュリティリスク）
* **現状の課題**: `process.env.NODE_TLS_REJECT_UNAUTHORIZED = '0'` により、すべての外部通信でSSL/TLS証明書の検証が無効化されており、中間者攻撃（MitM）のリスクが生じています。
* **解決策**: グローバルな無効化を廃止し、`undici.Agent` を用いて局所化します。URL判定（例：`isInternalAIOrBS`）を行い、自己署名証明書で稼働している内部通信（AI-Board 宛通信および Board System 宛通信）にのみ適用することで、外部サードパーティ連携等との通信セキュリティを保護します。

### ③ バックエンド外部通知処理の同期ブロック（スレッド消費）
* **現状の課題**: Board Systemバックエンドで `urllib.request.urlopen`（同期通信）をスレッドでラップして使用しており、高負荷時のレスポンス遅延やスレッドプール枯渇に繋がっています。
* **解決策**: FastAPI の `lifespan` 内で `httpx.AsyncClient` インスタンスを生成・破棄し、`app.state.http_client` 経由で各ルーターおよびサービスから参照します。これにより、循環インポートを回避しつつ `urllib` を完全に排除し、コネクションプールの再利用（Keep-Alive）による全外部通信の完全非同期・高速化を実現します。

### ④ デスクトップアプリの一時ファイル（WAV）消し残しとファイルロック
* **現状の課題**: `audio_player.py` の非同期再生後、アプリが30秒以内に終了すると `%TEMP%` にWAVファイルが永遠に残存します。また、Windows上において `tempfile.mkstemp` が返すファイルディスクリプタ（fd）が開いたままだとファイルロックが発生し、削除時に `PermissionError` が発生する問題があります。
* **解決策**:
  * 一時ファイル生成時、ファイル名に現在のプロセスID（PID）を付与します（例: `linko_audio_{os.getpid()}_...`）。
  * `mkstemp` 呼び出し直後に `os.close(fd)` を明示的に実行し、Windows OS上でのファイルロックを解消します。
  * アプリの**起動時（`main()` 開始直後）**および**終了フック（`cleanup_resources`）**にて、自身のPIDが含まれるファイルを一括削除します。これにより、他プロセスの音声を誤削除することなく、強制終了等で残った過去の自プロセスゴミファイルも確実にクリーンアップします。

### 3.1 付箋ボード (`wl-sticky-note/src/server.js`) の堅牢化
* **アトミック保存・排他制御とグレースフル・シャットダウン（競合対策・`.tmp`残存防止含む）**:

```javascript
const fs = require('fs');
const fsPromises = fs.promises;
const { Agent } = require('undici');

let isSaving = false;
let saveTimeout = null;

// 通常時の非同期アトミック保存（排他制御付き）
const flushBoardsToDiskAsync = async () => {
    if (isSaving) return;
    isSaving = true;
    const dataStr = JSON.stringify(boards, null, 2);
    const tempFile = `${DATA_FILE}.tmp`;
    try {
        await fsPromises.writeFile(tempFile, dataStr, 'utf8');
        await fsPromises.rename(tempFile, DATA_FILE);
    } catch (err) {
        console.error('❌ Failed to save boards.json:', err.message);
        try { await fsPromises.unlink(tempFile); } catch (e) {} // 失敗時はゴミを削除
    } finally {
        isSaving = false;
    }
};

const saveBoards = () => {
    if (saveTimeout) clearTimeout(saveTimeout);
    saveTimeout = setTimeout(() => flushBoardsToDiskAsync(), 500);
};

// シャットダウン時の同期アトミック保存と通信クローズ（非同期書き込みの完了待機付き）
const handleShutdown = async (signal) => {
    console.log(`Received ${signal}. Closing connections and flushing data...`);
    if (saveTimeout) clearTimeout(saveTimeout);
    
    // 非同期保存中の場合は処理完了を待機
    while (isSaving) {
        await new Promise(resolve => setTimeout(resolve, 50));
    }

    const exitProcess = () => {
        const tempFile = `${DATA_FILE}.tmp`;
        try {
            const dataStr = JSON.stringify(boards, null, 2);
            fs.writeFileSync(tempFile, dataStr, 'utf8');
            fs.renameSync(tempFile, DATA_FILE);
        } catch (err) {
            console.error('Shutdown save error:', err);
            try { fs.unlinkSync(tempFile); } catch (e) {} // 万が一失敗した場合は.tmpを破棄
        }
        process.exit(0);
    };

    if (io) io.close();
    if (httpServer) {
        httpServer.close(() => exitProcess()); // 接続クローズ完了後に安全に保存・終了
    } else {
        exitProcess();
    }
};
process.on('SIGINT', () => handleShutdown('SIGINT'));
process.on('SIGTERM', () => handleShutdown('SIGTERM'));

// TLS 検証の局所化（AI-Board 宛および Board System 宛通信を包括対象化）
const insecureDispatcher = new Agent({ connect: { rejectUnauthorized: false } });
const aiBoardBase = (process.env.AI_BOARD_URL || '').replace(/\/$/, '');
const boardSystemApiBase = (process.env.BOARD_SYSTEM_API_URL || '').replace(/\/$/, '');

const isInternalAIOrBS = (url) => {
    if (!url) return false;
    return (aiBoardBase && url.startsWith(aiBoardBase)) || 
           (boardSystemApiBase && url.startsWith(boardSystemApiBase));
};

// fetch呼び出し時の適用例:
// fetch(url, { dispatcher: isInternalAIOrBS(url) ? insecureDispatcher : undefined, ... });
```

### 3.3 デスクトップアプリ (`wl_desktop_app`) のクリーンアップとファイルロック回避
* **`audio_player.py` の改修（PID指定管理＋fd安全処理）**:
```python
import os
import glob
import tempfile

def get_audio_temp_prefix():
    # 自身のPIDをプレフィックスに含めて他プロセスと分離
    return f"linko_audio_{os.getpid()}_"

def download_linko_wav(...):
    # ...
    fd, path = tempfile.mkstemp(suffix=".wav", prefix=get_audio_temp_prefix())
    os.close(fd)  # Windowsでのファイルロックを防ぐため即座にクローズ
    # ...

def cleanup_temp_audio_files():
    # 自身のPIDを持つ一時ファイルのみを安全に削除
    pattern = os.path.join(tempfile.gettempdir(), f"{get_audio_temp_prefix()}*.wav")
    for path in glob.glob(pattern):
        try:
            os.unlink(path)
        except Exception:
            pass
```

* **`app.py` への組み込み**:
  起動時（`main()` 開始直後）および終了フック（`cleanup_resources()` 内）の双方で `cleanup_temp_audio_files()` を呼び出し、正常終了時はもちろんのこと、前回の強制終了等で残った不要な音声ファイルも確実にクリーンアップします。

## 5. 検証および運用計画 (Verification Plan)

### 自動テスト / 負荷テスト
* **非同期通信のパフォーマンス検証**: バックエンドで `DELETE /api/sticky_notes/{id}` 等を連続呼び出しし、スレッド枯渇エラーが発生せず、コネクションプールの再利用により応答速度が向上していることを確認する。

### 手動・結合検証
1. **データ永続性の耐障害テスト (`wl-sticky-note`)**:
   - 付箋ボードで大量に付箋を操作している最中に `pm2 restart wl-sticky-note` を実行。
   - 実行中の非同期保存が完了するのを待機してから安全に切断され、`.tmp` ファイルの競合や 0 バイト化が発生せず、データが完全に復元されることを確認する。
2. **TLS設定の局所化確認 (`wl-sticky-note`)**:
   - 内部 AI-Board や Board System（自己署名証明書環境）宛の通知がエラーなく送信されること。
   - 外部 API との通信に `insecureDispatcher` が適用されず、SSL エラーが発生しない（正常な HTTPS 通信ができている）ことを確認する。
3. **一時ファイルの確実なクリーンアップ確認 (`wl_desktop_app`)**:
   - 複数アプリ（または別ユーザーとして複数プロセス）を起動し、音声通知を鳴らし、30秒経過する前に一方のアプリを終了する。
   - Windows上で `PermissionError` が出ずにファイルが削除されること。
   - `%TEMP%` フォルダ内で、終了したプロセスの PID を持つファイルのみが削除され、起動中の別プロセスのファイルは維持されていることを確認する。
   - アプリを強制終了（タスクキル）させた後、再起動したタイミングで過去のゴミファイルが正常に一掃されることを確認する。
