# 改善計画17：自己署名証明書の導入によるウイルス誤検知の解消と自動配布プラン

## 1. 概要・目的

Windows Defender 等におけるデスクトップアプリ（`WonderLinko.exe` および MSI）のヒューリスティック検知（`Trojan:Win32/Bearfoos.A!ml` 等）や SmartScreen の警告、および未署名・不明な発行元としてのブロックを解消するため、**自己署名コードサイニング証明書（オレオレ証明書）** を導入します。

高価なパブリック証明書を購入せず、社内アプリであることを活かして無料でデジタル署名を実現します。また、Active Directory（GPO）が存在しない環境であることを前提とし、**「ビルド時の自動署名」**から**「利用者PCでの証明書登録＋インストール」**までをスクリプト化し、ユーザーに負担をかけないセキュアな配布フローを確立します。
※ 機械学習型検知（ML型）はバイナリ構造そのものを判定することがあるため、署名だけで100%防げないケースも残りますが、本計画により発行元が明示されることで、SmartScreen等の主要なブロッカーを大幅に低減できます。

---

## 2. 現状の課題と解決アプローチ

- **課題**：
  これまでの対策（`cx_Freeze` への移行やホットキーAPIの適正化）でコードの挙動はクリーンになりましたが、**「未署名のパッケージバイナリである」**という事実だけでセキュリティソフトにブロックされるリスクが残っています。また、GPOがないため社内PCの証明書ストアを一括管理できません。さらに、MSIだけに署名した場合、インストール後に展開された `WonderLinko.exe` が未署名のままとなり、実行時に検知・削除されるという重大な問題が発生します。
- **解決策**：
  開発環境で自己署名証明書を発行し、`build_msi.ps1` で生成物に自動署名します。**この際、必ず「内部の exe 本体」と「最終的な MSI」の両方に署名を行います。**
  社内配布時はMSI単体ではなく、**「証明書登録とMSI実行を連続して行うインストール用スクリプト（ラッパー）」**を利用者に配布し、GPOなしでも安全かつワンクリックでインストールできる仕組みを構築します。
  ※一度この仕組みで証明書が登録されれば、次回以降のアップデートはMSIの直接実行でシームレスに行えるようになります。

## 3. 具体的な実装仕様

### ① 自己署名証明書の作成と管理（初回セットアップ）

開発管理者のPCで以下のPowerShellスクリプトを1回のみ実行し、証明書を生成・エクスポートします。

```powershell
# 有効期間は社内運用負荷を下げるため 3〜5年（例: 3年）を推奨
$cert = New-SelfSignedCertificate `
    -Type CodeSigningCert `
    -Subject "CN=WonderLink Internal, O=WonderLink, C=JP" `
    -KeyAlgorithm RSA `
    -KeyLength 2048 `
    -HashAlgorithm SHA256 `
    -CertStoreLocation "Cert:\CurrentUser\My" `
    -NotAfter (Get-Date).AddYears(3) `
    -KeyUsage DigitalSignature `
    -TextExtension @("2.5.29.37={text}1.3.6.1.5.5.7.3.3")

# パスワード保護付きで .pfx をエクスポート
$pwd = ConvertTo-SecureString -String $env:CERT_PASSWORD -Force -AsPlainText
Export-PfxCertificate -Cert $cert -FilePath "cert/WonderLink_CodeSigning.pfx" -Password $pwd

# 配布用公開鍵（.cer）をエクスポート
Export-Certificate -Cert $cert -FilePath "cert/WonderLink_InternalRoot.cer"
```

> **TIP**: パブリックな認証局と異なり、自己署名証明書は1年制限の縛りを受けません。有効期間を 3〜5年 に設定しておくと、更新頻度が下がり社内運用の負担を大幅に削減できます。

- **【重要】証明書の用途制限**：万が一の秘密鍵漏洩時に中間者攻撃等へ悪用されるのを防ぐため、証明書の「拡張キー使用法（EKU）」は**「コード署名 (1.3.6.1.5.5.7.3.3)」のみに限定**して生成します。
- 署名用秘密鍵ファイル（`cert/WonderLink_CodeSigning.pfx`）：プロジェクトの `cert` フォルダに配置（Gitにはコミットしない）。
  **【追加】バックアップ運用**：PCの故障に備え、発行した `.pfx` と `.env` のパスワードは、アクセス権が制限された社内のセキュアなファイルサーバーやパスワードマネージャー等にバックアップとして安全に保管します。
- 署名用パスワード管理：パスワードはプロジェクトの `.env` ファイルに `CERT_PASSWORD=your_password` として定義し、ビルドスクリプトから読み込ませる安全な設計とします。
- 社内配布用公開鍵ファイル（`cert/WonderLink_InternalRoot.cer`）：ビルド時に `dist/` へコピーして MSI と一緒に配布します。

### ② ビルドパイプラインへの自動署名組み込み

`build_msi.ps1` を改修し、Windows SDK の `signtool.exe` を用いて、2段階の署名プロセスを実装します。

0. **証明書の有効期限自動チェック**:
   署名処理の前に `.pfx` を読み込み、有効期限が残り60日未満の場合はコンソールに警告（`Write-Warning`）を出力する処理を追加します。これにより、証明書の期限切れ（更新漏れ）を未然に防ぎます。
1. **signtoolの自動探索**:
   `C:\Program Files (x86)\Windows Kits\10\bin\*\x64\signtool.exe` 等から、実行環境の `signtool.exe` のパスを自動解決する処理を追加します。（実行にはWindows SDKのインストールが必須です）
2. **exeおよびMSIのビルドと署名フロー**:
   - `python setup.py build_exe` を実行し、出力されたビルド成果物に対して、**署名前にバンドル漏れチェック（PIL、socketio、engineio等）や不要パッケージ（pynput）の除外チェック**を実施します。ビルド不備がある場合は署名処理を行わずに即中断（Aborting）させます。
   - チェック通過後、出力された `WonderLinko.exe` に加え、同梱された **`*.dll` や `*.pyd` も一括で** `.pfx` を用いて署名します。
   - 続いて **`python setup.py bdist_msi --skip-build`** を実行します（※再ビルドによる署名済みバイナリの上書きを防ぐため、必ず `--skip-build` オプションを適用します）。
   - 生成された `WonderLinko.msi` に対して、再度署名を行います。
3. **タイムスタンプの付与とフェールオーバー**:
   証明書の期限切れに備え、署名時には必ずタイムスタンプサーバーを指定し、ハッシュアルゴリズムは `sha256` を使用します。環境依存で古い SHA-1 が使われるリスクを防ぐため、ファイルダイジェストとタイムスタンプダイジェストのオプションを明記します。
   例: `signtool sign /f $pfx /p $pwd /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 $file`
   ※一時的な通信障害に備え、メインサーバー（例: `http://timestamp.digicert.com`）がタイムアウトした場合は、代替サーバー（例: `http://timestamp.sectigo.com`）へリトライするロジックを実装します。

### ③ クライアントPC向けインストールスクリプトの作成（GPO代替）

GPOによる自動配布ができないため、ユーザーには `WonderLinko.msi` と `.cer`、そして **`install.bat`** をセットでZIP等にして配布します。
※`dist/` ディレクトリは `.gitignore` で除外されているため、`install.bat` のマスターファイルは `scripts/install.bat` として Git 管理し、ビルド時に `dist/` フォルダへコピーします。

- **`install.bat` の処理フローとスクリプト例**:
  1. **文字コードの指定**: パス解決時の文字化けやコマンド実行エラーを防ぐため、スクリプトは必ず **Shift-JIS (CP932)** で保存することを徹底します。
  2. **UAC自動昇格**: 一般ユーザーがダブルクリックした場合でも、PowerShell 経由で管理者権限への昇格プロンプトを自動表示します。
  3. **パスの指定とカレントディレクトリ移動**: UAC昇格に伴いカレントディレクトリが `C:\Windows\System32` 等へ移動する対策として、`cd /d "%~dp0"` でバッチ自身のディレクトリへ移動し、確実なパス解決を行います。
  4. **ZIP未解凍実行のガード**: エクスプローラー等でZIPを開いたまま実行するトラブルを防ぐため、MSIファイルの存在チェックを行います。
  5. **常駐プロセスの自動終了**: 更新インストール時、タスクトレイに常駐中のアプリが存在するとMSI実行時にファイルロックエラーとなるため、事前に強制終了します。
  6. **旧証明書のクリーンアップ (将来向け準備)**: 古い自己署名証明書がゴミとして残るのを防ぐための削除処理を準備しておきます。
  7. **インストール自動化と完了メッセージ**: `msiexec` に `/qb` などの UI 制御オプションを渡し、処理結果をユーザーに明示します。
  
  ```bat
  @echo off
  :: 管理者権限の確認と自動昇格
  net session >nul 2>&1
  if %errorlevel% neq 0 (
      powershell -Command "Start-Process '%~f0' -Verb RunAs"
      exit /b
  )

  :: カレントディレクトリをバッチファイルの存在する場所へ移動
  cd /d "%~dp0"

  :: 【追加】ZIP未解凍実行のチェック
  if not exist "WonderLinko.msi" (
      echo [ERROR] 必要なファイルが見つかりません。
      echo ZIPファイルをすべて展開（解凍）してから install.bat を実行してください。
      pause
      exit /b 1
  )

  :: 常駐プロセスの終了（ファイルロックによるインストール失敗防止）
  taskkill /f /im WonderLinko.exe >nul 2>&1

  :: 【将来用】古い証明書の削除（Thumbprint等で指定）
  :: certutil -delstore "Root" "OLD_CERT_THUMBPRINT" >nul 2>&1

  :: 証明書の登録 (Root および TrustedPublisher)
  certutil -addstore -f "Root" "WonderLink_InternalRoot.cer" >nul 2>&1
  certutil -addstore -f "TrustedPublisher" "WonderLink_InternalRoot.cer" >nul 2>&1

  :: MSIインストーラーの起動 (基本UIのみ表示で自動進行)
  msiexec /i "WonderLinko.msi" /qb
  if %errorlevel% equ 0 (
      echo.
      echo ============================================
      echo インストールが正常に完了しました。
      echo ============================================
  ) else (
      echo.
      echo [ERROR] インストール中にエラーが発生しました (ErrorCode: %errorlevel%)。
      pause
  )
  ```

## 5. 検証および運用計画 (Verification & Operation Plan)

### ビルドと署名の検証

1. **自動署名の成功確認**:
   - 開発環境で `build_msi.ps1` を実行し、有効期限の警告チェックが正常に動くこと、およびエラーなくビルドが完了することを確認する。
   - タイムスタンプサーバー通信のリトライ挙動（ネットワーク切断時等のタイムアウト）が適切に機能するかテストする。
   - 出力された MSI および展開後の `WonderLinko.exe`、主要な `.dll`, `.pyd` のプロパティを開き、「デジタル署名」タブが存在し、証明書とタイムスタンプが正しく付与されていることを確認する。

### インストールフローと実行時の検知回避検証

1. **クリーンなWindows PCでの実行**:
   - 自己署名証明書が未登録のテストPCに、配布用セット（`MSI`, `.cer`, `install.bat`）をコピーする。
2. **スクリプトの動作と検知回避確認**:
   - `install.bat` をダブルクリックして実行し、UACプロンプトで「はい」を選択した後、自動的に証明書がインストールされることを `certlm.msc`（ローカルコンピューターの証明書）を開いて確認する。
   - 続けて MSI が起動し、SmartScreen の青い警告画面が出ずにインストールが完了することを確認する。
   - インストール後、`WonderLinko.exe` を起動し、Windows Defender のリアルタイムスキャンやSmartScreenブロックに引っかかることなく正常に動作することを確認する。

### 運用計画と社内アナウンス

- **インストール手順の周知とメリットの提示**:
  社内ポータルやチャットツールにて、「次回からは `WonderLinko.msi` を直接実行せず、同梱されている `install.bat` をダブルクリックしてインストールしてください」という手順の変更を明確にアナウンスする。
  合わせて、「一度この手順で証明書がPCに登録されれば、次回以降のアップデート時はMSIの直接実行が可能になる（ブロックされなくなる）」というメリットも周知し、ユーザーの理解を得る。
- **【重要】UACプロンプトに関する事前告知**:
  ユーザーの不安・混乱を避けるため、アナウンスに以下のような文言を含める。
  > 「`install.bat` をダブルクリックすると、画面が暗くなり『このアプリがデバイスに変更を加えることを許可しますか？（Windows コマンド プロセッサ）』という警告が出ます。これはインストールに必要な権限を得るための正常な動作ですので、『はい』をクリックして進めてください。」
- **ブラウザダウンロード時の MotW（Mark of the Web）に関する注意事項**:
  社内WebポータルやTeams等からZIPをダウンロードした際の挙動について、以下のアナウンスを追加する。
  > 「ZIPダウンロード直後に実行すると、Windows のセキュリティ機能により青い警告画面（SmartScreen）が出ることがあります。その場合は『詳細情報』をクリックして『実行』を押すか、ZIPファイルのプロパティを開き『許可する（ブロックの解除）』にチェックを入れてから展開してください。」
- **証明書の更新管理（手動更新による計画的運用）**:
  GPO（Active Directory）がない本環境では、証明書を自動更新すると利用者のPCで信頼チェーンが途切れ、再度インストールがブロックされてしまいます。そのため、**証明書の自動更新は行いません。**
  代わりに、ビルドスクリプト（`build_msi.ps1`）に組み込んだ有効期限チェックにより、期限切れの60日前に開発者へ警告（Warning）を出します。警告が出た段階で新しい証明書を発行し、次回のリリース時に合わせて全社へ「今回のアップデートは（初回導入時と同様に）`install.bat` から実行してください」とアナウンスする、計画的な手動更新イベントとして運用します。
  ※この更新時には、`install.bat` 内の古い証明書の削除処理（Thumbprint指定）を有効化して配布します。
