## バグ1: パーソナルボード入力がタスクボードに振り分けられる ✅

**根本原因**: [`create_personal_note`](file:///c:/Users/yuuya/Documents/dev/wl-board-pj/board-system/backend/app/routers/sticky_notes.py#L233) が `process_new_note_ai()` を呼んでいた。このAI処理はタスクボード（TASK）への配置を生成するため、パーソナル投稿も自動的にタスクボードに乗っていた。

**修正内容** ([sticky_notes.py](file:///c:/Users/yuuya/Documents/dev/wl-board-pj/board-system/backend/app/routers/sticky_notes.py)):
```diff
- from app.services.orchestrator import process_new_note_ai
- await process_new_note_ai(note.id, db)   # ← TASKボードに配置されてしまう
+ # パーソナル投稿では process_new_note_ai を呼ばず、TASKボードへの配置は行わない
  await apply_due_date_rules_for_note(note.id, db)
```

## バグ2: パーソナルボードのゴミ箱が使えない ✅

**根本原因**: バグ1の副作用。パーソナル投稿した付箋がTASKボードにも配置されるため `is_from_task=true` と判定される。旧ゴミ箱は `isFromTask === "true"` の場合にドロップをブロックしていた。

**修正内容** ([PersonalBoardView.tsx](file:///c:/Users/yuuya/Documents/dev/wl-board-pj/board-system/frontend/app/components/PersonalBoardView.tsx)):
- `PersonalTrashDropZone` の `isFromTask` ブロックを削除 → どの付箋でもゴミ箱に捨てられる
- `handleTrashDrop` を分岐: タスク由来 → **PERSONAL配置のみ削除**、パーソナル独自 → **StickyNote本体を削除**

```diff
- async (noteId: number) => {
-   await api.stickyNotes.delete(noteId);  // isFromTaskのときブロックしていた
+ async (placementId: number, noteId: number, isFromTask: boolean) => {
+   if (isFromTask) {
+     await api.boardPlacements.delete(placementId); // 配置のみ削除（タスクボードは残る）
+   } else {
+     await api.stickyNotes.delete(noteId); // 付箋ごと完全削除
+   }
```

> [!NOTE]
> バグ1の修正後は is_from_task=false の付箋が正しく生成されるため、バグ2は自然に解消されます。ただし既存データ（修正前に投稿された付箋）のために明示的な修正も入れています。

## バグ3: タスクボードのゴミ箱で削除しても復活する ✅

**根本原因**: `delete_sticky_note` が wl-sticky-note への **グレー化通知を例外握りつぶし** で失敗していた可能性。グレー化通知が届かないと、5分ごとの自動取り込みが付箋を再インポートしてしまう。

**修正内容** ([sticky_notes.py](file:///c:/Users/yuuya/Documents/dev/wl-board-pj/board-system/backend/app/routers/sticky_notes.py)):
```diff
  if postit_board_id and postit_note_id:
-     await asyncio.to_thread(_notify_postit_archive, ...)
+     try:
+         await asyncio.to_thread(_notify_postit_archive, ...)
+         _logger.info("[delete_sticky_note] グレー化通知完了")
+     except Exception as e:
+         _logger.warning("[delete_sticky_note] グレー化通知失敗 (付箋が再取り込みされる可能性あり): %s", e)
```

> [!IMPORTANT]
> ログを確認することで `postit_board_url` の設定ミスや接続エラーが特定できます。グレー化通知が継続的に失敗する場合は `.env` の `POSTIT_BOARD_URL` を確認してください。

## バグ4: デスクトップアプリの通知が出ない ✅

**根本原因**: `show_toast` の `winotify` 呼び出し部分の `except Exception: pass` がエラーを握りつぶしていたため、なぜ通知が出ないか不明だった。

**修正内容** ([notifications.py](file:///c:/Users/yuuya/Documents/dev/wl-board-pj/wl_desktop_app/notifications.py)):
```diff
- except Exception:
-     pass
+ except Exception as _toast_err:
+     _err_msg = f"[Notify] winotify 失敗: {_toast_err}"
+     try:
+         from app_log import log_info
+         log_info(_err_msg)
+     except Exception:
+         print(_err_msg, flush=True)
```

> [!IMPORTANT]
> 修正後にアプリを再起動し、`WonderLinko.log` を確認することで通知失敗の原因が特定できます。一般的な原因:
> - Windows の通知設定で「WonderLinko.Desktop」が無効化されている → 設定 > システム > 通知で確認
> - フォーカスアシスト（集中モード）がオンになっている
> - `winotify` パッケージがインストールされていない

## バグ5: ショートカットから起動するたびにアプリアイコンが増える ✅

**根本原因**: `_acquire_single_instance_lock()` が候補ポート(50050, 50051, 50052)を **順番にバインド** していた。3つのプロセスが起動すると各自が別のポートを掴んで全員が「正規インスタンス」と判断してしまい、トレイアイコンが複数作成されていた。

**修正内容** ([app.py](file:///c:/Users/yuuya/Documents/dev/wl-board-pj/wl_desktop_app/app.py)):

新方式: **接続テスト → バインド** の2段階方式

```python
# Step 1: 先発プロセスの存在確認（接続テスト）
for port in _SINGLE_INSTANCE_PORTS:
    probe = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    probe.settimeout(0.3)
    result = probe.connect_ex(("127.0.0.1", port))
    probe.close()
    if result == 0:
        return False  # 接続成功 = 先発プロセスあり → 即終了

# Step 2: 先発プロセスなし → バインドしてロック取得
```

| 旧方式 | 新方式 |
|--------|--------|
| バインドできれば「正規」と判断 | まず接続テストで先発プロセスを確認 |
| 3ポートあるため3プロセス起動可能 | 1つでも接続できれば重複判定 |

## 検証方法

| バグ | 検証手順 |
|------|---------|
| **1** | board-system を再起動後、パーソナルボードに投稿 → タスクボードに**表示されない**ことを確認 |
| **2** | パーソナルボードの付箋をゴミ箱にドロップ → 削除されることを確認（タスク由来もパーソナル独自も両方）|
| **3** | タスクボードでゴミ箱ドロップ後、5分待って復活しないことを確認。ログで `グレー化通知完了` を確認 |
| **4** | デスクトップアプリ再起動後に `WonderLinko.log` で `[Notify] winotify 失敗` の有無を確認 |
| **5** | デスクトップのショートカットを連続クリックし、トレイアイコンが**1つだけ**しか増えないことを確認 |
