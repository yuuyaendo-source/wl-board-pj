# タスク期限設定と期限に基づくパーソナルボード自動移動機能の実装プラン

タスクに期限（due_date）を設定可能にし、期限までの日数に応じて自動的にパーソナルボードの `Today` レーンと `タスク (INBOX)` レーンを行き来する機能を実装します。

## User Review Required

> [!IMPORTANT]
> **日付とタイムゾーンの扱いについて**
> 期限の判定および「残り日数」の計算は、日本時間（JST, `Asia/Tokyo`）を基準として日次バッチ（毎日 8:00 実行の `run_8am` など）内で行います。
> フロントエンドとバックエンド間の `due_date` の送受信は、タイムゾーンによる日付ずれを防ぐため、**純粋な文字列形式 `YYYY-MM-DD`** で統一します。
>
> **期限切れタスクの扱いについて**
> 期限を過ぎたタスク（残り日数 `days < 0`）については、毎日自動的に **Today** レーンに配置します。
> ただし、**すでに完了（`DONE`）レーンにあるタスクは、期限切れであっても自動移動の対象から明示的に除外**し、`DONE` に留め続けます。
>
> **期限（due_date）変更時の手動フラグリセットについて**
> ユーザーが付箋の `due_date` を更新（新規設定・変更・削除）した場合、該当する付箋IDに紐づく**すべての `BoardPlacement`** について `is_manually_moved_to_today` フラグを強制的に `False` に一括更新（リセット）します。これにより、期限変更後に再度自動移動ロジックが適用されるようになります。

### Batch Job / Auto Migration Logic

#### [MODIFY] [routers/daily_reset.py](file:///c:/Users/yuuya/Documents/dev/wl-board-pj/board-system/backend/app/routers/daily_reset.py)
- 朝 8:00 に実行される `run_8am` API 内で、期限タスクの自動移動ロジックを実行する関数 `apply_due_date_rules(db)` を呼び出すように変更。
- `apply_due_date_rules(db)` の仕様：
  - `board_type == BoardType.PERSONAL` であり、紐づく付箋に `due_date` が設定されている配置を取得。
  - ただし、**`lane == Lane.DONE` のものは明示的に除外**。
  - `is_manually_moved_to_today == True` のものは判定をスキップ。
  - 日本時間 (JST) の当日日付を基準とし、`days = (due_date - today).days` を計算。
  - **期限切れルール (`days < 0`)**:
    - 毎日 `Lane.TODAY` に移動。
  - **短期ルール (1ヶ月未満 = `0 <= days < 30`)**:
    - `days` が `[0, 1, 2, 3, 4, 5, 10, 20]` のいずれかなら、レーンを `Lane.TODAY` にする。
    - それ以外なら、レーンを `Lane.INBOX` にする。
  - **長期ルール (1ヶ月以上 = `days >= 30`)**:
    - `days % 30 == 0` ならレーンを `Lane.TODAY` にする。
    - それ以外なら、レーンを `Lane.INBOX` にする。
