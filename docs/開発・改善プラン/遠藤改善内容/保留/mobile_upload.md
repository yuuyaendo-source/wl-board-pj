# スマホ付箋撮影・アップロード機能（Mobile Upload）拡張計画

## 1. 概要とコンセプト
本機能（`src/app/mobile/upload/page.js`）は、**「専用の定点カメラがない環境や外出先からでも、手元のスマートフォンで物理的な付箋やメモを撮影し、即座にデジタルボードへ取り込む」**ことを目的とした機能です。

現状はPoC（概念実証）レベルの最小限のコードとなっているため、これを実際の業務に耐えうる実用的な機能へと昇華させるための要件を整理します。

---

## 2. 現状の仕様と「できること」（As-Is）

現在のコードで既に実現されている機能は以下の通りです。

*   **デバイスネイティブなカメラ起動**: `<input type="file" capture="environment">` を使用し、ブラウザから直接スマホの背面カメラを起動できます。
*   **バックエンドへの画像送信**: Next.js の Rewrite 設定（`/api/proxy/upload_image`）を経由し、AI-Board（Python側 / Port 5000）へ画像を POST 送信できます。
*   **非同期UI（ローディングとトースト）**: 送信中のスピナー表示と、完了・失敗時のトースト通知（ポップアップ）が実装されています。

---

## 3. これから改善が必要な課題（技術・仕様面）

本格運用に向けて、直ちに解決すべき技術的な課題です。

### 3.1. PC画面からのUI動線（誘導）の欠如
*   **課題**: 現在、このページ（`/mobile/upload`）へアクセスする手段がありません。
*   **解決案**: PC版の `Toolbar.js` 等に「📱スマホで追加」ボタンを設置し、クリック時に**アクセス用QRコード**を表示するモーダルを実装します。

### 3.2. 送信先ボード（Board ID）の指定不足
*   **課題**: 画像を送信する際、どのボード（例: `wl` や `taskboard`）に追加するかの指定がありません。
*   **解決案**: URLのクエリパラメータ（例: `/mobile/upload?board_id=wl`）で対象ボードを受け取り、送信時の FormData に含めてバックエンドへ渡すようにします。QRコード生成時にこのURLを埋め込みます。

### 3.3. クライアント側での画像圧縮の欠如
*   **課題**: 最近のスマートフォンの写真は高解像度（数MB〜十数MB）であり、そのまま送信すると通信量が膨大になり、バックエンドのAI処理（OpenCV/Gemini）にも過度な負荷がかかります。
*   **解決案**: ブラウザ側（Canvas API等）で、送信前に画像を適切なサイズ（例: フルHD程度）と画質に圧縮（リサイズ）してから送信する処理を追加します。

### 3.4. 認証・セキュリティ
*   **課題**: 誰でもアクセスして画像を送信できてしまう状態です。
*   **解決案**: Board System のログインセッションと連携するか、QRコードに使い捨てのワンタイムトークンを含めることで、許可されたユーザーのみがアップロードできるようにします。

## 4. よりUXを向上させるためのアイデア（To-Be）

ユーザーが「面倒くさい」と感じず、アナログとデジタルをシームレスに行き来できるようにするための機能提案です。

### ① スムーズな連続撮影モード
現状は「撮影 → 待機 → トースト表示」で1サイクルが終わりますが、会議終了後などに大量の付箋を撮りたい場合、操作が煩雑になります。
*   **提案**: PWA (Progressive Web Apps) の機能や WebRTC（`navigator.mediaDevices.getUserMedia`）を用いて、ブラウザ内にカメラのプレビュー画面を直接埋め込みます。「シャッターボタンを押すと裏で非同期送信され、ユーザーは待たずに次の付箋を撮影できる」ような連続撮影UIを構築します。

### ② 画像の事前プレビューとトリミング（切り抜き）
*   **提案**: 撮影した直後に画面上でプレビューを表示し、ユーザー自身が付箋の四隅をドラッグして切り抜ける（パース補正できる）機能を提供します。これにより、AI側の検知エラーを未然に防ぐことができます。

### ③ 送信結果のリアルタイム・フィードバック
*   **提案**: 現在の「送信しました」というトーストだけでなく、バックエンドでのAI処理（付箋の抽出とテキスト化）が完了し、**「PC側のボードに実際に反映された」タイミングでスマホ側にも Socket.IO 経由で通知**を送り、「✨ ボードに追加されました」とフィードバックします。

### ④ AIへの音声メモ（プロンプト）の同時送信
*   **提案**: 写真を撮る際、テキスト入力欄やマイクボタンを用意します。「この付箋は重要タスクに入れて」「これは〇〇さん宛て」といった指示（プロンプト）を付与して送信し、AIの自動振り分け精度を向上させます。

## 5. 推奨される実装ステップ

まずは以下の順序で開発を進めることをお勧めします。

1.  **Step 1（動線の確保と安定化）**
    *   PC版にQRコード表示ボタンを追加。
    *   URLパラメータによる Board ID の受け渡し実装。
    *   フロントエンドでの画像圧縮処理の追加。
2.  **Step 2（バックエンド連携）**
    *   バックエンド側（AI-Board）で `upload_image` エンドポイントを整備し、受け取った画像から付箋を抽出・テキスト化して対象のBoard Systemへ反映させる。
3.  **Step 3（UXの高度化）**
    *   連続撮影モードやプレビュー機能、PWA化など、モバイル特有の体験向上。
