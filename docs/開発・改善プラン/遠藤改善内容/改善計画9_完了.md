# 改善計画9：タスクローテーション（停滞タスクの自動並び替え）機能の実装完了報告

ご依頼いただいた「改善計画9：タスクローテーション（停滞タスクの自動並び替え）機能の実装プラン」に基づく、停滞タスクの自動ローテーション処理、優先タスク（期限10日以内）の除外キープ、および日次バッチ（`run_8am`）への組み込み作業がすべて完了いたしました。

---

## 実施した変更の詳細

### 1. タスクローテーションロジックの実装 (`board-system/backend/app/routers/daily_reset.py`)
- **`rotate_stale_tasks(db: AsyncSession, force: bool = False)` の新設**:
  - **実行頻度判定**: JST現在日の `today.toordinal() % 2 == 0` により、2日に1回の頻度で自動実行されます（手動実行用の `force=True` パラメータも用意）。
  - **優先タスクの除外キープ**: 期限が10日以内のタスク（`0 <= (due_date - today).days <= 10` または期限切れ）はローテーション対象から除外し、先頭側の位置をキープします。
  - **Task Board のローテーション**:
    - 「完了（5）」以外の各象限（アイデア・短期・長期・重要）において、対象タスクが **11件以上** ある場合、先頭 **10件** を末尾へ移動します。
  - **Personal Board のローテーション**:
    - 各ユーザーの `Lane.INBOX` において、対象タスクが **4件以上** ある場合、先頭 **3件** を末尾へ移動します。
  - **並び順の再採番（正規化）**:
    - リスト全体に対して `sort_order` を `0` からの連番で再採番して保存し、D&D操作との整合性を担保します。

### 2. 日次バッチ (`run_8am`) への組み込み
- `apply_due_date_rules(db)` の実行直後に `rotate_stale_tasks(db)` を呼び出すよう連携しました。
- 期限間近で `Today` レーンへ移動すべきタスクを先に移動させた上で、残った `INBOX` および Task Board に対して安全にローテーションが適用されます。
- `POST /daily_reset/run_8am` のレスポンスに `task_rotation` 結果（移動件数・スキップ理由など）を含めるように拡張しました。

### 3. 手動実行・テスト用エンドポイントの追加
- `POST /daily_reset/rotate_tasks?force=true` を新設し、2日に1回の条件を無視して即座にローテーションをトリガー・テストできるようにしました。

---

## 確認方法

1. **手動トリガーによるローテーション確認**:
   - `POST /daily_reset/rotate_tasks?force=true` を実行し、レスポンスで `task_rotated_count` および `personal_rotated_count` の移動件数が返却されることを確認してください。
2. **優先タスクのキープ確認**:
   - 期限が今日から10日以内のタスクを配置した状態でローテーションを実行し、それらのタスクが先頭位置に維持されたまま、それ以外の停滞タスクのみが末尾に回ることを確認してください。
3. **日次バッチ (`run_8am`) での連携確認**:
   - `POST /daily_reset/run_8am` を実行し、期限タスクの Today 移動と停滞タスクのローテーションが順序通り実行され、ログが出力されることを確認してください。
