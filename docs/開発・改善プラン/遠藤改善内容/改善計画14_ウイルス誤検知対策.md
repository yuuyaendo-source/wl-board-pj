# 改善計画14：ウイルス誤検知（False Positive）対策とセキュリティ適正化の実装プラン

## 1. 概要・目的

Windows Defender等のセキュリティソフトにおいて、開発中のデスクトップアプリ（`build\exe.win-amd64-3.14\WonderLinko.exe` など）が「`Trojan:Win32/Bearfoos.A!ml`」として誤検知（False Positive）される問題を解決します。
セキュリティソフトの機械学習（ML）モデルに「悪意のある挙動」としてスコアリングされやすいコードパターンを排除・適正化し、開発時および社内PC展開時にブロックされることなく安全に実行・常駐できる状態にします。

---

## 2. 誤検知の根本原因（現状の課題）

以下の要素が組み合わさることで、ヒューリスティック検知（AIによる振る舞い検知）に引っかかっています。

1. **グローバルキーフック (`pynput`) の使用**
   - `mini_port.py` にて、アプリが非アクティブな状態でも `Ctrl+Shift+Space` を検知するために `pynput.keyboard.GlobalHotKeys` を使用しています。この「バックグラウンドでキー入力を監視する」挙動が、キーロガー（入力盗聴ソフト）のパターンと酷似しています。
2. **高リスクモジュールの起動時一括ロード**
   - `cv2`（カメラ制御）、`sounddevice`（マイク制御）、`socketio`（ネットワーク通信）といったモジュールが起動時近くに読み込まれると、スパイウェアやトロイの木馬の挙動特性として判定スコアが上がります。
3. **起動時のサイレントなレジストリ書き換え (`app.py` / `startup.py`)**
   - アプリ起動時に、ユーザーの明示的な許可なく `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` に自身を登録しています。これがマルウェアによる「永続化（Persistence）」の手口と判定されます。
4. **スタンドアロン化ツール（`cx_Freeze`）の特性と署名不在**
   - `cx_Freeze` が生成するブートストラップ用EXEファイルのヘッダー構造が検知されやすい傾向にあることに加え、デジタル署名がないため「未知の保護されていないアプリ」として処理されます。

---

## 3. 具体的な実装仕様 (Proposed Changes)

### ① グローバルキーフック機能のOS標準API（`RegisterHotKey`）への移行

誤検知の最大要因である `pynput` を完全に排除し、Windows OS が提供する安全な標準APIを利用してショートカットを実装します。

- **`requirements.txt` / `setup.py` の修正**:
  - `requirements.txt` から `pynput>=1.7.6` を削除します。
  - **【重要】** `setup.py` の `build_exe_options` 内の `includes` リストに加え、122行目付近の **`packages` リスト** にも `"pynput"` が指定されているため、これを**両方から確実に削除**します。その上で、ビルド時に再び取り込まれてしまうなど意図せぬ混入を防ぐため `excludes` に `"pynput"` を追加します。
- **`mini_port.py` の修正**:
  - `pynput` を用いたホットキー実装を廃止し、`ctypes.windll.user32.RegisterHotKey` を用いた Win32 API 経由での実装に置き換えます。（ダミーウィンドウを必要とせず、スレッドセーフでCPU負荷もゼロに近い、スレッドメッセージキューパターンを採用します。詳細は後述の実装Tipsを参照）

### ② 自動スタートアップ登録ロジックの適正化（明示的なオプトイン化）

アプリ起動時のサイレントなレジストリ操作はマルウェア的挙動として検知されやすいため廃止します。また、インストーラーによる強制的な自動起動（二重起動や無効化不可の問題を引き起こす原因）も行わず、アプリのデフォルト状態は「自動起動オフ」とします。

- **`app.py` の修正**:
  - 以下の起動時自動登録ロジック（サイレントなレジストリ書き換え）を完全に削除（またはコメントアウト）します。

  ```python
  # if (
  #     sys.platform == "win32"
  #     and getattr(sys, "frozen", False)
  #     and not startup.is_startup_enabled()
  # ):
  #     if startup.set_startup_enabled(True): ...
  ```

- **運用方針と `startup.py` の維持**:
  - インストール時の MSI 経由での `StartupFolder` へのショートカット作成機能は**使用しません**（設定の競合と二重起動を防ぐため）。
  - `startup.py` および `settings_dialog.py` による手動スタートアップ切り替え機能は維持します。ユーザーが希望する場合のみ、設定画面からチェックを入れることで明示的にレジストリへの登録が行われます。ユーザー操作起因の明示的な設定変更であるため、セキュリティソフトからの評価低下リスクを安全に抑えられます。

### ③ 高リスクモジュールの遅延インポート（Lazy Import）の徹底

カメラ、マイク、ソケット通信等の機能は、アプリ起動時（グローバルスコープ）に読み込むのではなく、機能が呼び出された（イベントハンドラやダイアログの初期化メソッド内）タイミングでのみインポートするようにコードをリファクタリングします。
（既存の `face_registry_admin_dialog.py` や `face_registry_client.py` での関数内インポートの良いパターンを、`mini_port.py` や `app.py` における `socketio`、`sounddevice`、`cv2` の読み込み等にも徹底します）

### ④ ビルドツール（`cx_Freeze`）の更新と最適化

`cx_Freeze` が生成するブートストラップバイナリの構造が、マルウェアと誤判定される原因を軽減します。

- **`build_msi.ps1` の修正**:
  - `cx_Freeze` を最新版に更新するコマンドが含まれていることを確認します。
- **代替手段（`PyInstaller` への移行検討）**:
  - もし `cx_Freeze` の更新後も誤検知が続く場合は、ビルドツールを `PyInstaller` に変更する移行計画を検討します。

### ⑤ ユーザー影響の周知とドキュメント更新

* **`README.md` の修正**:
  - 内部実装が `RegisterHotKey` に変更されたことに伴う仕様変更（他のアプリと競合した場合の挙動など）や、自動起動の仕組みが変更された旨（デフォルトオフ化）を追記します。

### ⑥ （運用面）開発環境の除外設定と配布時の対策

* **開発時の Defender 除外設定案内**:
  - 開発者のPC上で `build` フォルダ配下を Windows セキュリティの「ウイルスと脅威の防止」＞「除外」に追加する運用をドキュメント化します。
- **配布パッケージの署名**:
  - 社内配布時の `build_msi.ps1` プロセスに、将来的に Authenticode デジタル署名を付与するステップを組み込む検討事項をドキュメント化します。

## 5. 検証計画 (Verification Plan)

### Automated / Build Tests

1. **ビルド成功とクリーンナップの確認**:
   - `build_msi.ps1` を実行し、`pynput` への参照エラーなどが発生せずに完了することを確認する。
2. **成果物への `pynput` 混入チェック**:
   - ビルド完了後、出力フォルダ内に `pynput` が残存していないことを確認する。

### Manual Verification

1. **Windows Defender による即時コマンドラインスキャン**:
   - `Trojan:Win32/Bearfoos.A!ml` 検知が解消されたか、CLI ツールでビルド成果物を直接スキャンし確認する。

   ```powershell
   & "C:\Program Files\Windows Defender\MpCmdRun.exe" -Scan -ScanType 3 -File (Resolve-Path "dist\WonderLinko.msi")
   ```

2. **Win32 API ホットキーの動作確認**:
   - アプリを起動し、バックグラウンド状態で `Ctrl+Shift+Space` を押下した際、正しくミニポートが前面表示されることを確認する。
   - アプリ終了時にリソースリークが発生せず安全にスレッドが破棄されること。
3. **スタートアップ登録の動作確認**:
   - アプリ初回起動時にレジストリが勝手に書き換わらないこと（自動起動はデフォルトオフ）。
   - アプリの「設定」画面から「PC起動時に自動で起動」をオンにした場合のみ、次回PC起動時にアプリが自動起動すること。
   - オフにした場合は、正常に自動起動が無効化されること。ショートカットとレジストリによる二重起動が発生しないこと。

## 6. 実装に向けた技術的アドバイス（RegisterHotKey 実装Tips）

`mini_port.py` で `RegisterHotKey` を実装する際、ダミーウィンドウを作成せず、最もシンプルかつ安定して動作する「スレッドメッセージキューを利用する」パターンを推奨します。

`RegisterHotKey` で登録したホットキーは、登録したスレッドの終了時に Windows OS が自動的にクリーンアップします。`daemon=True` なバックグラウンドスレッド内でループを回す設計であれば、アプリ終了時（プロセス終了時）に安全に破棄されるため、リソースリークの心配もありません。

`RegisterHotKey` の第1引数 `hWnd` に `None` (NULL) を渡すことで、メッセージはウィンドウではなく呼び出し元スレッドのメッセージキューに直接配送されます。これにより、バックグラウンドスレッドでシンプルな `GetMessageW` ループを回すだけで完結します。

```python
import ctypes
from ctypes import wintypes
import threading
import sys

user32 = ctypes.windll.user32
MOD_CONTROL = 0x0002
MOD_SHIFT = 0x0004
VK_SPACE = 0x20
HOTKEY_ID = 1
WM_HOTKEY = 0x0312

def _start_hotkey_listener(self):
    if sys.platform != "win32":
        return

    def listen():
        # 1. スレッド内でホットキーを登録（hWnd=None でスレッドキューに送る）
        if not user32.RegisterHotKey(None, HOTKEY_ID, MOD_CONTROL | MOD_SHIFT, VK_SPACE):
            print("Linko Mini-Port: ショートカット (Ctrl+Shift+Space) の登録に失敗しました（他アプリと競合の可能性）")
            return

        try:
            msg = wintypes.MSG()
            # 2. GetMessageW でメッセージを待機（メッセージが来るまでスレッドは完全休止）
            while user32.GetMessageW(ctypes.byref(msg), None, 0, 0) > 0:
                if msg.message == WM_HOTKEY and msg.wParam == HOTKEY_ID:
                    # 3. Tkinter のメインスレッドに安全にフォーカス処理を委譲
                    self.after(0, self.focus_and_raise)
        finally:
            user32.UnregisterHotKey(None, HOTKEY_ID)

    t = threading.Thread(target=listen, daemon=True)
    t.start()
```

**このアプローチのメリット:**
- `pynput` と同様に `daemon=True` のスレッドで常駐し、アプリ終了時はプロセスごと安全に破棄されます。
- Windows API への過剰なアクセス（常時ポーリングなど）が発生せず、CPU負荷もゼロです。
- 他のアプリが同一ショートカットを使用している場合でも例外でクラッシュせず、安全にフォールバックできます。

## 7. 実装に向けた補足メモ（着手時の確認用）

- **既存 `.venv` のクリーンアップの徹底 (重要)**:
  `cx_Freeze` は仮想環境内に存在するパッケージを自動で収集してしまうことがあるため、不具合や不要ファイルの混入を防ぐ良いプラクティスとして、ビルド前に必ず以下のコマンドを実行し、環境をクリーンにしておくことを徹底します。

  ```powershell
  .venv\Scripts\python.exe -m pip uninstall -y pynput
  ```

* **ビルドツールの検討**:
  - 現時点では `build_msi.ps1` で `cx_Freeze` のアップグレード（`pip install -q --upgrade freeze-core cx_Freeze`）が行われているため、最新版の利用が試みられています。誤検知が続く場合は、PyInstaller で生成した EXE を WiX Toolset などで MSI 化するフローへの移行を検討します。
