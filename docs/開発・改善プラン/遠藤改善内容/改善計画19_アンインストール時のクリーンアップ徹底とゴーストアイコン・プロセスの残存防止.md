# **改善計画19：アンインストール時のクリーンアップ徹底とゴーストアイコン・プロセスの残存防止 (改訂版 v4)**

## **1. 概要・目的**

アプリをアンインストールした際や終了した際に、バックグラウンドプロセス、システムトレイのアイコン（ゴーストアイコン）、およびスタートアップフォルダのショートカットが残存してしまう問題を解決します。

プログラム側で「終了・削除時に跡を残さない仕組み」を徹底することで、ユーザーが手動でタスクマネージャーからプロセスを終了させたり、エクスプローラーを再起動したりする手間をなくし、クリーンで安全なライフサイクル管理を実現します。

## **2. 現状の課題と解決アプローチ**

* **課題1：プロセスの残存によるアンインストール不全**
  WonderLinko.exe がバックグラウンドで動作したままアンインストールを実行すると、ファイルが使用中のため完全に削除されず、プロセスだけがシステムに残ってしまいます。
* **課題2：スタートアップショートカットの残留（ユーザーコンテキストの不一致）**
  `startup.py` によって動的に `%APPDATA%`（一般ユーザーのスタートアップフォルダ）内に作成された `.lnk` ショートカットは、MSIの標準アンインストール（SYSTEM権限で実行されることが多い）では別ユーザー領域とみなされ、削除されずに残ってしまいます。
* **課題3：システムトレイのゴーストアイコン現象**
  アプリのプロセスが強制終了されたり、終了処理が不完全だったりすると、Windowsの通知領域にアプリアイコンが残り続け、マウスオーバーするまで消えない「ゴーストアイコン」現象が発生します。

**解決策：**
運用補助のクリーンアップスクリプト（`uninstall.bat`）を同梱し、アンインストール運用をこれに一本化します。また、アプリコード（`app.py`）の終了処理をシグナル、`atexit`、さらに **Tkinterのウィンドウイベントフック** を併用して堅牢化し、トレイアイコンのリソースを通常終了経路で確実に解放します。

## **3. 具体的な実装仕様**

### **① トレイアイコンの明示的解放 (app.py) の堅牢化**

アプリの終了処理において、`pystray.Icon` のリソースおよび Tkinter ウィンドウのリソースを確実に解放してからプロセスを終了するように改修します。

* **終了フック (`atexit`)、シグナル (`signal`)、ウィンドウイベント (`WM_DELETE_WINDOW`) の併用:**
  正常終了 (`quit_app`) だけでなく、OSからのシャットダウン・タスクキル (`SIGTERM` や `WM_CLOSE` 要求) を受け取った際にも、確実にクリーンアップ処理が呼ばれるようにします。
  Python の `signal` ハンドラはメインスレッドで実行される制約があり、Tkinter のメインループがブロックしていると即座に処理されない可能性があるため、Tkinter のトップレベルウィンドウに対するイベントフック（`WM_DELETE_WINDOW`）でもクリーンアップ処理を呼び出せるように設計を調整します。

**（実装イメージ: app.py）**
```python
import atexit
import signal
import sys

def cleanup_resources():
    global _icon, _miniport_window
    # トレイアイコンの破棄
    if _icon is not None:
        try:
            _icon.stop()
        except Exception:
            pass
    # ミニポートウィンドウの破棄
    if _miniport_window is not None:
        try:
            _miniport_window.quit()
            _miniport_window.destroy()
        except Exception:
            pass

def on_closing():
    cleanup_resources()
    sys.exit(0)

# イベントハンドラの登録
atexit.register(cleanup_resources)
signal.signal(signal.SIGTERM, lambda sig, frame: on_closing())

# Tkinterウィンドウ生成時 (mini_port.py 側で設定、あるいは app.py から設定)
# _miniport_window.protocol("WM_DELETE_WINDOW", on_closing)
```

* **【補足】Windowsの強制終了とゴーストアイコンの仕様について:**
  Windows環境において、タスクマネージャーからの「タスクの終了」や `taskkill /f`（強制終了 API: `TerminateProcess`）が実行された場合、プロセスが即座に破棄されるため上記の終了フックは実行されません。この場合、Windowsの仕様上マウスオーバーするまでゴーストアイコンが残ることは避けられないため、強制終了時のゴースト化については仕様（許容事項）とします。

### **② アンインストール時のプロセス自動停止と確実な削除**

* **`uninstall.bat` の作成と同梱（当面の主軸対応）:**
  MSI標準の挙動だけに依存せず、運用で確実に削除できるよう、事前プロセス停止＋スタートアップ削除＋MSIサイレントアンインストールを順次行うバッチファイルを作成し、配布セットに含めます。

* **プロセス停止の二段構え実装（ゴーストアイコン防止）:**
  いきなり `taskkill /f` を行わず、まずは通常終了（`/f` なし: `WM_CLOSE` 送信）を試みて Tkinter イベントや `atexit` フックを走らせ、タイムアウト後に `/f` で強制終了させる実装とします。
* **MSIファイル非依存のサイレントアンインストール:**
  元の `.msi` ファイルが手元になくてもアンインストールできるよう、`wmic` を用いてプロダクト名から一意にアンインストールを実行します。

**（実装イメージ: scripts/uninstall.bat）**
```bat
@echo off
echo アプリを終了しています...
:: 通常終了要求（/f なし: WM_CLOSE を送信）
taskkill /im WonderLinko.exe >nul 2>&1
:: 3秒待機して atexit/Tkinterフック を走らせる
timeout /t 3 /nobreak >nul
:: 残っていれば強制終了
taskkill /f /im WonderLinko.exe >nul 2>&1

echo スタートアップのショートカットを削除しています...
:: ユーザーディレクトリを列挙して各プロファイルのショートカットを削除 (ワイルドカード制約回避)
FOR /D %%U IN ("C:\Users\*") DO (
    IF EXIST "%%U\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\Wonder Linko.lnk" (
        del /Q "%%U\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\Wonder Linko.lnk" >nul 2>&1
    )
)

echo アプリケーションをアンインストールしています...
:: wmic を使用してプロダクト名からサイレントアンインストールを実行
wmic product where "name='WonderLinkoDesktop'" call uninstall /nointeractive >nul 2>&1

echo アンインストールが完了しました。
pause
```

* **（運用上の注意）:**
  ユーザーが「Windowsの設定 > アプリ > インストールされているアプリ」から標準のアンインストールを実行してしまうと、このバッチは呼ばれません。社内配布時に「アンインストール時は必ず同封の `uninstall.bat` を管理者権限で実行してください」と周知する必要があります。

### **③ スタートアップショートカットの自動消去（全ユーザープロファイル走査）**

前項のバッチファイルで記述した通り、アプリ自身が作成したショートカットはアンインストール時に責任を持って削除します。
Windowsのコマンドプロンプトの制約上、`del` コマンドはパスの途中にワイルドカード (`*`) を含める構文をサポートしていません。この制約を回避し、複数ユーザーのプロファイルを確実にクリーンアップするため、`FOR /D` ループを使用して `C:\Users\*` をディレクトリ単位で走査し、ショートカットが存在する場合にのみ削除を実行します。

* **（将来検討事項）スタートアップ方式のレジストリ移行に関する留意点:**
  `.lnk` ファイルの生成ではなく、レジストリ `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` を用いたスタートアップ登録に切り替える案もありますが、アンインストーラーを SYSTEM 権限や別の管理者権限で実行した場合、**一般ユーザーの HKCU レジストリキーを消しに行くことが非常に困難**になるという懸念があります。
  現在の「ショートカットを配置する」方式は、バッチファイルから全ユーザーディレクトリを舐めて物理ファイルを強制削除できるため、運用上のクリーンアップが確実に行いやすいというメリットがあります。将来的な方式変更の際には、このトレードオフに留意します。

## **5. 検証および運用計画 (Verification & Operation Plan)**

### **ビルドと実装の確認**

1. **トレイアイコン・リソースの解放確認:**
   開発環境でアプリを起動し、トレイメニューから「終了」を選択した際、Windowsの通知領域からアイコンが即座に消滅し、ミニポートウィンドウも確実に閉じることを確認する。
   また、コマンドプロンプトから `taskkill /im WonderLinko.exe`（`/f`なし）を送信した際にも、Tkinter や signal フックが機能し、アイコンが消滅するか確認する。
2. **`uninstall.bat` の動作確認:**
   アプリを起動した状態で `uninstall.bat` を管理者権限で実行する。
   実行中にエラーや再起動要求が出ず、`WonderLinko.exe` のプロセスが終了し、MSIのアンインストールが完了することを確認する。

### **インストール・アンインストール後の状態確認（クリーンネス）**

1. **プロセスの完全終了:**
   `uninstall.bat` 完了後、タスクマネージャーに `WonderLinko.exe` が一切残っていないことを確認する。
2. **スタートアップの消去確認:**
   「Win + R」キーで `shell:startup` を開き、アンインストール完了後に「Wonder Linko」のショートカットが確実に削除されていることを確認する。複数ユーザー環境でテストし、別ユーザーのフォルダに残っていないかも確認する。
3. **次回起動への影響なし:**
   アンインストール後、PCを再起動してもショートカット起動エラー等のメッセージが表示されず、完全にアプリの痕跡が消えていることを確認する。
