# 改善計画19：アンインストール時のクリーンアップ徹底とゴーストアイコン・プロセスの残存防止 (改訂版 v2)

## 1. 概要・目的

アプリをアンインストールした際や終了した際に、バックグラウンドプロセス、システムトレイのアイコン（ゴーストアイコン）、およびスタートアップフォルダのショートカットが残存してしまう問題を解決します。

プログラム側で「終了・削除時に跡を残さない仕組み」を徹底することで、ユーザーが手動でタスクマネージャーからプロセスを終了させたり、エクスプローラーを再起動したりする手間をなくし、クリーンで安全なライフサイクル管理を実現します。

---

## 2. 現状の課題と解決アプローチ

- **課題1：プロセスの残存によるアンインストール不全**
  `WonderLinko.exe` がバックグラウンドで動作したままアンインストールを実行すると、ファイルが使用中のため完全に削除されず、プロセスだけがシステムに残ってしまいます。
- **課題2：スタートアップショートカットの残留（ユーザーコンテキストの不一致）**
  `startup.py` によって動的に `%APPDATA%`（一般ユーザーのスタートアップフォルダ）内に作成された `.lnk` ショートカットは、MSIの標準アンインストール（SYSTEM権限で実行されることが多い）では別ユーザー領域とみなされ、削除されずに残ってしまいます。
- **課題3：システムトレイのゴーストアイコン現象**
  アプリのプロセスが強制終了されたり、終了処理が不完全だったりすると、Windowsの通知領域にアプリアイコンが残り続け、マウスオーバーするまで消えない「ゴーストアイコン」現象が発生します。

- **解決策**：
  運用補助のクリーンアップスクリプト（`uninstall.bat`）を同梱し、アンインストール運用をこれに一本化します。また、アプリコード（`app.py`）の終了処理をシグナルやフックを利用して堅牢化し、トレイアイコンのリソースを通常終了経路で確実に解放します。

---

## 3. 具体的な実装仕様

### ① トレイアイコンの明示的解放 (`app.py`) の堅牢化

アプリの終了処理において、`pystray.Icon` のリソースおよび Tkinter ウィンドウのリソースを確実に解放してからプロセスを終了するように改修します。

- **終了フック (`atexit`) とシグナル (`signal`) の導入**:
  正常終了 (`quit_app`) だけでなく、OSからのシャットダウン・タスクキル (`SIGTERM`) 要求を受け取った際にも、確実にクリーンアップ処理が呼ばれるようにします。

  ```python
  import atexit
  import signal
  import sys

  def cleanup_resources():
      global _icon, _miniport_window
      # ミニポートウィンドウの破棄
      if _miniport_window is not None:
          try:
              _miniport_window.quit()
              _miniport_window.destroy()
          except Exception:
              pass
      # トレイアイコンの破棄
      if _icon is not None:
          try:
              _icon.stop()
          except Exception:
              pass

  atexit.register(cleanup_resources)
  signal.signal(signal.SIGTERM, lambda sig, frame: sys.exit(0))
  ```

- **【補足】Windowsの強制終了とゴーストアイコンの仕様について**:
  Windows環境において、タスクマネージャーからの「タスクの終了」や `taskkill /f`（強制終了 API: `TerminateProcess`）が実行された場合、プロセスが即座に破棄されるため上記の終了フックは実行されません。この場合、Windowsの仕様上マウスオーバーするまでゴーストアイコンが残ることは避けられないため、強制終了時のゴースト化については仕様（許容事項）とします。

### ② アンインストール時のプロセス自動停止と確実な削除

- **`uninstall.bat` の作成と同梱（当面の主軸対応）**:
  MSI標準の挙動だけに依存せず、運用で確実に削除できるよう、事前プロセス停止＋スタートアップ削除＋MSIサイレントアンインストールを順次行うバッチファイルを作成し、配布セットに含めます。
  
  **プロセス停止の二段構え実装（ゴーストアイコン防止）**:
  いきなり `taskkill /f` を行わず、まずは通常終了（`/f`なし）を試みて `atexit` フックを走らせ、タイムアウト後に `/f` で強制終了させる実装とします。

  ```bat
  @echo off
  echo アプリを終了しています...
  :: 通常終了要求（/f なし）
  taskkill /im WonderLinko.exe >nul 2>&1
  :: 3秒待機して atexit フックを走らせる
  timeout /t 3 /nobreak >nul
  :: 残っていれば強制終了
  taskkill /f /im WonderLinko.exe >nul 2>&1
  ```
  
- **（運用上の注意）**:
  ユーザーが「Windowsの設定 > アプリ > インストールされているアプリ」から標準のアンインストールを実行してしまうと、このバッチは呼ばれません。社内配布時に「アンインストール時は必ず同封の `uninstall.bat` を管理者権限で実行してください」と周知する必要があります。

- **（将来検討）MSI への CustomAction 埋め込み**:
  `cx_Freeze` によるMSI生成後、データベースを直接編集しアンインストール初期段階に CustomAction を埋め込む処理は、ビルド安定性の観点から難易度が高いため、将来的な高度な改善案と位置づけます。

### ③ スタートアップショートカットの自動消去（全ユーザープロファイル走査）

アプリ自身が作成したショートカットは、アンインストール時に責任を持って削除します。

- **全ユーザーディレクトリの走査**:
  `uninstall.bat` 内で、`C:\Users\*\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\Wonder Linko.lnk` をワイルドカードで走査して削除します。これにより、SYSTEM権限で実行された場合でも一般ユーザーのスタートアップファイルが残る問題を防ぎます。

  ```bat
  echo スタートアップのショートカットを削除しています...
  del /Q /S "C:\Users\*\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\Wonder Linko.lnk" >nul 2>&1
  ```
  
- **（将来検討事項）スタートアップ方式のレジストリ移行**:
  `.lnk` ファイルの生成ではなく、レジストリ `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` を用いたスタートアップ登録に切り替えることで、MSIの標準機能でのクリーンアップをより容易にする方針を検討します。

## 5. 検証および運用計画 (Verification & Operation Plan)

### ビルドと実装の確認

1. **トレイアイコン・リソースの解放確認**:
   開発環境でアプリを起動し、トレイメニューから「終了」を選択した際、Windowsの通知領域からアイコンが即座に消滅し、ミニポートウィンドウも確実に閉じることを確認する。
   また、`taskkill`（`/f`なし）を送信した際にもアイコンが消滅するか確認する。
2. **`uninstall.bat` の動作確認**:
   アプリを起動した状態で `uninstall.bat` を管理者権限で実行する。
   - 実行中にエラーや再起動要求が出ず、`WonderLinko.exe` のプロセスが終了し、MSIのアンインストールが完了することを確認する。

### インストール・アンインストール後の状態確認（クリーンネス）

1. **プロセスの完全終了**:
   `uninstall.bat` 完了後、タスクマネージャーに `WonderLinko.exe` が一切残っていないことを確認する。
2. **スタートアップの消去確認**:
   「Win + R」キーで `shell:startup` を開き、アンインストール完了後に「Wonder Linko」のショートカットが確実に削除されていることを確認する。複数ユーザー環境でテストし、別ユーザーのフォルダに残っていないかも確認する。
3. **次回起動への影響なし**:
   アンインストール後、PCを再起動してもショートカット起動エラー等のメッセージが表示されず、完全にアプリの痕跡が消えていることを確認する。
