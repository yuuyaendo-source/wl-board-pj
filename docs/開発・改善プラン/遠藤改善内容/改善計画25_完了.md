# 改善計画25：応援要請の仕様改善・削除制御・複数人アサインの可視化・通知UIの統合と最適化 完了報告書

**作成日:** 2026年10月6日

**対象システム:** Wonder Linko エコシステム全体（Board System, wl_desktop_app, wl-sticky-note）

**ステータス:** 完了

---

## 1. 概要・目的

本計画では、タスクの「応援要請」におけるライフサイクル（レーン移動・復帰・視覚的情報の保持）を明確化し、複数アサイン時の状態管理および削除制御を厳格化することで、業務の抜け漏れや誤操作を防止しました。
また、パーソナルボード上において同じタスクを持つ他担当者の進捗状態（対応中・完了）をリアルタイムに視覚可視化できるようにしました。
さらに、デスクトップアプリで重複・混在していた通知UI（OSネイティブトーストとアバター吹き出し）を「吹き出しウィンドウ」へ一本化し、ミニポート本体が非表示の状態であっても右下に一時ポップアップ表示される共通通知体験を構築しました。

---

## 2. 実施した改善内容の詳細

### ① 応援要請のレーン復帰と赤色表示の継承

* **DBスキーマ拡張とフラグ保持:**
* `sticky_notes` テーブルに `is_help_request`（Boolean）カラムを追加し、付箋自体が応援要請由来であることをDBレベルで保持可能にしました。

* **引き取り時の自動レーン復帰 (`sticky_notes.py`):**
* 他のユーザーが付箋をパーソナルボード（`move_to_personal`）やチーム（`copy_to_team`）へ引き取った際、要請者本人の配置が `HELP_REQUEST` レーンにある場合は自動的に `INBOX` レーンへ復帰・更新されるロジックを追加しました。

* **赤色表示の永続化 (`board_placements.py`, `boards.py`):**
* `is_help_request = True` の付箋は、引き取った担当者および要請者本人のパーソナルボード上でも、完了（`DONE`）するまで赤基調のハイライト表示（`cardColor="red"` / `is_help_request=True`）が維持されるよう改修しました。

### ② 複数人アサイン時の安全な削除制御

* **削除ブロック制御 (`board_placements.py`):**
* バックエンドの削除API（`DELETE /board_placements/{id}`）において、該当付箋に他の未完了パーソナル配置（`lane != Lane.DONE`）が存在するかチェックする安全制御を実装しました。

* 未完了の他担当者が存在する場合、`他の担当者（○○）が完了にするまで削除できません` という明確なメッセージとともに HTTP 400 エラーを返し、誤操作によるタスクステータスの矛盾発生をブロックします。

### ③ 複数人アサインの状況可視化と完了ステータスの共有

* **レスポンススキーマ拡張 (`board_placement.py`):**
* `TakenByUser` スキーマに `is_done: bool` フィールドを追加しました。

* **他担当者のリアルタイム共有 (`boards.py`):**
* パーソナルボード取得API（`GET /boards/personal`）およびタスクボード取得API（`GET /boards/task`）において、自分以外の担当者一覧（`taken_by`）を組み立てる際、各担当者のレーンが `DONE` であるかを判定して `is_done` フラグを設定・返却するようにしました。

* これにより、フロントエンド側で他担当者が完了した際にアバターバッジの色変化（グレーアウト＋チェックマーク✅）で直感的に進捗が把握できるようになりました。

### ④ 通知UIの「吹き出し」への一本化（ネイティブトースト廃止）

* **ネイティブトーストの廃止 (`notifications.py`):**
* `win10toast` などの OS ネイティブトースト呼び出しコードおよび不調時の自前トースト描画フォールバックを整理し、通知トリガーをすべて UI ディスパッチ経由でアバターの吹き出しモジュールへ移譲・一本化しました。

* **吹き出しの独立ポップアップ化 (`speech_bubble.py`):**
* `SpeechBubble` に `standalone=True` オプションを拡張しました。

* ミニポート本体がバックグラウンド（非表示）状態であっても、通知受信時にはミニポート本体を出現させることなく「吹き出しウィンドウ」のみを画面右下に独立表示・自動フェードアウトさせる処理を確立しました。

### ⑤ Alembic マイグレーションの追加と一貫性確保

* **リビジョンファイル追加 (`n4o5p6q7r8s9_add_is_help_request_to_sticky_notes.py`):**
* リビジョン `m3n4o5p6q7r8` から更新する形で、`sticky_notes` テーブルへの `is_help_request` カラム追加（`server_default=false`, `nullable=False`）を行うマイグレーションスクリプトを作成・配置しました。

## 4. 確認・検証結果

1. **応援要請のライフサイクル検証:**

* パーソナルボードで付箋を `HELP_REQUEST` レーンに置くと赤色に強調され、他のユーザーが引き取った段階で要請者の付箋が自動的に `INBOX` レーンへ戻り、完了するまで両者の画面で赤色が維持されることを確認しました。

1. **複数人アサインの可視化と削除制御検証:**

* 同一タスクを所有する他担当者がパーソナルボード上にアバターバッジで表示され、他担当者が `DONE` に移動するとバッジがグレーアウト＋チェックマークに変化することを確認しました。

* 未完了の他担当者が存在する状態でゴミ箱投入（削除）を試みた際、「他の担当者（○○）が完了にするまで削除できません」とブロックされることを確認しました。

1. **通知UI（吹き出し）の動作検証:**

* ミニポート本体を非表示にした状態で通知（新着・リマインド等）が発生した際、ミニポート本体は出現せず、画面右下に「吹き出し」のみがポップアップ表示され、指定秒数後に消えることを確認しました。
