# 改善計画20：アプリおよびボードシステムの不具合修正とパフォーマンス改善 完了報告

ご依頼いただいた「改善計画20：アプリおよびボードシステムの不具合修正とパフォーマンス改善」に基づく、報告された5件の課題への対策実装がすべて完了いたしました。

---

## 実施した変更の詳細

### 1. パーソナル投稿のタスク化防止（アイコン・振り分けの修正）
- **DBスキーマの拡張**: `sticky_notes` テーブルに `is_personal_only` フラグを追加し、パーソナルボードからの直接投稿であることを明示できるよう改修しました。
- **同期ガードの徹底**: 付箋サーバー（`server.js`）および Board System 側の取り込みAPIにおいてこのフラグを維持し、`process_new_note_ai` によるタスクボードへの意図しない自動登録をブロックしました。

### 2. ゴミ箱投入タスクの復活防止
- **バックエンド連動の実装**: `board_placements.py` において、パーソナルボード上でタスク由来の配置が削除（ゴミ箱へ移動）された際、タスクボード側の該当付箋のステータスを自動的に「完了（`matrix_quadrant = 5`）」へ更新する連動ロジックを実装しました。これにより、不要タスクが再び未アサイン状態として復活する現象を解決しました。

### 3. デスクトップアプリの通知問題の改善
- **フォールバックUIの提供**: Windowsの集中モードやポリシーによって `winotify` がブロックされた場合のエラーを捕捉し、フォーカスを奪わない `customtkinter` ベースのフローティングトースト（自前UI）をフォールバックとして表示する安全な仕組み (`notifications.py`) を実装しました。

### 4. 多重起動（トレイ・プロセス増殖）の防止
- **単一インスタンス制御の刷新**: 旧来のポートバインド方式から、Windowsの OS名前付き Mutex (`Local\WonderLinko.Desktop.SingleInstance`) を用いた排他制御に変更しました。
- **既存プロセスの前面化**: 重複起動された場合は即座に自プロセスを終了し、`show_request` ファイル経由で既存の常駐プロセスに対してミニポートの最前面表示を依頼するスマートな挙動へ改善しました。

### 5. 付箋のドラッグもたつき・パフォーマンス向上
- **DOM直接操作への移行**: 付箋ボードのフロントエンド（`StickyNote.js`）において、ドラッグ中は React の State を更新せず、`useRef` を用いて DOM の `transform` を直接書き換える実装へ最適化しました。これにより毎ピクセルの再レンダリングを防ぎ、ドラッグ終了時の一括同期と合わせ、操作のレスポンスが劇的に向上しました。

## 確認方法

1. **パーソナルボードとゴミ箱**: パーソナル投稿が Task に現れないこと、およびタスクをゴミ箱に入れた際に Task 側で完了（グレー）になることを確認してください。
2. **多重起動防止**: アプリを起動中に再度ショートカットを複数回実行し、トレイアイコンが増殖せずに既存のミニポートが前面へポップアップすることを確認してください。
3. **付箋のドラッグ操作**: タスクボードや付箋ボードで付箋を移動させる際、マウスカーソルに追従してカクつくことなく滑らかに移動することを確認してください。
