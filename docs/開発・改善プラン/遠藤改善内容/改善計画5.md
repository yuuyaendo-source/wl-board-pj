# 改善計画5：期限設定機能の追加とUI/UX改善プラン（最終版）

タスク管理の効率化と視認性の向上のため、タスクボードおよび付箋ボードへの「期限（Due Date）」設定機能の追加、ボード間の双方向同期、およびそれに伴う自動振り分けロジックの実装プランを提案します。

---

## Proposed Changes (変更提案)

### 1. タスクボードと付箋ボードへの期限設定・双方向同期機能の追加
タスクの期限を明示的に管理し、タスクボード（`board-system`）と付箋ボード（`wl-sticky-note`）の両者間で期限が常に同期されるよう、バックエンド・フロントエンドおよび付箋サーバーの処理・APIを拡張します。

#### ① Backend 修正 (`board-system/backend`)
*   **DBスキーマ・モデル:**
    *   既存のマイグレーション (`k1l2m3n4o5p6_add_due_date...` 等) およびモデル定義に合わせ、`due_date` はタイムゾーンのズレを防ぐため **`Date` 型 (`YYYY-MM-DD`)** として扱います。
*   **スキーマ・Routerの拡張 (`app/schemas/sticky_note.py`, `app/routers/sticky_notes.py`):**
    *   `StickyNoteCreate` スキーマに `due_date: Optional[date] = None` を追加。
    *   `POST /sticky_notes` および `POST /sticky_notes/create_personal` エンドポイントにて、新規作成時に `due_date` を DB に保存できるように修正。
    *   `CreatePersonalNoteBody` にも `due_date` を追加。新規パーソナル投稿時、`due_date` が「今日」の場合は初期 `lane` を自動的に `Lane.TODAY` とするロジックを組み込み。
    *   `SyncFromPostitBody` および `ImportFromPostitItem` スキーマに `due_date: Optional[str] = None` を追加。
    *   `import_from_postit`: 付箋ボードからの取り込み時に `due_date` もパースして DB に保存するよう拡張。
    *   `sync_from_postit`: 付箋ボード側からの追記・更新通知に `due_date` が含まれている場合、DB の `due_date` も更新し、日付変更時は `is_manually_moved_to_today` フラグをリセットした上で `apply_due_date_rules_for_note` を再実行。
    *   `_notify_postit_note` (旧 `_notify_postit_text`): タスクボード側で期限が変更された際、付箋ボード（`wl-sticky-note`）へ `dueDate` を同期通知できるように通知ペイロードを拡張。
    *   `PATCH /sticky_notes/{id}`: 期限が変更された際も付箋ボードへ通知が飛ぶように連動。
*   **ボードAPI拡張 (`app/routers/boards.py`):**
    *   `GET /boards/task`, `GET /boards/main`, `GET /boards/morning`, `GET /boards/personal` のレスポンスに `due_date` をマッピングして返却。

#### ② Frontend 修正 (`board-system/frontend`)
*   **型定義とAPIクライアントの拡張 (`lib/types.ts`, `lib/api.ts`):**
    *   `createPersonalNote` や `createStickyNote`, `importFromPostit` の引数・レスポンス型に `due_date?: string | null` を追加。
*   **UIコンポーネントの拡張 (`OneLineInput.tsx`, `NoteCard.tsx`):**
    *   `OneLineInput.tsx`: 1行入力の横にカレンダーアイコンを配置し、オプショナルで期限を選択できるポップオーバー形式のピッカーを追加。
    *   `NoteCard.tsx`: 既存インラインピッカー (`DueDatePicker`) のUI微調整および期限表示の強調。
*   **タスクボード取り込み処理 (`app/taskboard/page.tsx`):**
    *   付箋ボードからの取り込み処理 (`handleImportFromPostit`) において、取得した付箋データから `dueDate` を抽出して `importFromPostit` API に引き渡すよう修正。

#### ③ 付箋サーバー修正 (`wl-sticky-note/src/server.js`)
*   **`GET /api/boards/:id/notes` レスポンス拡張:**
    *   全件取得APIの出力項目に `dueDate: n.dueDate || n.due_date || null` を追加。
*   **`PATCH /api/boards/:id/notes/:noteId` 外部更新API拡張:**
    *   `board-system` 側から送信される `dueDate` / `due_date` を受け取り、付箋データへ反映して Socket.IO (`note-updated`) でリアルタイム同期する処理を追加。
*   **`socket.on('update-note')` イベント拡張:**
    *   付箋ボード上で付箋が更新された際、`board-system` の `/sticky_notes/sync_from_postit` へ `content` に加えて `due_date` も送信するよう連携。

### 2. Todayへの自動移動ロジック（期限連動）
設定したタスクが実行すべき日に確実に目に入るよう、自動振り分けを行います。

#### Backend 修正 (`app/routers/sticky_notes.py` または該当Service)
*   **期限設定・更新時の即時フック:**
    *   新規作成時または `PATCH` 更新時に `due_date` が設定・変更された場合、その日付が「今日（JST基準）」であるかを判定します。
    *   該当する場合、対象の Personal Board の `lane` を自動的に `TODAY` に更新します。
    *   既存の `daily_reset.py` 内の `apply_due_date_rules` との整合性を保ち、手動移動フラグ (`is_manually_moved_to_today`) のリセット等の共通ロジックを適用します。
    > [!NOTE]
    > **複数人引き取り時の挙動**
    > タスクボード由来の付箋を複数人が Personal Board に引き取っている場合、誰かが期限を「今日」に更新した際に「紐づく全ユーザーの Personal 配置の `lane` を `TODAY` に更新する」仕様を徹底します。

### 3. 期限の強調表示 (UI改善)
設定された期限をユーザーがパッと見て認識できるよう、カードのUIデザインを改善します。

#### Frontend 修正 (`NoteCard.tsx`)
*   **視認性の向上:**
    *   既存の `DueDateBadge` コンポーネントを改修し、フォントサイズを拡大、または太字 (`font-bold`) にしてメタデータ内で目立たせます。
*   **条件付きスタイリングの強化:**
    *   期限までの日数に応じた色分けを明確にします。
        *   **期限切れ:** 赤色（`bg-red-100 text-red-700` 等）で強烈に強調（太赤枠＋赤パルスバッジ ⚠️）
        *   **今日が期限:** オレンジ・アンバー色で強調（太オレンジ枠＋🔥 バッジ）
        *   **期限に余裕がある場合:** 通常のカラー（黄・青）

---

### 4. プロパティ名（`dueDate` vs `due_date`）の互換性設計
JavaScript側（CamelCase: `dueDate`）と Python/FastAPI側（SnakeCase: `due_date`）でのプロパティ名不一致によるバグを回避するため、通信・受け入れAPIでは常に以下の形でフォールバック解決を行います。

```javascript
// JavaScript / Node.js 側の例
const targetDueDate = dueDate !== undefined ? dueDate : due_date;
```

## Verification Plan (検証計画)

### Automated / API Tests
*   **新規作成・取り込みテスト:** `POST /sticky_notes`, `POST /sticky_notes/create_personal`, `POST /sticky_notes/import_from_postit` に `due_date` を含めた際、DBに正しく保存されること。
*   **双方向同期テスト:** 
    *   `board-system` 側で期限を変更した際、`wl-sticky-note` 側の付箋にも即座に期限が反映されること。
    *   `wl-sticky-note` 側で期限を設定・更新した際、`board-system` 側の付箋およびタスクボードへ期限が自動同期されること。
*   **ロジックテスト:** `due_date` を「今日」に設定して作成・更新した際、即座に `board_placements` の `lane` が `TODAY` へ変更されること（複数人引き取り時の全員分反映を含む）。

### Manual Verification
1.  **入力・表示確認:** タスクボード・パーソナルボード・付箋ボードにて、新規作成時および既存カード編集時にカレンダーピッカーから期限が設定でき、表示が強調（太字・サイズ大）されることを確認する。
2.  **取り込み・同期確認:** 付箋ボードで期限を設定した付箋をタスクボードで「取り込む」ボタンで取り込んだ際、期限が脱落せずに保持されていることを確認する。
3.  **自動移動確認:** 期限を「今日」に設定した瞬間に、パーソナルボードの該当付箋が即座に「Today」レーンへ移動することを確認する。
4.  **色分け・タイムゾーン確認:** 「期限切れ」「今日」「未来」の付箋が意図した色で表示されること。また、深夜0時をまたいだ際にフロントエンド・バックエンド間で日付のズレ（JST基準）が生じないことを確認する。
