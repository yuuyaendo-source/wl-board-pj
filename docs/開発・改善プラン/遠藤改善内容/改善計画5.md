# 改善指示書13：期限設定機能の追加とUI/UX改善プラン（最終版）

タスク管理の効率化と視認性の向上のため、タスクボードおよび付箋ボードへの「期限（Due Date）」設定機能の追加、およびそれに伴う自動振り分けロジックの実装プランを提案します。

## Proposed Changes (変更提案)

### 1. タスクボードと付箋ボードへの期限設定機能の追加
タスクの期限を明示的に管理できるようにするため、バックエンドおよびフロントエンドの入力インターフェースを拡張します。

#### Backend 修正
- **DBスキーマ・モデル:**
  - 既存のマイグレーション (`k1l2m3n4o5p6_add_due_date...` 等) およびモデル定義に合わせ、`due_date` はタイムゾーンのズレを防ぐため **`Date` 型 (`YYYY-MM-DD`)** として扱います。
- **スキーマ・Routerの拡張:**
  - `app/schemas/sticky_note.py`: `StickyNoteCreate` スキーマに `due_date: Optional[date] = None` を追加します。
  - `app/routers/sticky_notes.py`: 
    - `POST /sticky_notes` および `POST /sticky_notes/create_personal` エンドポイントにて、新規作成時に `due_date` を DB に保存できるように修正します。
    - **[Tips]** 同ファイル内の `CreatePersonalNoteBody` にも `due_date: Optional[date] = None`（または `str | None`）を追加します。また、新規パーソナル投稿時、`due_date` が「今日」の場合は初期 `lane`（デフォルト `INBOX`）を自動的に `Lane.TODAY` として作成するロジックを組み込みます。
  - `app/routers/boards.py`: `GET /boards/task` および `GET /boards/morning` エンドポイントのレスポンス生成において、`due_date` をマッピングしてフロントエンドに返すよう修正します。

#### Frontend 修正
- **型定義とAPIクライアントの拡張:**
  - `lib/types.ts`, `lib/api.ts`: バックエンドのスキーマ拡張に伴い、`createPersonalNote` や `createStickyNote` の引数およびAPIペイロードに `due_date?: string | null` を追加します。
- **UIコンポーネントの拡張:**
  - `board-system/frontend/app/components/OneLineInput.tsx`: 1行入力の横にカレンダーアイコンを配置し、オプショナルで期限を選択できるポップオーバー形式のピッカーを追加します。
  - `NoteCard.tsx` の既存インラインピッカー (`DueDatePicker`) のUI微調整を行います。
  - ※付箋ボード (`wl-sticky-note`) 側の同期仕様については別途スコープを定義し、今回は `board-system` 側を主軸とします。

### 2. Todayへの自動移動ロジック（期限連動）
設定したタスクが実行すべき日に確実に目に入るよう、自動振り分けを行います。

#### Backend 修正 (`app/routers/sticky_notes.py` または該当Service)
- **期限設定・更新時の即時フック:**
  - 新規作成時または `PATCH` 更新時に `due_date` が設定・変更された場合、その日付が「今日（JST基準）」であるかを判定します。
  - 該当する場合、対象の Personal Board の `lane` を自動的に `TODAY` に更新します。
  - 既存の `daily_reset.py` 内の `apply_due_date_rules` との整合性を保ち、手動移動フラグ (`is_manually_moved_to_today`) のリセット等の共通ロジックを適用します。
  - **[Tips]** タスクボード由来の付箋を複数人が Personal Board に引き取っている場合、誰かが期限を「今日」に更新した際に「紐づく全ユーザーの Personal 配置の `lane` を `TODAY` に更新する」仕様になる点に留意して実装を行います。

### 3. 期限の強調表示 (UI改善)
設定された期限をユーザーがパッと見て認識できるよう、カードのUIデザインを改善します。

#### Frontend 修正 (`NoteCard.tsx`)
- **視認性の向上:**
  - 既存の `DueDateBadge` コンポーネントを改修し、フォントサイズを拡大、または太字 (`font-bold`) にしてメタデータ内で目立たせます。
- **条件付きスタイリングの強化:**
  - 期限までの日数に応じた色分けを明確にします。
    - **期限切れ:** 赤色（`bg-red-100 text-red-700` 等）で強く強調
    - **今日が期限:** オレンジ・アンバー色で強調
    - **期限に余裕がある場合:** 通常の控えめなカラー

## Verification Plan (検証計画)

### Automated Tests
- **APIテスト:** 新規作成API (`POST /sticky_notes`, `POST /sticky_notes/create_personal`) に `due_date` を含めた際、DBに正しく保存されること。
- **ロジックテスト:** `due_date` を「今日」に設定して作成・更新した際、即座に `board_placements` の `lane` が `TODAY` へ変更されること（複数人引き取り時の挙動含む）。

### Manual Verification
1. **入力・表示確認:** タスクボード・パーソナルボードにて、新規作成時および既存カード編集時にカレンダーピッカーから期限が設定でき、表示が強調（太字・サイズ大）されることを確認する。
2. **自動移動確認:** 期限を「今日」に設定した瞬間に、パーソナルボードの該当付箋が即座に「Today」レーンへ移動することを確認する。
3. **色分け・タイムゾーン確認:** 「期限切れ」「今日」「未来」の付箋が意図した色で表示されること。また、深夜0時をまたいだ際にフロントエンド・バックエンド間で日付のズレ（JST基準）が生じないことを確認する。
