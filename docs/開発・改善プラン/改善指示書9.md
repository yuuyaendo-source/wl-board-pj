Board System Implementation Guide (Wonder Rinko)
1. Project Overview
本プロジェクトは、オフィスの情報感度を高め、行動を促すための「AI付箋ボードシステム」を構築する。 ユーザーの思考を中断させない「ワンクリック・オペレーション」と、AIによる「自動整理（ゴミ拾い・仕分け）」を核とする。

2. Core Features (The 4 Boards)
システムは以下の4つのボード（View）で構成される。データの実体は一つだが、ステータスやタグによって表示場所が変わるアーキテクチャとする。

A. Main Board (The Sandbox)
役割: 全員が見る「広場」。アイデア、雑談、依頼の投げ込み先。

挙動:

ユーザーは迷ったらここに投稿する。

AI (Rinko): 投稿内容を解析し、タスク性があれば「Task Board」へ、特定個人への依頼なら「Personal Board」へ自動でコピー/リンクを作成する。

B. Task Board (The Matrix)
役割: 組織全体のタスク地図。

View: アイゼンハワー・マトリクス（緊急度 × 重要度） の4象限表示。

AI (Rinko):

Main Boardから来たタスクを、LLMが判定した「緊急度(0-100)」「重要度(0-100)」のスコアに基づき、自動的に座標(x, y)に配置する。

ユーザーはD&Dで位置を修正可能。

C. Personal Board (My Cockpit)
役割: 個人の作業台。

View: シンプルな3レーン（カンバン方式）。

Inbox: 他人からの依頼、Mainからのアサイン待ち。

Today: 今日やると決めたもの（最大5件推奨）。

Done: 完了。

Feature:

Morning Check-in: 毎朝、前日の残タスクを「今日やる」か「Task Boardに戻す（リリース）」か選択させるダイアログを表示。

D. Morning Meeting Board (The Stage)
役割: 朝会の進行台本。

View: 全参加者の「Today」レーンにあるタスクを一覧表示。

Sync: 毎朝8:50（設定時刻）に、各メンバーのPersonal Boardの状態をスナップショットとして表示する。

3. Data Architecture (Schema Plan)
Cursorは以下のER図（概念）に基づいてモデルを作成すること。

Tables
users

id, name, role, interest_vector (embedding)

sticky_notes

id, content, author_id

status: 'DRAFT', 'ACTIVE', 'DONE', 'ARCHIVED'

created_at, updated_at

board_placements (付箋がどのボードのどこにあるかを管理)

note_id (FK)

board_type: 'MAIN', 'TASK', 'PERSONAL', 'MORNING'

owner_id: (Personal Boardの場合の所有者)

lane: 'INBOX', 'TODAY', 'DONE' (Personal用)

position_x, position_y (Task Board用 0-100)

matrix_quadrant: 1, 2, 3, 4 (キャッシュ用)

4. AI Logic (Rinko Core)
Backend (Python) で実装すべきAI処理の要件。

Logic 1: Auto-Triage (自動仕分け)
Trigger: Main Boardに新規投稿された時。

Prompt:

「この投稿は『タスク（作業）』か『情報の共有』か？」

「タスクの場合、担当者は明記されているか？」

Action:

タスク → Task Board に配置。

特定の担当者あり → その人の Personal Board (Inbox) にも配置。

Logic 2: Matrix Scoring (マトリクス配置)
Trigger: Task Board に配置される時。

Prompt:

「以下のタスクの『緊急度』と『重要度』を0-100で採点せよ」

Action:

返却されたスコアを position_x, position_y に保存。

Logic 3: Daily Reset (日次リセット)
Trigger: 毎朝の初回アクセス時 or バッチ処理。

Action:

Personal Boardの Today にある未完了タスクを特定。

ユーザーへの問いかけを生成。「昨日の『〇〇』は持ち越しますか？」

5. UI/UX Guidelines
Framework: Next.js (App Router), Tailwind CSS, Framer Motion (D&D用).

Design Philosophy:

Drag & Drop First: 状態遷移はすべてD&Dで行えること。

Minimal Input: 入力フォームは1行（LINE風）。詳細は後から編集。

Visual Feedback: AIが動いた形跡（自動配置など）は、"✨" アイコンや色で明示する（ユーザーに「勝手に動いた」と思わせないため）。

6. Implementation Steps for Cursor
Step 1: Database Setup

SQLite/PostgreSQLでのモデル定義 (SQLAlchemy/Prisma)。

Step 2: Backend API (FastAPI)

CRUD操作と、ボード間の移動ロジック（move_to_personal, release_to_task_board）の実装。

Step 3: AI Worker

Gemini APIを用いた「自動仕分け」「スコアリング」関数の実装。

Step 4: Frontend (Boards)

4つのビューのコンポーネント実装。まずは「Personal Board」の3レーンから着手。
