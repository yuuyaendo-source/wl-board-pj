# 改善指示書9 開発プラン（Board System / Wonder Rinko）

改善指示書9に基づく実装の開発プラン。**DB作成から順に進める**想定でフェーズ分けしている。

---

## 1. 全体像とスタック

| 層 | 技術 | 備考 |
|----|------|------|
| DB | SQLite（開発）→ PostgreSQL（本番可） | SQLAlchemy で共通化 |
| Backend API | FastAPI (Python) | CRUD・ボード間移動・AI連携の窓口 |
| AI Worker | Python + Gemini API | 自動仕分け・マトリクススコア・日次リセット |
| Frontend | Next.js (App Router), Tailwind, Framer Motion | 4ボードView・D&D |

既存の **02_1_sticky-note**（Next.js + Express + JSON）は、段階的に DB + FastAPI を併用するか、新規「Board System」として別ディレクトリで立ち上げるかを選択可能。本プランは **DB を軸にした新規バックエンド** を前提に記載する。

---

## 2. フェーズ1: データベース設計・作成

**目的**: 指示書9のスキーマを実装し、マイグレーションと初期データで運用可能にする。

### 2.1 成果物

- プロジェクト: 例）`02_1_sticky-note/backend` または 新規 `board-system/` の `backend/`
- 以下を配置:
  - モデル定義（SQLAlchemy）
  - マイグレーション（Alembic または 手動 SQL）
  - 接続設定（SQLite 開発用・本番は PostgreSQL 対応可）

#### 2.2.3 `board_placements`

付箋が「どのボードのどこにあるか」を管理。1付箋が複数ボードに現れる場合は複数行（コピー/リンクは実装方針で決定）。

| カラム | 型 | 説明 |
|--------|-----|------|
| id | PK | |
| note_id | FK → sticky_notes.id | 付箋 |
| board_type | VARCHAR(32) | 'MAIN', 'TASK', 'PERSONAL', 'MORNING' |
| owner_id | FK → users.id, NULL可 | Personal Board の所有者（他ボードは NULL） |
| lane | VARCHAR(32), NULL可 | Personal用: 'INBOX', 'TODAY', 'DONE' |
| position_x | FLOAT, NULL可 | Task Board 用 (0–100) |
| position_y | FLOAT, NULL可 | Task Board 用 (0–100) |
| matrix_quadrant | INT, NULL可 | 1–4（キャッシュ用） |
| sort_order | INT, デフォルト0 | 同一レーン内の並び |
| created_at | TIMESTAMP | |
| updated_at | TIMESTAMP | |

- 一意制約: `(note_id, board_type, owner_id)` の組み合わせでユニーク（Personal は owner ごと、他は owner_id NULL で1件想定）。

## 3. フェーズ2: Backend API（FastAPI）

**目的**: 4ボード用の CRUD と、ボード間移動（move_to_personal, release_to_task_board）を API で提供する。

### 3.1 主なエンドポイント案

- `GET/POST /users`（必要に応じて）
- `GET/POST /sticky_notes`
- `GET/PATCH/DELETE /sticky_notes/{id}`
- `GET/POST/PATCH /board_placements`（フィルタ: board_type, owner_id）
- `POST /sticky_notes/{id}/move_to_personal`（body: owner_id, lane）
- `POST /sticky_notes/{id}/release_to_task_board`（Task Board に戻す）
- `GET /boards/main`, `GET /boards/task`, `GET /boards/personal?owner_id=`, `GET /boards/morning`（View 用の集約 API でも可）

### 3.2 タスク一覧（フェーズ2）

| # | タスク | 詳細 |
|---|--------|------|
| 2.1 | FastAPI プロジェクト化 | backend に FastAPI アプリ、CORS、ルーター構成 |
| 2.2 | CRUD: users | 必要最小限（取得・作成） |
| 2.3 | CRUD: sticky_notes | 作成時に board_placements の MAIN 1件も作成する等、方針を決めて実装 |
| 2.4 | CRUD: board_placements | 一覧（board_type/owner_id フィルタ）、更新（lane, position_x/y） |
| 2.5 | ボード間移動 API | move_to_personal, release_to_task_board のロジック実装 |
| 2.6 | 認証（任意・後回し可） | とりあえず owner_id を body/query で渡す形でも可 |

## 4. フェーズ3: AI Worker（Rinko Core）

**目的**: Gemini を用いた「自動仕分け」「マトリクススコア」「日次リセット」を実装する。

### 4.1 タスク一覧（フェーズ3）

| # | タスク | 詳細 |
|---|--------|------|
| 3.1 | Logic 1: Auto-Triage | Main Board 新規投稿をフックし、「タスクか情報か」「担当者明記か」を LLM で判定。Task/Personal に board_placements 作成 |
| 3.2 | Logic 2: Matrix Scoring | Task Board に載せる際、LLM で緊急度・重要度 0–100 を返し、position_x/y に保存（matrix_quadrant は算出してキャッシュ） |
| 3.3 | Logic 3: Daily Reset | 毎朝 or 初回アクセス時に、Personal の Today 未完了を検出し、「持ち越すか」問いかけ用のメッセージ生成（API またはバッチ） |
| 3.4 | トリガー設計 | Main 投稿時は FastAPI 内で同期的に呼ぶか、キュー＋ワーカーにするか方針決定 |

## 5. フェーズ4: Frontend（4 Boards）

**目的**: Next.js (App Router) で 4 種類の View を実装し、D&D と最小入力で操作できるようにする。

### 5.1 タスク一覧（フェーズ4）

| # | タスク | 詳細 |
|---|--------|------|
| 4.1 | Personal Board | 3レーン（Inbox / Today / Done）、D&D、1行入力。既存 02_1 の UI を流用・拡張するか新規コンポーネントか決定 |
| 4.2 | Main Board | 広場 View、投稿は1行。AI が動いた付箋に ✨ 等のフィードバック表示 |
| 4.3 | Task Board | 4象限（アイゼンハワー）、position_x/y に基づく配置、D&D で座標更新 |
| 4.4 | Morning Meeting Board | 参加者の Today スナップショット一覧、8:50 同期の仕様（API の時刻トリガー or フロントの時刻表示）を確定 |
| 4.5 | 共通 | Tailwind, Framer Motion、既存デザインとの統一感 |

## 6. 進め方の推奨（DB から始める流れ）

1. **フェーズ1 のみ先行**
   - 上記 2.3 の 1.1〜1.6 を実施。
   - 「DB 作成〜マイグレーション〜1件 CRUD 確認」までを完了させる。

2. **配置場所の選択**
   - **A)** 既存 `02_1_sticky-note` に `backend/` を追加し、既存 Express と並行（または徐々に API を FastAPI に移行）。
   - **B)** 新規リポジトリ/ディレクトリ `board-system` を切り、DB + FastAPI をそこに実装。Frontend は 02_1 をコピーして 4 ボード用に改修。

3. **次のステップ**
   - フェーズ1 完了後、フェーズ2 の 2.1〜2.4 で FastAPI の CRUD を実装。
   - その後、2.5（ボード間移動）→ 3（AI）→ 4（Frontend）の順で拡張。
