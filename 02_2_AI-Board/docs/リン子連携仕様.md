# リン子連携仕様

AI-Board における「リン子さん」のコメント・発声がいつ・どのように行われるかを整理した仕様です。

---

## 1. Sticky-note に投稿されたら → AI-Board に連携し、リン子がコメントする

| 項目 | 内容 |
|------|------|
| **トリガー** | ユーザーが **付箋ボード（Sticky-note）** に付箋を追加したとき |
| **経路** | (1) ブラウザで「付箋を追加」→ Socket.IO `add-note` がサーバへ送信される<br>(2) 外部から **POST /api/sticky_notes** で付箋が追加されたとき |
| **連携** | 付箋ボード（02_1_sticky-note）のサーバが、対象ボードが連携対象（例: `wl`）かつ author が `AI` 以外の場合に **AI-Board の POST /api/receive_note** を呼ぶ（`AI_BOARD_URL` 必須） |
| **リン子の動作** | AI-Board 側で付箋の **テキスト** から Gemini でコメントを生成 → VOICEVOX で音声合成 → **Socket.IO `ai_comment`** でフロントに配信。画面上にコメント表示＋音声再生。 |
| **実装** | 付箋ボード: `02_1_sticky-note/src/server.js`（add-note / POST /api/sticky_notes）<br>AI-Board: `src/webapp/app.py` の `receive_note()` → `generate_comment_from_text()` → `socketio.emit('ai_comment', …)` |

---

## 2. リアル付箋が貼られたら → リン子がコメントする

| 項目 | 内容 |
|------|------|
| **トリガー** | **カメラでリアル（物理）付箋** が検知され、その付箋が付箋ボードに送信されたとき |
| **経路** | (1) **付箋検知（sticky_note_detector.py）** が画像から付箋を検出・OCR してテキストを取得<br>(2) 検知結果を **付箋ボードの POST /api/sticky_notes** に送信（author: `Real Cam`）<br>(3) 付箋ボードがその付箋を保存し、**AI-Board の POST /api/receive_note** を呼ぶ |
| **リン子の動作** | 上記 1 と同様。付箋の **テキスト**（OCR 結果）でコメント生成 → 音声合成 → **`ai_comment`** で表示・発声。 |
| **補足** | 画像を AI-Board の **POST /api/upload** で直接アップロードする経路もある（レガシー・デバッグ用）。その場合は画像から `generate_comment(filepath)` でコメント生成し、同様に `ai_comment` で配信。 |

---

## 3. AI-Board 上の付箋同士の合体 → リン子が生成アイデアのタイトルをコメント表示・発声する

| 項目 | 内容 |
|------|------|
| **トリガー** | AI-Board の **ピン留めエリア** で、2 枚の付箋を重ねて「合体」させたとき |
| **経路** | フロントが **POST /api/generate_idea_from_notes**（textA / textB）を呼ぶ → Gemini で 2 テキストから新アイデア（title + description）を生成 |
| **リン子の動作** | (1) 生成したアイデア付箋を付箋ボード（POST /api/sticky_notes）に送信<br>(2) **アイデアのタイトル（idea_title）** を VOICEVOX で音声化<br>(3) **Socket.IO `ai_comment`** で `comment: idea_title` と `audio_url` を配信 → 画面上にタイトルをコメント表示し、音声で読み上げる |
| **実装** | AI-Board: `src/webapp/app.py` の `api_generate_idea_from_notes()` 内の `speak_idea()` → `socketio.emit('ai_comment', {'comment': idea_title, 'audio_url': ...})` |

---

## まとめ

| トリガー | コメント内容 | 表示・発声 |
|----------|--------------|------------|
| Sticky-note に付箋投稿 | 付箋テキストに対するリン子のコメント（Gemini 生成） | `ai_comment` で表示＋音声 |
| リアル付箋をカメラ検知 | 同上（OCR テキストに対するコメント） | 同上 |
| 付箋 2 枚を合体（アイデア生成） | 生成されたアイデアの **タイトル** | `ai_comment` でタイトル表示＋タイトルを読み上げ |

いずれも **AI-Board のフロント** が Socket.IO の **`ai_comment`** を受信し、コメント欄に表示し、`audio_url` があれば音声を再生します。

---

## コメント機能が動作しないときの切り分け

以下が考えられる原因です。上から順に確認すると原因を絞り込みやすくなります。

### 付箋ボード（Sticky-note）側

| 原因 | 確認方法・対処 |
|------|----------------|
| **AI_BOARD_URL が未設定・誤り** | 付箋ボードの `02_1_sticky-note/src/.env` に **`AI_BOARD_URL`** があるか。本番なら `http://wl-ai-board.local` など、AI-Board に実際に届く URL になっているか。変更後は **PM2 再起動**（`pm2 restart wl-sticky-note --update-env`）が必要。 |
| **HTTPS 自己証明書で fetch が失敗** | AI-Board が HTTPS かつ自己署名証明書の場合、付箋ボードの .env に **`AI_BOARD_INSECURE_SSL=1`** がないと Node の fetch が証明書エラーで失敗する。設定してから再起動。 |
| **連携対象ボードではない** | 付箋を追加しているボード ID が **`AI_BOARD_LINK_BOARD_IDS`** に含まれているか（未設定時は `wl` のみ）。別ボードに投稿していると receive_note は呼ばれない。 |
| **author が AI** | AI が生成した付箋は意図的に通知対象外。それ以外の付箋で試す。 |

### AI-Board サーバー側

| 原因 | 確認方法・対処 |
|------|----------------|
| **receive_note に届いていない** | 付箋を追加したあと、AI-Board の **コンソール／ターミナル** に `Received note from Web App: …` が出ているか。出ていなければ付箋ボード→AI-Board のリクエストが失敗している（URL・ネットワーク・SSL）。 |
| **GEMINI_API_KEY が未設定** | AI-Board の `.env` に **`GEMINI_API_KEY`**（または `GOOGLE_API_KEY`）があるか。未設定だと `generate_comment_from_text` が動かず、コメントは「ふむ、いい付箋ですね。」のフォールバックになるか失敗する。 |
| **Gemini API エラー** | ターミナルに `generate_and_notify error: …` や Gemini 関連の例外が出ていないか。API キー無効・クォータ・ネットワークを確認。 |
| **レート制限** | 同じ付箋 ID に対して **10 秒以内** に連続でコメントしない仕様。連続で試していると 2 回目以降はスキップされる。ログに `Skipping comment for note … (rate limited)` が出る。 |
| **VOICEVOX 未起動** | 音声だけ出ない場合、**VOICEVOX** が起動しているか。未起動だとログに「音声未生成」と出るが、**コメント表示は行われる**（`ai_comment` は必ず emit される）。 |

### AI-Board フロント（表示）側

| 原因 | 確認方法・対処 |
|------|----------------|
| **AI-Board の画面を開いていない** | コメント・音声は **AI-Board のブラウザタブ** に Socket.IO で届く。**AI-Board のページ（例: http://wl-ai-board.local や :5000）を開いたタブ** がなければ表示・再生されない。 |
| **Socket.IO 未接続** | ブラウザの **F12 → コンソール** で `connect_error` や切断メッセージが出ていないか。同じオリジン・ポートで開いているか、プロキシ設定を確認。 |
| **ai_comment のハンドラでエラー** | コンソールに `ai_comment handler error: …` が出ていないか。出ていればフロントの JS で例外が起きている。 |

### 確認の順序（推奨）

1. **付箋を 1 枚追加** → AI-Board を起動している **ターミナル** に `Received note from Web App:` が出るか。  
   - 出ない → 付箋ボードの `AI_BOARD_URL`・ネットワーク・SSL を確認。  
   - 出る → 2 へ。
2. 同じターミナルに **`AI Comment (from text): …`** が出るか。  
   - 出ない → Gemini API キー・エラーログを確認。  
   - 出る → 3 へ。
3. **AI-Board の画面を開いたブラウザ** でコメント欄に表示されるか。  
   - 出ない → Socket.IO 接続・コンソールエラーを確認。  
   - 出るが音声だけ出ない → VOICEVOX の起動を確認。
