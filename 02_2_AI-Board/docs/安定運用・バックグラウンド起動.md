# AI-Board の安定運用・バックグラウンド起動

作業用PCで AI-Board を動かす際の「PowerShell を閉じると止まる」「落ちてしまう」問題への対応方針です。

---

## 1. PowerShell を閉じても止まらないようにする

### 方法A: バックグラウンド起動スクリプト（推奨・手軽）

プロジェクトルート（`02_2_AI-Board`）で次を実行します。

```powershell
cd 02_2_AI-Board
.\start_server_background.ps1
```

- **効果**: サーバーが別プロセスとして起動するため、**この PowerShell を閉じてもサーバーは動き続けます**。
- ログは `logs\server_YYYYMMDD_HHMMSS.log` に出力されます。
- PID は `logs\server.pid` に保存されます。

**停止するとき**

```powershell
.\stop_server_background.ps1
```

PID ファイルがない場合は、スクリプト内の案内に従って「ポート 5000 のプロセスを終了」を選ぶか、タスクマネージャーで「python」を終了してください。

**付箋検知（sticky_note_detector）も使う場合**

- 付箋検知はウィンドウ（プレビュー・スライダー）が必要なため、**別の PowerShell またはコマンドプロンプト**で `.\start_detector.ps1` を実行してください。
- そのウィンドウを閉じると付箋検知は止まります。付箋検知だけ常駐させたい場合は「方法C: タスクスケジューラ」で「ログオン時」に別タスクとして登録する方法があります。

---

### 方法B: Windows サービス化（NSSM）

常時稼働・PC再起動後も自動起動したい場合に有効です。

1. **NSSM を入手**
   - [NSSM - Non-Sucking Service Manager](https://nssm.cc/download) からダウンロードし、例: `C:\nssm\nssm.exe` に配置。

2. **サービス登録（管理者 PowerShell）**

   ```powershell
   cd C:\Users\hisas\Documents\dev\wlinko-pj\02_2_AI-Board
   $pythonExe = (Resolve-Path ".venv\Scripts\python.exe").Path
   $workDir = (Resolve-Path "src\webapp").Path
   $appPy = Join-Path $workDir "app.py"

   C:\nssm\nssm.exe install "AI-Board" $pythonExe $appPy
   C:\nssm\nssm.exe set "AI-Board" AppDirectory $workDir
   C:\nssm\nssm.exe set "AI-Board" AppStdout (Join-Path $PWD "logs\service_stdout.log")
   C:\nssm\nssm.exe set "AI-Board" AppStderr (Join-Path $PWD "logs\service_stderr.log")
   C:\nssm\nssm.exe set "AI-Board" AppRotateFiles 1
   ```

3. **起動・停止**

   ```powershell
   Start-Service "AI-Board"
   Stop-Service "AI-Board"
   ```

4. **削除**

   ```powershell
   C:\nssm\nssm.exe remove "AI-Board" confirm
   ```

NSSM は「クラッシュ時に再起動」などの設定も可能です（NSSM の GUI: `nssm.exe edit AI-Board`）。

---

### 方法C: タスクスケジューラで「ログオン時」に起動

- 電源投入やログオン後に自動でサーバーを立ち上げたい場合に使います。
- 「タスクの作成」で以下を目安に設定します。
  - **トリガー**: ユーザーのログオン時
  - **操作**: プログラムの開始
    - プログラム: `02_2_AI-Board\.venv\Scripts\python.exe`
    - 引数: `app.py`
    - 開始: `02_2_AI-Board\src\webapp`
  - 「最上位の特権で実行」は不要ならオフでよいです。
- これでログオン時にバックグラウンドでサーバーが起動し、PowerShell に依存しません。

## 2. 安定動作（落ちないようにする）のポイント

### 2.1 想定される落ちる要因

| 要因 | 対策の例 |
|------|----------|
| **RTSP／カメラのタイムアウト** | README の「Stream timeout」のとおり、環境によっては 30 秒程度で切れることがあります。カメラやネットワークの状態を確認し、必要なら RTSP の再接続処理の見直し。 |
| **Gemini API のレート制限・エラー** | 短時間に大量リクエストを送らない、エラー時はリトライやログを確認。 |
| **VOICEVOX 未起動** | 音声を使う場合は VOICEVOX を先に起動。未起動でもコメントは表示されるが、ログに「音声未生成」が出ます。 |
| **メモリ不足** | 付箋検知＋Flask＋ブラウザを同時に動かすと負荷が高い場合、付箋検知の解像度やフレーム間隔の調整を検討。 |
| **未処理の例外** | ログ（`logs\` またはコンソール）でスタックトレースを確認し、該当箇所の例外ハンドリングを強化。 |

### 2.2 ログの確認

- **バックグラウンド起動時**: `logs\server_*.log` を開くか、PowerShell で  
  `Get-Content .\logs\server_YYYYMMDD_HHMMSS.log -Wait -Tail 30`  
  で末尾をリアルタイム表示。
- **サービス化（NSSM）時**: `logs\service_stdout.log` / `service_stderr.log` を確認。

### 2.3 落ちたときに自動で再起動したい場合

- **NSSM**: 上記「方法B」でサービス化し、NSSM の「Exit actions」で「Restart application」を設定すると、プロセス終了時に再起動されます。
- **バックグラウンドスクリプトのみ**: 自動再起動は含まれていません。必要ならタスクスケジューラで「1 分ごと」に「ポート 5000 が Listen していなければ start_server_background.ps1 を実行」するようなタスクを組むか、NSSM の利用を検討してください。

## 3. 運用の目安

| 運用スタイル | おすすめ |
|--------------|----------|
| 開発・手元で試す | 通常の `.\start_server.ps1` で十分。止めたくなったら Ctrl+C。 |
| 作業中は常時起動したいが、PowerShell は閉じたい | **方法A: start_server_background.ps1** |
| PC 再起動後も自動でサーバーを立ち上げたい | **方法B: NSSM** または **方法C: タスクスケジューラ** |
| 落ちても自動で立ち上げ直したい | **方法B: NSSM** で再起動オプションを設定 |

## 4. 遠隔から https://&lt;IP&gt; でアクセスできないとき

| 確認項目 | 対処 |
|----------|------|
| **URL にポートを付けたか** | サーバー直アクセス時は **ポート 5000**（例: `http://wl-ai-board.local:5000`）。本番で Nginx 等のリバースプロキシを使う場合は **http://wl-ai-board.local** でポートなしアクセス可能。 |
| **Windows ファイアウォール** | 他PCから接続する場合は、**このPC（サーバーを動かしている方）** でポート 5000 の受信を許可する必要があります。プロジェクトルート（wlinko-pj）で **管理者として PowerShell** を開き、`.\scripts\allow_firewall_port_5000.ps1` を実行してください。 |
| **サーバーが動いているか** | バックグラウンド起動後、タスクマネージャーで「python」プロセスがあるか確認。なければ `02_2_AI-Board\logs\` の直近の stderr ログを開き、起動エラー（証明書・モジュール不足など）が出ていないか確認してください。 |
| **自己署名証明書の警告** | HTTPS は自己署名のため、ブラウザで「接続はプライベートではありません」と出たら「詳細」→「〜へ移動」で進めてください。 |

---

## 5. 本番で wl-ai-board.local を使う場合（サーバー移動後）

AI-Board を専用サーバーまたは別PCで動かし、**http://wl-ai-board.local** でアクセスする構成にする場合のポイントです。

- **名前解決**: 利用する各PCの **hosts** に `（AI-Board サーバーのIP） wl-ai-board.local` を追加するか、DNS で `wl-ai-board.local` をその IP に解決させる。
- **ポート**: AI-Board はポート 5000 で待ち受ける。**リバースプロキシ（Nginx 等）** で 80/443 を 5000 に振る場合は、`http://wl-ai-board.local` でポートなしアクセス可能。プロキシを使わない場合は `http://wl-ai-board.local:5000` でアクセスする。
- **付箋ボード・Desktop**: 付箋ボードの `AI_BOARD_URL` と Desktop の `ai_board_url` を **`http://wl-ai-board.local`**（プロキシ利用時）または **`http://wl-ai-board.local:5000`** に設定する。

以上を組み合わせて、作業用PCでも安定して AI-Board を動かせるようにしてください。
