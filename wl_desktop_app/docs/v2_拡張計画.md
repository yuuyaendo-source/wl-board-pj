# デスクトップアプリ v2 拡張計画

2026-05-27 議論まとめ

## 背景

- 内部ドメインを `wonder-link.co.jp` → `wonder-link.com` に移行する作業に併せて、デスクトップアプリの **新 msi をビルド・配布する必要が発生**
- せっかく再配布するので、**機能拡張を 1 つのリリースにまとめる**方針
- 配布対象: 社内 10 人
- 利用形態: 社内 LAN ＋ 社外も CATO 経由で社内サーバに到達可

## 目的

社員ひとりひとりの「業務サポート的なリン子」をデスクトップに常駐させる。受付業務だけでなく、業務全般のブレスト相手・通知ハブとして機能させる。

## 検討中の機能

### 1. タスクバー配置オプション

**現状**: フローティングなミニポートのみ。
**追加**: 通常の Window としてタスクバーにも出せるモードを設ける。

- 設定で `floating_mini` / `taskbar_window` を排他切替
- 両方同時表示は UI が散漫になるので避ける

### 2. リン子 2D アバター表示

**理由**: 3D (VRM) は GPU 描画コスト・起動時間・配布バイナリサイズの問題があり、デスクトップ常駐には不適。

**採用方針**: **PNG セット (表情切替)** + 喋り中に口パク 2-3 枚をスイッチ。

| 候補 | 描画コスト | 表現力 | 実装コスト |
| --- | --- | --- | --- |
| 静止画 + 表情切替 (PNG) | 極小 | 中 | 小 |
| GIF / PNG 連番 | 小 | 中 | 小 |
| Live2D | 中 | 高 | 大 |
| Lottie (JSON) | 小 | 中 | 中 |

将来 Live2D に格上げできるよう「表情キーで画像を差し替える」構造で抽象化する。

### 3. ブレスト機能 (チャット + 音声)

**業務サポート用途**。雑談ではなく、社内情報を引いた回答が出せる **RAG ベースのアシスタント**を目指す。

**アーキテクチャ方針**:

- LLM / STT / TTS は **既存リン子サーバ (172.16.1.251) を流用** (Ollama + VOICEVOX + GPT-SoVITS + Whisper)
- ただし **受付業務との競合を避けるため、ブレスト用に LLM 別建ても検討**
- デスクトップ側は薄い **WebSocket / Streaming クライアント**

**RAG の情報源候補** (優先度順):

| 情報源 | 接続難度 | 業務インパクト |
| --- | --- | --- |
| board-system DB (付箋・議事録・ToDo) | 低 (SQL 直接) | 中 |
| Google Drive (docs / sheets) | 中 (既存 SA あり) | 高 |
| Google Calendar | 低 (既存統合あり) | 中 |
| Gmail | 中〜高 (権限・プライバシー) | 高 |
| Chatwork メッセージ履歴 | 中 (API あり) | 中 |
| 社内 wiki / Confluence | ?(有無不明) | ? |

**最小有用版**: board-system DB + Google Drive。Embedding は **bge-m3** クラスを Ollama で動かし、ベクタ DB は **PGVector** (既存 postgres に拡張) または **Qdrant** (別建て)。

### 4. 来客通知 (デスクトップ音声 + 視覚)

**現状**: Chatwork 通知のみ。
**追加**: デスクトップアプリでリン子が音声でお知らせ + トースト通知。

- **方針**: linko-system が来客検知時に発行している SocketIO イベント (`ai_comment` 等) に、デスクトップアプリも subscribe
- 通知音声は linko 本体で生成済みの WAV を URL 経由で取得して再生 (リアルタイム生成不要)
- **Chatwork 通知とは併用** (連携ハブとしてのコンセプト)
- Python `python-socketio` クライアント + `win10toast` 等

### 5. 全機能 OFF / opt-in

すべての新機能は `config.json` の `features` フラグで OFF 既定:

```json
"features": {
  "taskbar_mode": false,
  "linko_avatar": false,
  "visitor_notify": false,
  "brainstorm": false
}
```

- 設定ダイアログ (customtkinter) で個別 ON/OFF
- ON のときだけ Socket.IO 接続を張る → サーバ無駄接続を回避

### 6. アプリアイコン変更

- 既存 VRM リン子のキャプチャを加工して .ico/.png 作成
- PyInstaller の `--icon` + msi (WiX) のアイコン + Window / Tray アイコンを統一

## ユーザ判断 (2026-05-27)

| 質問 | 回答 |
| --- | --- |
| 通知対象 PC 数 | 10 人 (Socket.IO 接続は技術的に楽勝) |
| ブレストの方向性 | 業務サポート + **RAG で社内情報** / LLM 別建ても検討 |
| 来客通知の運用 | **Chatwork と併用** (連携ハブのコンセプト) |

## 全体ロードマップ

| Phase | 内容 | 期間目安 | 配布方法 |
| --- | --- | --- | --- |
| **1** | アイコン変更 + 設定 UI + opt-in トグル枠 + 旧→新 URL の手動配布版 msi | 1-2 日 | **手動配布** |
| **2** | リン子 2D アバター (PNG 表情 + 口パク) | 2-3 日 | 自動更新 |
| **3** | 来客通知 (Socket.IO subscribe + 音声再生 + トースト) | 2-3 日 | 自動更新 |
| **4** | タスクバーモード切替 | 1 日 | 自動更新 |
| **5a** | ブレスト チャット (LLM 直叩き、RAG なし) | 3-5 日 | 自動更新 |
| **5b** | RAG: board-system DB のベクタ化 + 検索 | 1 週間 | 自動更新 |
| **5c** | RAG: Google Drive 取り込み | 1 週間〜 | 自動更新 |
| **5d** | 音声対話 (mic 入力 + STT + Streaming TTS) | 1 週間 | 自動更新 |

**Phase 1 + 4 を最初の手動配布 msi に同梱** → 「旧 cert 期限切れで自動更新が動かない問題」を一発解消、以降の Phase 2-5 はサーバ側の `latest.json` 更新で段階配布できる。

## Phase 1 着手内容

1. 新アイコン (.ico/.png) を VRM リン子のキャプチャから作成 → `assets/` に配置
2. `config.json` に `features` セクションを追加
3. `config_loader.py` に features ヘルパー関数を追加 (`is_feature_enabled("...")`)
4. 設定ダイアログ (customtkinter) を新規実装 — チェックボックスで個別 ON/OFF
5. ミニポート右クリック または トレイメニューから設定ダイアログを開く動線
6. `version.py` の version bump
7. PyInstaller + WiX で msi ビルド + `latest.json` 更新
8. **手動配布**: 10 人に新版を案内 (旧 cert 期限切れで自動更新は今回限り動かない)

## アイコンの方針

**採用**: 既存 VRM リン子のキャプチャ + 加工。

- linko-system の frontend_v2 で動いている VRM をブラウザでキャプチャ
- 顔アップで切り抜き → Photoshop / Affinity / GIMP で輪郭・背景処理
- .ico (16/32/48/256 マルチサイズ) + .png (各種サイズ) を書き出し

## 未確定事項 / 後で詰める

- **ブレスト用 LLM サーバを別建てするか**: 受付業務との競合が運用上どの程度起きるかで判断。Phase 5a 開始時に再度議論
- **RAG のベクタ DB**: PGVector or Qdrant の選定。Phase 5b 開始時
- **設定ダイアログのレイアウト・UX**: Phase 1 着手時に簡易モックを作って合意取り
- **アイコンのデザイン素材**: VRM のどのポーズ・表情をベースにするか。Phase 1 着手時に linko の VRM を起動して候補出し
- **来客通知の音声**: 既存 WAV の流用か、新規生成か。Phase 3 開始時
- **Live2D 化のタイミング**: PNG セットで十分かどうかは Phase 2 リリース後に評価
