# 指示書: 顔登録の複数枚対応（連写3枚＋眼鏡あり/なし）

作成: 2026-06-12 / 対象リポジトリ: wl_desktop_app / バックエンド側（linko-system）は対応済み

## 背景・目的

顔認識バックエンド（linko-system）は、登録APIを呼ぶたびに照合用データ（embedding）を
**1人あたり最大5件まで蓄積**し、照合は「最も似ている1件」とのベストマッチで行う。
角度・照明・眼鏡あり/なしのバリエーションを登録するほど認識率が上がる。

現在のデスクトップアプリは **1回の操作で1枚しか登録しない**ため、この恩恵を受けられて
いない。本対応で「撮影1回の操作で自動連写3枚＋眼鏡使用者は外してもう1枚」を登録できる
ようにする。**バックエンドAPIの変更は不要**（既存APIを複数回呼ぶだけ）。

## バックエンドAPI仕様（変更不要・このまま使う）

ベース: `{base}/api/face_registry`（`face_registry_client.py` の `_api_root` / `_admin_headers` を流用）

| API | 挙動 |
| --- | --- |
| `PUT /api/face_registry/<person_id>` body `{"faceData": "<data URL>"}` | **呼ぶたびに** embedding を追記（最大5件、超えたら古い順に削除=FIFO）。表示用写真は最新に上書きされ、旧写真は `face_gallery` に履歴退避（最大20件） |
| `GET /api/face_registry` | `persons[]` に `face_embeddings_count` / `face_embeddings_v2_count` / `face_gallery_count` を含む。トップレベルに `embeddings_key`（現エンジンの照合キー）。`embeddings_key == "face_embeddings_v2"` なら `face_embeddings_v2_count` を表示に使う（2026-06-12 追加済み） |
| `GET /api/face_registry/<person_id>` | 上記サマリに加え `faceData`（現在の写真 data URL）と `face_gallery: [{dataUrl, ts}]`（履歴） |

注意: **顔が写っていない画像を PUT してもサーバは 200 を返す**（embedding は保存されず
サーバログに警告が出るだけ）。クライアントでの検知はできないため、撮影ガイダンスで
「顔を枠の中央に」と誘導する（後述）。

## 実装タスク

### 1. `FaceCaptureDialog`（face_registry_admin_dialog.py）を連写対応にする

- 「撮影して登録」ボタン1回で **3枚を自動連写**する（間隔 0.8〜1.0 秒）。
- 連写中はステータスラベルでガイダンスを出す:
  1枚目「正面を向いてください」→ 2枚目「少しだけ左を向いてください」→
  3枚目「少しだけ右を向いてください」。各撮影前に短いカウントダウン（例: ラベルに 3,2,1）。
- 実装は `webcam_capture.capture_jpeg_data_url(self._cap)` を3回呼ぶだけでよい
  （`after()` でスケジュールし、UIスレッドをブロックしない）。
- `on_captured` コールバックのシグネチャを `Callable[[str], None]` →
  `Callable[[list[str]], None]`（data URL のリスト）に変更する。
  ファイル選択（`_on_pick_file`）経路は従来どおり1枚（リスト1件）でよい。

### 2. アップロード処理（`_open_capture` 内 `_upload`）を複数枚対応にする

- 受け取った data URL リストを**直列で** `face_registry_client.update_face()` に渡す
  （並列不要。1枚失敗したら同じ画像を1回だけリトライ、それでも失敗なら中断）。
- 完了メッセージは部分成功が分かる形にする:
  - 全成功: 「○○さんの顔を3枚登録しました。」
  - 部分成功: 「2/3枚を登録しました（1枚は通信エラー）。」
- 登録後は一覧を再読込（既存の `_reload_list`）。

### 3. 眼鏡あり/なしの追加登録を促す

- 3枚の登録完了後に確認ダイアログ:
  「眼鏡をかけて撮影した場合、外した状態でもう1枚追加すると認識率が上がります。追加撮影しますか？」
  （眼鏡なしで撮った人には不要な文言だが、判定はできないので一律でよい。
  「いいえ」で終了、「はい」で `FaceCaptureDialog` を**1枚モード**で再度開き、追加1枚を PUT）。

### 4. 一覧に「照合データ N/5」を表示する

- `GET /api/face_registry` のレスポンスから `embeddings_key` を読み、
  `face_embeddings_v2` なら各 person の `face_embeddings_v2_count`、
  それ以外は `face_embeddings_count` を採用する。
- 各社員行の表示を「顔登録済み」→「顔登録済み（照合データ N/5）」に変更。
- ボタン文言「顔を変更」→「**顔を追加**」に変更（蓄積される動作と一致させる）。
  ツールチップまたは説明文: 「撮影するたびに照合データが追加されます（最大5件。
  古いものから入れ替わります）。表示写真は最新のものになります。」

### 5. 「顔を確認」を履歴込みの一覧表示にする

- 現状は `fetch_face_image_bytes()` で現在の1枚のみ表示。
- `GET /api/face_registry/<id>` を呼び、`faceData`（現在）＋ `face_gallery[].dataUrl`（履歴）
  をサムネイル一覧で表示する（ラベル: 「現在」「履歴 1」「履歴 2」…）。
  タイトルに「登録画像（M枚）・照合データ N/5」を出す。
- 工数を抑えたい場合の最低ライン: 現在の1枚表示のまま、タイトルに
  「照合データ N/5・履歴M枚」の注記を追加するだけでも可。

### 6. 社員自身のセルフ登録経路も同じ挙動にする

- セルフ登録（社員が自分の顔を登録するフロー）が `FaceCaptureDialog` / `_upload` と
  同じ経路を通っているなら、上記1〜3で自動的に複数枚対応になる。
  別実装になっている場合は同じ「連写3枚＋眼鏡追加」仕様に合わせること。

## やらないこと（スコープ外）

- バックエンドAPIの変更・新設（不要）
- クライアント側での顔検出による品質チェック（OpenCV等の追加依存は入れない。
  ガイダンス文言での誘導に留める）
- 5件を超えた場合の手動管理UI（FIFOで自動入れ替えに任せる）

## 受け入れ基準

1. 撮影操作1回で3枚が登録され、linko の `/manager` 画面で該当社員が
   「照合データ 3/5」と表示される（バックエンド側は対応済み）
2. 眼鏡追加撮影をすると 4/5 になる
3. 既に5件登録済みの社員が追加しても5件で頭打ちになり、エラーにならない
4. 通信エラーで途中失敗した場合、何枚まで登録できたかがメッセージで分かる
5. ファイル選択（アップロード）経路は従来どおり1枚で動作する
